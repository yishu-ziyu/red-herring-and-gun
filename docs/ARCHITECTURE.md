# 红鲱鱼与枪 · 结构和容易踩的坑

本文件只写代码看不出来的约束和坑。产品该是什么样看 `docs/PRODUCT.md`，为什么这样决定看 `docs/DECISIONS.md`。调查流程从 `apps/server/src/lib/casePipeline/runCasePipeline.ts` 读起。

## 不能破的约束

- **判断由代码定，模型只写理由。** 每一截和整句的标签都由规则表算出，模型写的理由要是和标签矛盾、太长、带内部用语，就不用它，改用各截标签拼成的句子。原因：模型写的整句理由曾经和标签相反（标签「不属实」，理由说「部分属实」）。
- **引号里的话必须逐字出自来源。** 模型摘的句子要由代码在本轮拿到的来源文字里找到，找不到就不加引号，显示「我们的概括」。原因：模型会改写、拼句、加省略号，而用户会把引号里的话当成原文。
- **拆出来的每一截必须用用户的原话。** 模型改写了原话（「会致癌」写成「会产生致癌物」），代码删掉原句没有的字；删完对不上原句时，换回原句那一截。原因：查改写后的句子，等于查了另一句话，曾经因此把谣言判成「属实」。
- **支持或反驳要有独立核验。** 核查模型分好的支持、反驳来源，要再由来源核验模型逐条确认方向，没确认的只作背景。
- **分享只从服务器存的那一轮生成，不接收浏览器提交的内容。** 否则任何人都能借分享发布伪造的结论。

## 容易踩的坑

- **推理模型的输出上限包含思考。** MiniMax M2 系列不能关闭思考，上限给少了，模型想完就没额度写正文，只返回思考。上限要留足；出错时看日志里的 `stop_reason` 和实际用量。
- **模型返回的 JSON 常带没转义的英文双引号。** 来源标题和原文里常有 `"`，两家模型都会照抄。解析前会先补转义；新加的模型步骤要走同一个解析函数。
- **两个模型写的同一截，文字可能差一两个字。** 核查结果和核验结果对号时，不能要求一字不差，要按网址找文字最接近的那一截，否则所有来源都会被降为背景，结论变成「还查不清」。
- **同一句话多次调查，结论可能不同。** 主要来自搜索结果每次不同。判断一处修改有没有效果，至少跑同一句话两三次再下结论。
- **开发服务器保存后端文件就重启**，正在进行的调查会中断。跑端到端测试时不要改后端文件。
- **本机有网络代理**，偶尔出现约 5 秒就断开的模型请求。线上服务器上是否也会出现，还不知道（#146）。
