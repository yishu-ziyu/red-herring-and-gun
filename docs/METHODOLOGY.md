# 协作方法

人负责定义价值函数，机器负责搜索。需求先变成「什么现象出现时算成功」，再动手。本文件是可迁走的完整包。

## 规范怎么写

按生命周期分层，每层只回答一个问题。短、可执行、有归属。不追求「文档齐全」。

| 层 | 放哪 | 只回答 |
| --- | --- | --- |
| 协议 | `AGENTS.md` | 每次会话默认怎么做 |
| 契约 | `docs/evals/日期-任务.md` | 这一次什么叫好 |
| 工作记忆 | `docs/NOTES.md` | 压缩后还要记得什么 |
| 方向档案 | `docs/devlog/` | 为什么改了方向 |
| 经验（可选） | wiki patterns/ | 这个坑下次怎么避 |
| 技能（可选） | skills / 改协议 | 下次默认按什么流程做 |

`AGENTS.md` 每个会话都会读，所以必须短。只放默认行为：先验收后实现、上下文怎么管、本仓库用来判定「能合并」的真实命令。产品品味、某次踩坑、技术选型，都不进这一层。

验收卡是核心。动手前写，存档，commit 引用。固定三块：一句话任务、带 evaluator 的勾选标准、明确的非目标。没有 evaluator 的句子不算标准。能拆成命令的拆成命令；拆不动的标「人评」，交付时单独列出来等人裁。还有一条写卡纪律：Change / Not this——用户必须能观察到什么；测试绿了但用户路径没通、只改了文案、只出了报告，都不算。

NOTES 是压缩对抗层。头部永远是「当前状态」。每个子任务刚做完就写，不等会话结束。等压缩再写等于没写。

开发日志只记转向：改了什么、为什么、结果如何、哪条路被实测推翻。不是 commit 复述。

最反直觉的一条叫 **现象即信号**：你说「太慢」「不好用」时，Agent 不准直接改。先追问成数值、行为、截图、复现路径，再翻译成测试。删掉这一条，协议就退回聊天式开发。

## 依据

不是审美，是两件事。

**搜索怎么分工。** 写软件是在巨大改动空间里找「足够好」。好必须由人定，模型没有这个权——验收卡就是把价值函数写下来。搜索必须由机器做：写、跑检查、对着失败迭代。人不要当 Agent 的测试跑者。机器项全绿才交付，是为了不把半成品丢给你当判断材料。人评不是偷懒，是价值函数里机器没有传感器的那一段。

**长程 Agent 的记忆怎么分层。** 来自两篇 2026 年的论文。

- ContextPilot (https://arxiv.org/abs/2608.28476) 管一次任务内部。上下文不能单增。探索派子代理（软卸载）、结论立刻外置到 NOTES、压缩后先读 NOTES。论文消融里有一句直接能用：只给工具、不变成习惯，效果更差。所以这些必须写成 `AGENTS.md` 里的默认规则，不能指望模型想到了就做。
- WikiSkill (https://arxiv.org/abs/2608.27454) 管跨任务。三层分开：原始轨迹可扔；wiki 一坑一页、只增不删、永不回滚；skill 原子修改、验证门控、可回滚。两条硬约束：日常会话不要读 wiki（论文里推理期注入 wiki 会掉分）；离线复盘的 Agent 不准直接改 skill，只许提案，落地必须经过你。

## 人和 Agent 怎么协作

标准路径：

你提需求（可以很模糊）→ Agent 写验收卡（必要时先问「什么现象算更好」）→ 你确认卡，或改价值函数 → Agent 自己搜、自己跑机器检查到绿 → 人评项列清单给你 → 你裁；不通过就改卡或改实现 → 过了：NOTES 落结论，转向写开发日志，commit 引用那张卡。

你是价值函数的所有者，不是副驾驶程序员。你定什么叫好、裁人评、裁经验提案。你不替 Agent 跑测试，也不在机器项未绿时判断「是不是差不多了」。

Agent 缺的是价值判断，不是执行。卡自己起草，只在「缺一个价值判断会改变结果」时才问你。机器绿了但真实路径没通，改 evaluator，不改口说完成。不把 wiki 当运行时手册。不在你未裁决时改协议。

卡写完之后，还有一圈内循环：Goal（停下来时必须存在的、你能看见的东西）→ Hard bar（失败 = 没做完）→ Improve（硬条过了之后要拉的一个数，没有就没有）。先功能后设计。范围外的重构不算完成。

## 长期怎么维护

三个时间尺度，对应三套记忆。混用会腐烂。

- **一次会话内（小时）：** 怕上下文被压掉、主会话被探索淹没。对策是子代理 + NOTES。压缩丢细节没关系，持久事实必须已经在 NOTES。
- **跨任务（天到周）：** 怕「当时什么叫好」说不清、同一方向错误再走一遍。`docs/evals/` 是质量标准的历史；`docs/devlog/` 是设计转向的历史。一个仓库养不养得久，看 evals 能不能回答：上周承认的好，和今天说的好，是不是同一件事。
- **跨周到跨月（可选）：** 会话结束，离线 consolidator 读轨迹，写成 pattern，最多提一条 skill 提案。你接受就落地并提交；拒绝就归档，防止下次再提。没有「会话结束能拉起一个 Agent」这种钩子，就不要假装有第三层。停在前两层已经能转。

腐烂信号很清楚：先写代码再补卡；卡没有 evaluator 或全是人评；NOTES 只在结束时补一段；日志变成 commit 复述；把测试绿当成用户路径通了；日常读 wiki；复盘 Agent 直接改了协议。出现这些，停在当前任务补卡，不要加新文档层。

## 迁走带什么

最小内核，任何仓库都能用，不依赖特定 Agent 产品：

1. `AGENTS.md`
2. `docs/evals/`
3. `docs/NOTES.md`
4. `docs/devlog/`
5. 现象即信号
