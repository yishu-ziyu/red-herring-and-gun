## 一、产品是什么

红鲱鱼与枪是一款可检查的信息调查工具。用户提交一句话、截图或链接，系统把说法拆成可核查命题，追查公开证据，并展示每个判断如何从证据与证据缺口中形成。

查完直接回答原句，指出哪些部分成立、哪些有问题、哪些仍未查清，并提供能点开的来源。追出处是证据工作的一部分：说法从哪来、是不是一手、转载有没有添油加醋。

这份定义不依赖任何 Agent、模型或搜索品牌成立。只读第一至三节就能知道产品是什么、用户看见什么、沿哪条路径走，不需要读后台章节。

有技术含量的是溯源与证据，不是话术。不是搜索总结，不是论证课，不是转发顾问，不是指挥台。

## 二、用户看见什么（产品宪法）

本节是产品宪法：不可让步的原则与唯一主路径。任何界面、数据结构、文案改动先对这一节；与后面实现章节冲突时，以本节为准。

### 两条不可让步原则

**1. Evidence Auditability > Agent Observability。** 默认展示调查逻辑，不展示执行日志。白盒 ≠ 展示所有 Agent 行为：白盒不是把 Agent 日志、工具调用、管线状态摊给用户看，而是展示判断为什么成立——原话被拆成了什么，每个命题找到了哪些证据，哪些支持、哪些反驳、哪些只是相关、哪些还缺，证据为什么冲突，最终判断因此如何形成。

**2. 复杂调查，简单理解。** 严谨不意味着难用。低摩擦、友善、漂亮是产品要求，不是发布后的美化项。视觉体验属于产品门禁：视觉验收与功能验收同等作为发布门禁；不先解决信息架构再留到 polish，也不先换皮再解决信息架构。视觉层级、留白、动效和交互节奏必须帮助用户理解调查逻辑、降低摩擦、产生探索欲。**视觉验收必须写正向目标**：说明画面该长什么样、对照哪份资产、哪些特质算好，不得只用禁令（不玻璃、不卡片、不加动效）验收——只有禁令的设计系统必然退化成一张灰纸（2026-09-11 修正案，见 `docs/devlog/2026-09-11-visual-identity-amendment.md`）。

### 白盒三层

| 层 | 用户能检查什么 |
|----|----------------|
| 命题透明 | 原话被拆成了什么，是否改变了原意。拆分过程不呈现（中间尝试、模型推理不上脸），呈现的是拆分结果与原句的对照 |
| 证据透明 | 支持 / 反驳 / 仅相关分别是什么，各自必须绑定可点开的出处；尚缺是一等 Evidence Gap：写明缺什么、为什么这个缺口阻止更强判断——没有来源就明确写没有来源，不许为凑链接把相关结果当支撑 |
| 判断透明 | 为什么得到这个结论，冲突在哪里，仍不能推出什么 |

### 唯一 Golden Path

只允许一条默认主路径。其余能力挂在这条路径上，不为「看起来功能多」另开入口：

```text
输入（一句话 / 截图 / 链接）
  → 命题拆解：系统说明这句话被拆成了哪些需要分别核查的问题
  → 证据汇入：支持 / 反驳 / 仅相关 / 尚缺
  → 冲突/缺口：有实质冲突时显示争点及冲突原因；缺口如实标出
  → 判断：第一句直接回答原句（会不会、是不是、哪一层成立）
  → 来源下钻：任一关键结论可逐层下钻到可点开的原文
```

调查逻辑默认可见并渐进呈现：原句 → 命题 → 证据关系 → 缺口/冲突 → 判断。执行过程——Agent、tool call、provider、token、模型推理、内部日志——默认隐藏。两个对象不许混为一谈：隐藏的永远是执行过程，不是调查逻辑。

### 默认隐藏（实现层）

Agent 名、provider、tool call、token、RRF、pipeline、内部 verdict enum（`verdictType` / `faceVerdict` 这类四字章）、调试信息，都是实现层概念，不是产品核心概念，默认不出现在用户界面。第四节的管线术语全部受本条约束。

调查必需的证据语义——**支持、反驳、仅相关、尚缺、争议**——属于调查逻辑透明的核心组成部分，必须直接呈现在用户面前，向用户清晰表达证据关系。实现层词汇（Agent 名、provider、tool call、token、pipeline、模型推理、内部 verdict enum、调试信息）一律不许出现。


### 主路径行为

半真半假就点名哪一截站住。查不清就说查不清。没搜到不等于假。执行日志默认隐藏；调查逻辑默认可见并渐进呈现。查完可以再问一句，追问留在同一条里；换问题才点再查一条回首页。

### 默认体验：先解决主要疑问，再按需要深入（2026-09-17 用户确认）

采用方案二：普通人无需先配置模式或确认拆题；自动接收材料、展示实际核查范围，优先检查主要主张及回答它所需的依据。重点优先不等于全文已核；没有进入本轮或证据不足的部分必须明确保留边界。

首轮收束给出有证据边界的回答；重要发现可以提前显示，但不得冒充最终结论。查看已有依据只读取当前材料，不重新调查。继续补查必须明确发送问题，留在同一份调查内，保留之前各轮的问题、结果、出处与原核查日期；补查失败或停止不得覆盖原结果。历史重开是读取，不是重新核查；分享保留所分享轮次的判断范围。

暂不加入从方案一到三的滑条：范围、交付形式和等待成本不是同一个连续参数。在真实深度政策和各档质量/成本未验证前，固定方案二；不以缩短时限或减少证据标准模拟「低思考强度」。

### 质询与调查留存（2026-09-05 当前规则）

- 有已绑定的真实证据冲突时，独立意见提出具体问题，进入统一补查。只有取得新材料才重判；重判不完整则保留先前完整判断。意见分歧本身不扣分，不以共识代替证据。
- 结果先直接回答原句，再呈现关键争点、回应、相关出处和未解决的问题。没有质询就不补造；旧报告缺少记录不能写成已经复核。
- 完成的调查自动留存，打开旧调查显示原日期且不启动模型或搜索。纯文本同句只规范化空白，显式选择打开旧调查或重新核查；新增链接、图片以及人物或日期变化不静默继承。语义相似只用于搜索线索。
- 本地访客和账号历史分开；不跨用户汇总私人调查。保存失败、账号同步失败必须可见。
- （2026-09-29 用户裁决）说法档案自更新并共享：预先收集权威辟谣，用户查过的**公共说法**（政策、健康、公共事件等）去掉提问人信息后进入共享档案，所有人可用；涉及普通个人、私人群聊内容的说法不进共享档案，只留在提问人自己的历史里。档案结论带核查日期，按版本追加不覆盖；写入须通过引用回查，并标明是权威机构辟谣还是本系统核查。换了时间、地点、人物、数字的变体不继承旧结论。
- 当前后端与历史接线已有实现，结果页尚未消费新质询记录，完整用户路径未验收。先用临时 HTML 确认呈现方式，用户认可后接生产；真实收益和五次调查留存仍需独立验证。原型不证明真实功能完成。

### 用户看见的字（输出语言）

检索是工具。用户看见的是判断、问题和可点开的出处，不是谁调了什么工具。

| 只许出现 | 不许出现 |
|----------|----------|
| 对原句的直接回答（会不会、是不是、哪一层成立） | 「能信 / 不能信 / 只能信一部分 / 还查不清」当结论第一句；FactChecker、ReportComposer、search360、Tavily、MiniMax、Agent、智能体、工具调用 |
| 立场型 / 不适用真/假判断 | 灰 |
| 哪一截有出处、哪一截没有 | 先别转发、转不转、建议你转 |
| 来源标题和可点开的链接 | 模型记忆、函数名、检索商标当结论 |

conclusion 第一句直接回答原问题，像 **不会。** / **原句站不住。** / **只有后半截能站住。** 禁止用「能信 / 不能信 / 只能信一部分 / 还查不清」当第一句——那四个词是内部类型（`verdictType` / `faceVerdict`），留给闸门，不盖在脸上。小节标题写成判断本身（「一、已发生的事实：…」），不要写成「问题拆三层 / 分析 / 建议」。recommendation 只重复答案，不写行动建议。代码在收束时再剥一遍工具名和四字章（`publicCopy`），不靠模型自觉。

写法从教材文（如 [工具使用](https://adp.xindoo.xyz/chapters/Chapter%205_%20Tool%20Use/)）借结构，不借题材：

```text
答案。   ← 第一句就回答原问题，不是盖章
对象。   ← 这句话在断言什么
材料。   ← 哪条出处支持或反驳了什么
边界。   ← 仍不能推出什么
```

一句一事。先骨架后填空。抽象判断立刻跟一条具体出处。并列的条目用同一句式。不写「然而 / 截至目前 / 总的来说」起段。结尾不添新主张。不训人。用户发来的下一篇参考，继续抽结构，不抄它的主题。

#### 每一截的用词（2026-09-29 用户确认）

用哪个词由原文依据决定，不由模型语气决定。

| 用词 | 条件 | 颜色 |
|---|---|---|
| 属实 | 原文逐项证实这一截 | 绿 |
| 基本属实 | 核心被证实，只有次要细节不准（日期差几天、发文机关说错） | 绿 |
| 说过头了 | 有一部分道理，但程度或范围被放大（原文说「作用有限」「部分」「个别」） | 黄 |
| 言过其实 | 只剩很小一部分为真，主体是夸大（个别说成普遍） | 红 |
| 不属实 | 原文明确说了相反的事 | 红 |
| 查不到 | 按常理不会有公开记录，或确实没有找到 | 灰 |
| 有争议 | 权威来源之间结论相反 | 灰 |
| 立场，不判真假 | 价值判断 | 灰 |

主要的一截为「言过其实」或「不属实」时整句为「不能信」（评分规则 2、5）。每一截下面直接给出已逐字核对的原文、实际来源域名和真实发表日期（有数据才展示），可跳到原网页的这一句。其余材料与调查经历默认折叠；没有缺口时不生成推荐追问，保留自由输入。本轮只数材料篇数，不把转载算成独立来源；缺乏可靠分组时不显示独立来源数。细分程度没有足够信息时不硬套八档标签，旧历史沿用原判断。材料不足时写“目前的材料不足以判断。”交互样例：`outputs/evidence-first-mock.html`（本机）。

## 三、赛题背景（保留原始权重，不作为本轮价值函数）

| 权重 | 评什么 | 产品上怎么兑现 |
|------|--------|----------------|
| 30% | 准确性 | 对着公开材料核，不靠模型编；混合说法拆开查 |
| 20% | 至少 3 类谣言 | 健康、社会、截图/视频等都能收 |
| 20% | 结果 | 查完有结论，结论能被拿走（报告 / 复制 / 归档），不是「建议你转不转」 |
| 10% | 记忆 / 知识库 / 多 Agent | 查过的能复用；Agent 之间传的是核查材料，不是演戏 |
| 10% | 国产大模型 | 国内模型也能查准 |
| 10% | 360 生态 | 至少接上一个 360 产品（搜索等） |

脸必须简单。准确性要求查的时候可以拆、可以多源、可以打分。

## 四、后台怎么查（实现，不是卖点）

确定性代码管类型、编排、筛选、打分；模型只做需要语义的几步。本节全部是实现层：出现的 Agent、provider、tool call、RRF、pipeline 名字按第二节「默认隐藏」执行，不出现在用户面前。

1. 材料进入后生成执行计划，按职责裁剪每个 Agent 的输入。
2. **RumorDetector（拆题）**：同一套模型（公网默认 MiniMax-M2.7-highspeed；M3 可显式覆盖）被叫来只做分类，不判真假。拆出原句里真实存在的判断，给每条写 `type` 和 `verifiable`。另一次自证调用丢掉原句没说过的。详见本节「类型谁标」。
3. 可核查判断各自检索（上限 6 条，按负荷选：因果/「导致」优先于带数字，再高于其余）。没进名额的可核查条仍按原句序出现，只能是还查不清。被标成立场/价值的判断不发起证真证伪检索，报告该条写「立场型 / 不适用真/假判断」。读起来像流传说法却被标立场时，代码强制当可核查去查（不是更强分类器）。预测若有公开承诺、正式文件、已发布预测等现在能追溯的抓手，照常检索——查的是抓手，不是未来是否发生；没有抓手则还查不清，不判假。无 http(s) 出处、或只有检索垫上的相关链接，单条和整句都不得停在能信/不能信。
4. **FactChecker / SourceValidator**：按条对照实际取得的原文，判断证据方向；引句必须与该命题对应正文逐字核对，摘要不能单独支撑确定判断。
4a. **证据充分性循环**（ADR-004）+ **证据追索**（ADR-005）：核查后对 unverified / 证据冲突的原子按证据缺口生成查询组合（Exact / 原始来源 / 反证 / 时间 / 当事方），多 query 结果做 RRF 融合；同站转载不计入有效增益。每次补查最多2轮，获得新材料且缺口未闭合时最多续查一次；受总时限约束。只有新URL或同URL首次补齐正文才重跑核查。无证据 ≠ 假。过程层可回看每一跳的目标与缺口，不把检索工具调用当主秀。
4b. **冲突意见**：只在已经绑定的证据相互冲突时提出问题；该步骤不检索、不重判，问题进入4a的统一补查。意见分歧本身不扣分。
5. **ReportComposer**：正式判断在写作前确定。模型只读取正式分条判断、已核引句、范围与缺口，组织解释；不能另改判词或来源方向，不能自行补事实。2026-09-30用户确认：含任何未查清分条时，结果保留正式分条、原文与真实缺口，不采用模型整段自由解释；全部查清时保留模型报告，不额外增加一次模型审稿。
6. 0–100 可信度由公式算（`credibilityScore`），不让模型拍分数。分数是实现层信号：不替代证据解释，不代表白盒——白盒是第二节的三层透明。

检索并行调用有 key 的源（360 mweb / Tavily / Exa / Metaso / AnySearch 等）；失败不阻断整次。进核查前过筛选漏斗：无 URL 丢掉、去重、按条 top-k。不要对外说「我们只搜好东西」——只是少把不可追溯噪声送进证据链。

无证据 ≠ 假。定向检索无结果 → 未能证实 / 待补证。

### 类型谁标（同一模型换工单，不是更强的分类器）

拆题、核查、写报告的公网默认都是 **MiniMax-M2.7-highspeed**；需要高深度时可显式选择 MiniMax-M3。不是 Mimic，也没有另雇一个更强的模型来认类型。

同一模型被叫多次，每次只许填一张工单：

| 工单 | 谁在跑 | 只许回答 | 不许做 |
|------|--------|----------|--------|
| 拆题 RumorDetector | MiniMax-M2.7-highspeed（可覆盖 M3） | 这句话在断言什么：`type`（事实 / 因果 / 价值 / 预测 / …）和 `verifiable`（能不能去查） | 不许写能信 / 不能信 |
| 自证 | 同一模型 | 这条判断原句有没有说过 | 不许改类型、不许判真假 |
| 核查 FactChecker | 同一模型 | 对着检索来源，这条能核的判断是 true / false / partial / unverified | 不许重新分类 |
| 写报告 ReportComposer | 同一模型 | 根据正式判断、已核引句和缺口写解释 | 不许自己补事实，不许改变正式判断或证据方向 |

代码只读拆题工单上的两个字段决定搜不搜。`verifiable: false` → 不检索、不进真假清单；该条在报告上显示「立场型」「不适用真/假判断」。不要把这叫「灰」——那是内部样式类名，用户看见的是这两句。

例外：读起来像正在流传的判断（含「导致/致癌」这类），即使工单写成立场，代码也强制可核查并检索。这是同一套确定性闸，不是另雇更强模型。

「还查不清」和「证据两边打架」不是拆题标的。那是搜过之后，核查模型写出 unverified，或同一条既有支撑又有反证，代码才再搜或换 StepFun 二审。

证据冲突有第二意见（公网主判 MiniMax-M2.7-highspeed，可覆盖 M3；二审 step-3.7-flash）。**类型标签没有第二模型复核。** 模型整步挂掉会 fail-open（整句当可核查继续搜）。流传说法被标错立场，现在由强制可核查闸兜住。


## 五、失败

失败要显式，不能补一段流畅解释糊弄。搜索失败、超时、来源不可达显示为状态。可选 Agent 失败不阻断收束；核心失败则阻断。报告超时走确定性兜底，结构完整、不撒谎、不空白。

## 六、明确不是

- 不是「先别转发」公益广告。
- 不是「转不转」决策工具。
- 不是「可以说 / 不可以说」的措辞教练。用户要的是对原句的直接回答，不是四字章。
- 不展示虚构的角色对话或运维面板。执行过程（Agent 名、tool call、provider、模型推理、内部日志）不上前台（见第二节）。**产品可以有拟人化的视觉角色**：角色是这次调查的视觉身份，允许出现在与材料状态绑定的位置（页头、尚缺、争点、结论收束），但不得出现在执行流程里、不得伪装成判断者、不得代表证据本身，也不得为演示制造对话。
- 不是编排框架演示。不迁移 LangGraph / DeepAgents（ADR-002 结论维持）；动态加在证据维度，不加在拓扑维度。
- 不做无界自主执行。允许有界质询与补查；必须保留引用约束、停止条件、失败状态和判断变化。
- 不是论证结构课、不是闲聊、不是空间画布。查完可以再问一句，问的还是这条材料，不是把产品改成聊天。
