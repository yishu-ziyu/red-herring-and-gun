# 子 Agent 协调手册（本项目实证版）

> 依据：2026-09-12 本会话多轮 swarm 实战（追问观测、六步验证、看板修复）总结。主会话按此手册派发；手册本身按实证持续修订。

## 一、什么时候派、派多少

| 类型 | 拆分原则 | 合适数量 |
|---|---|---|
| 探索/取证（只读） | 一个独立问题一个分身 | 并行 2–4 个，再多结论合不拢 |
| 实施（写代码） | **按文件不相交拆分**，每个分身有明确文件所有权；同一文件的多项改动给同一个分身 | 一次 2–4 个并行 |
| 验证 | 实施完成后单独派，**与实施者不同人**（不许自己验自己） | 每批 1 个 |
| 真实走查 | 每批收口一次，专用分身；烧真实额度，不复用 fixture 结论 | 每批 1 次 |

判断标准不是「能拆多细」，而是「拆到互不冲突后还剩几块」——文件所有权有交叠就必须合并成一块。

## 二、身份与工具（本运行时可选的旋钮）

- `explore`：只读。用于代码映射、接线核对、设计调研。
- `coder`：读写。用于实施与验证（验证分身的提示词里限定「只读仓库、不改代码」）。
- 工具权限没有更细的粒度可调，靠提示词约束 + 契约里的文件归属清单兜底。
- 模型：`opencode-go/deepseek-v4.1-flash` 为默认（规格明确的实施/取证/验证）；`primary`（K2.8）留给契约起草、架构判断、冲突仲裁。
- 故障处理：provider 400/路由错误 → resume 一次 → 再失败换 primary 重派（实证：2026-09-12 opencode-go 缺 session 头，config 加 custom_headers 后恢复）。

## 三、提示词五件套（每个分身必含）

1. **背景一句话**——分身没有我们的对话历史；
2. **先读契约**——Change / Not this / Evaluator / 文件归属；
3. **文件所有权**——拥有哪些、禁动哪些；
4. **验证义务**——跑哪些命令；全量门禁留给主会话统一跑；
5. **回报格式**——改动清单 / 与契约的差异 / 测试结果 / 遗留风险。

## 四、协作纪律（每一条都有本项目的血泪对应）

- **契约先行**：动手前钉死接口字段与文件归属，分身间只通过契约耦合，不通过对话。
- **证据先于断言**：动代码前 `codegraph query / callers` 验证符号位置；回报结论带 `文件:行`；代码里看不分明的明说看不出，不许编。
- **变异自查**：写测试的分身临时改坏一处实现，确认测试真的会红，再还原（防假绿）。
- **真实路径为王**：fixture 回放和单测绿 ≠ 用户路径通（2026-09-12 实证：1341 测试全绿但真实一轮六步塌了五步）。**每批以真实走查收口**。
- **归属与定性**：验证分身用干净 HEAD worktree 区分「本批引入」与「历史既有」；发现的历史遗留问题登记清单，不擅自扩大范围修。
- **状态收口**：每个批次完成后由主会话统一落 `docs/NOTES.md` 头部；分身只写自己的报告目录，不抢共享状态板（防并发写冲突）。

## 五、已实证有效的模式

- **三分身验证**（离线回放 / 代码接线核对 / 真实走查）并行跑，视角互补；跨分身交叉证据（如服务端落库 vs 客户端画面）比任何单视角可靠。
- 契约里写死「文件归属」段，swarm 并发零冲突。
- 真实走查分身的提示词里写死额度授权边界（「拦 /api/** 不计费」或「真实计费 N 次，别重跑」）。
