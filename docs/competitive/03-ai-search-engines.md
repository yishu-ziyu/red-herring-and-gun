# 竞品调研：AI 搜索引擎 / 大模型联网搜索 / RAG 增强型问答

> **调研日期**：2026-07-25
> **调研目的**：为「中文 AI 核查 Agent」（用户提交一条说法/截图/链接，系统用多 Agent 流程拆解为可核查子命题、交叉验证证据、输出可信度评分与证据链）做竞品对比，重点回答四个差异化问题：
> 1. 能不能做**论证结构分解**（事实 / 价值 / 因果 / 预测四类混合判断的拆分）？
> 2. 能不能识别**混合判断**（单一句子内同时含事实与价值断言）？
> 3. 能不能区分**相关 vs 因果**？
> 4. 能不能给**证据评级**（不只是"附了引用"，而是评估源头的可信度）？
>
> **来源标注约定**：⛏️ 表示已通过网络搜索/抓取获得一手资料；📚 表示基于模型公开训练知识（含产品官网/官方文档/通用媒体报道，无当前网络验证）。所有用户规模/收入数字均注明来源日期。

## 二、每个竞品的短描述

### 1. Perplexity AI（⛏️ 多源验证）
**核心机制**：检索 + 多 LLM 协作（Head of Search 公开称「数十个 LLM 并行工作处理一个用户请求」）。自研 Sonar（基于 Llama 3 70B 精调）+ Sonar Pro，Sonar Pro 在 SimpleQA 上 F-score 0.858。关键差异化是创始人 Aravind Srinivas 强调的原则：「你不应该说出任何你没有检索到的东西，这比 RAG 更强大。RAG 只是说『使用这个额外的上下文来写答案』，而我们会说『除此之外，不要使用任何其他东西。』」也就是说，Perplexity 不只检索增强，而是把「事实 grounding」做成硬约束——检索不到就直接告知用户，不硬编。**功能**：2025-08 上线视频生成（Pro 5 个/月，Max 15 个）；Comet 浏览器 2025-10 免费开放；与 Motorola、三星预装合作；Deutsche Telekom "AI Phone"。**商业**：2025 年化收入 1 亿美元（500% 同比），订阅 $20/月起，Comet Plus $5/月，4250 万美元出版商分成计划（80% 给出版商）。**用户**：238 国/46 语言，AI 搜索份额 6.6%，月搜索 7.8 亿次，App 下载 1390 万，Product Hunt 4.8 分。

### 2. You.com（📚）
2021 年由 Richard Socher 创立，早期主打「工具栏可拆卸的 AI 搜索引擎」，2024 起转向自研 ARI（Advanced Research & Insights）模型，提供 Research、Genius、Create 等多模式；推出 You Apps 生态让第三方构建小型 Agent。**特点**：多模式（每种对应不同工作流：Research=研究任务；Genius=多步复杂问题；Create=内容创作）。**弱点**：在 2023 年 ChatGPT 出圈后市场关注度下降，目前定位「专业研究人群」而非大众；中文处理较弱。**用户规模**：2022 年披露月活 1100 万、2022 年 B 轮融资 2.25 亿美元，此后无新公开数据。

### 3. Brave Search + Leo（📚）
Brave 是少数仍坚持独立网页索引的搜索引擎（不依赖 Google/Bing），2021 年从 Beta 毕业。Leo 是 Brave 浏览器内的 AI 助手（免费 + Premium 两档），底层使用 Mixtral 8x7B（免费）和 Llama 70B（Premium），支持问答、总结、翻译、代码。**特点**：隐私优先（不收集用户 IP/查询）、独立索引（避 Bing）、答案附「来源数 N」的标注。**弱点**：在中文场景索引覆盖度落后于百度/秘塔；不做论证结构拆解。

### 4. Microsoft Copilot / Bing Chat（⛏️）
2023-02 推出 Bing Chat（基于 GPT-4），后并入 Copilot 品牌。2025-03 推出「Deep Research」模式（基于 OpenAI o3 深度研究模型），可对复杂任务做多步搜索+推理。**机制**：Bing 索引 + GPT-4/4o + 多步工具调用（Deep Research 主动分解子研究问题）。**特点**：与 Microsoft 365、Edge、Windows 深度集成；段落级引用「Learn more」链接。**弱点**：来源链接无评级；不区分事实与价值断言；Deep Research 偏任务流（"我要研究 X"），不针对单条说法做命题拆解。

### 5. ChatGPT Search / GPT-4o with browsing（⛏️）
2024-07-25 起对所有用户免费开放搜索功能（此前 Plus 独占）。底层：GPT-4o/o-series + 浏览工具（与 Bing 合作）。**特点**：通过 system prompt 强约束「不能编造来源」，但来源验证仍依赖模型判断；多模态原生支持图片/PDF 上传分析。**弱点**：2025 年初 ChatGPT 多次因误给付费墙新闻 URL 翻车（来源：baidu.com 媒体报道）；不显示可信度评分；不做论证拆解。

### 6. Grok (xAI)（⛏️ 有完整系统提示词）
xAI 2025-05 开源了 Grok 全套系统提示词（github.com/xai-org/grok-prompts），可清楚看到其设计哲学：
- **Chat 模式**：默认「思考模式」按钮开启即做推理；DeepSearch 模式迭代搜索网络。
- **DeepSearch Summarizer 提示词**显式要求：
  - 直接回答部分以**关键点 + 简短章节**开始，然后才是「调查部分」（survey section）。
  - 「关键点必须根据你的不确定程度具有适当的自信程度，并突出显示有关该主题的任何争议。」
  - 「**仅当问题绝对不敏感/不争议**且你**绝对确定**时才使用绝对陈述。否则，使用承认复杂性的语言，例如『research suggests』『it seems likely that』『evidence leans toward』，以保持内容易于理解和开放式，尤其是在敏感或有争议的主题上。」
- **Grok Explain 模式**（分析 X 帖子）：要求「**优先考虑同行评审的研究，并对来源持批判态度以避免偏见**」——这是少数在提示词层面显式要求「信源评级」的设计。
- **关键引用部分**：每条引用附长描述性标题（约 10 词），要求 URL 嵌入 markdown 内联。
**特点**：X 平台原生（可读 X 帖子、用户画像）；多语言支持。**弱点**：DeepSearch 输出"调查笔记"风格，文档长而非结构化分解；不做事实/价值判断分类。

### 7. 秘塔 AI 搜索 (metaso.cn)（⛏️ 第三方测评 + 官网）
上海秘塔网络科技 2024 年初上线，自研 MetaLLM。**核心特点**：
- 无广告纯净搜索
- 结构化输出：思维导图、大纲、表格、PPT 导出
- 三种模式：**简洁** / **深入** / **研究**（学术资源聚焦）
- 学术模式：覆盖中英文文献，可生成 APA/MLA 参考文献
- 法律/金融垂直：自动输出法规时间线、司法解释对比
**官方披露**："上线数月即突破数百万访问量，日均搜索量超千万次"。**弱点**：信息不足时给「暂无可靠证据」但无显式可信度分；图像/视频搜索在 2026 路线图中。

### 8. 360 AI 搜索 (ai.so.com)（⛏️ 官网 HTML）
360 集团 2024 年推出的 AI 搜索产品，定位「搜索 Agent，你的全能搜索助手」。首页 HTML 显示：接入性能监控（首屏性能、LCP、FCP、LongTask），强调作为 iframe 嵌入 360 搜索结果页。**机制**：360 智脑 + 第三方模型（Kimi、豆包等）+ Agent 化任务流。**用户规模**：依托 360 搜索流量（市场份额约 1%），AI 搜索子产品未单独披露。

### 9. 纳米 AI 搜索 (n.cn)（⛏️ 首页抓取）
360 系子产品，主打「多模型路由」，聚合国内主流大模型（自研 + Kimi + 豆包 + 智谱 + MiniMax 等），用户可切换底层模型。首页可见 GA 分析、QAPM 监控等 360 系基础设施痕迹。**用户规模**：未单独披露。

### 10. 百度 AI 智能回答 / 文心一言搜索增强（📚）
百度搜索结果页 AI 答案（2023 起逐步推广）+ 文心一言 App/ERNIE 大模型。**机制**：百度搜索索引 + ERNIE 4.0（多模态）+ 多步 RAG。**特点**：与百度搜索深度绑定，触达 6 亿+ 搜索用户；引用脚注可见。**弱点**：来源标注不区分等级；不拆解论证结构。**用户规模**：百度 AI 搜索日均 8000 万次 AI 摘要调用（2024 财报）。

### 11. Kimi 探索版 (Moonshot AI)（⛏️ 首页确认）
2026-07 K3 上线，定位「专为智能体编程与知识工作打造」。**机制**：超长上下文（早期 200K → 现 2M）+ 工具调用 + 联网 + Agent 任务（首页明确支持 "Agent 任务"）。**特点**：开源 + 月活 3000 万+；深度研究模式主动规划多步搜索。**弱点**：不专门做论证类型分类；适合"研究一个问题"而非"核查一条说法"。

### 12. 智谱清言 / 通义千问 / 文心一言 搜索增强（📚）
- **智谱清言**：GLM-4 + 智能体编排（Z 智能体）+ 联网；2025 推出「智谱清言」App。
- **通义千问**：Qwen 长上下文 + 联网 + 通义点金（实时联网增强）+ Qwen-VL 多模态；模型开源下载 700 万+。
- **文心一言 4.0**：百度文心 + 联网 + 多模态（ERNIE-ViLG）。
**共同弱点**：作为「通用大模型 + 搜索增强」组合，不专门做论证结构分解；不显式给可信度评分。

## 三、关键差异化对比（用户重点关心的四个问题）

> 本节用三个表格回答调研委托中的核心问题。

### 3.1 论证结构分解（能不能把一句话拆成事实/价值/因果/预测四类？）

| 竞品 | 是否做论证结构分解 | 备注 |
|---|---|---|
| Perplexity | ❌ | 按主题拆子问题，不做断言类型分类 |
| You.com Research | ❌ | 拆任务流，不拆断言类型 |
| Brave Leo | ❌ | 单轮 QA，不做拆解 |
| Copilot Deep Research | ⚠️ 拆子研究问题，但不拆断言类型 | 偏 "研究任务计划" |
| ChatGPT Search | ❌ | 直接给出综合回答 |
| Grok DeepSearch | ⚠️ 输出"调查笔记"，按工具调用顺序展开，不分类 | 系统提示词明确说"survey section"风格 |
| 秘塔 | ⚠️ 输出"大纲/思维导图"，相当于浅层结构化 | 自动整理但仍按主题，不按断言类型 |
| 360 AI / 纳米 AI | ❌ | 通用搜索 |
| 百度 AI / Kimi 探索 / 智谱 / 通义 / 文心 | ❌ | 通用搜索 + 任务流拆解，不做断言类型拆解 |
| **目标产品（中文 AI 核查 Agent）** | **✅ 应做** | 这是核心差异化卖点 |

### 3.2 混合判断识别（单句内「事实 + 价值 + 因果 + 预测」混合）

| 竞品 | 表现 |
|---|---|
| Perplexity / You.com / Brave / Copilot / ChatGPT / Grok / 秘塔 / 百度 / Kimi / 智谱 / 通义 / 文心 | **❌ 全部不做**。所有竞品把整段说法当一个 QA 任务处理，输出综合答案时不会显式标出「这一句里前半是事实陈述、后半是价值判断、末尾是因果推断」 |
| **目标产品** | **✅ 应做**：这是核查型 Agent 的关键差异化 |

### 3.3 相关 vs 因果区分

| 竞品 | 表现 |
|---|---|
| 全部 12 个 | **❌ 没有一家做显式区分**。即便是 Grok DeepSearch 的"调查笔记"也只输出"研究表明 / 证据倾向于"这类 hedging 措辞，不会标注「这条证据是相关关系，不是因果关系」 |
| **目标产品** | **✅ 应做**：核查场景下"相关 ≠ 因果"是高频陷阱 |

### 3.4 证据评级（信源可信度评分）

| 竞品 | 评级深度 |
|---|---|
| Perplexity | ⚠️ **「grounding 硬约束」**：检索不到就不答，但不给分。Sonar Pro 的引用数约为基础 Sonar 的 2 倍 |
| Grok Explain 模式 | ⚠️ 提示词显式要求「**优先考虑同行评审的研究，并对来源持批判态度以避免偏见**」——是 12 家中唯一在系统提示词里**显式要求信源评级**的设计；但不输出数字分 |
| Copilot / ChatGPT / Brave | ⚠️ 显示引用 URL，无评分 |
| 秘塔 学术模式 | ⚠️ 倾向学术资源（期刊、数据库），相当于隐式偏好 |
| 其他（You.com / 360 / 纳米 / 百度 / Kimi / 智谱 / 通义 / 文心） | ⚠️ 引用可见，无评级 |
| **目标产品** | **✅ 应做**：分级信源（官方文件 > 学术论文 > 权威媒体 > 一般媒体 > 自媒体 > UGC）+ 加权评分 |

## 四、总结：通用 AI 搜索/总结工具 vs 专业核查 Agent 的边界差异

> 这一节回答用户的核心战略问题——我们的产品到底和 Perplexity / Kimi / Copilot 有什么不同，能不能替代它们。

### 4.1 相同之处（看起来很像的部分）

1. **底层都是「检索 + LLM」**：12 家竞品和我们都依赖「实时检索 + 大模型总结」的 RAG 范式。基础设施同质化严重——索引、向量数据库、prompt 工程这些底层能力上我们没有代差优势。
2. **都附引用链接**：从 Perplexity 到 Kimi，「段后附 URL」已是标配；用户对「没引用 = 不靠谱」已经形成共识。
3. **都做"多步研究"**：Copilot Deep Research、Perplexity Pro Search、Grok DeepSearch、Kimi 探索版都在做"主动规划多步搜索"。这是 2025 年以来 AI 搜索的主流演进方向。
4. **都支持多模态输入**：2025 年后所有主要玩家都已支持图片/PDF/截图上传分析。

### 4.2 真正的边界差异（我们的护城河）

通用 AI 搜索的设计目标 = **"我有一个问题，给我一个答案"**。
专业核查 Agent 的设计目标 = **"我有一条不确定的说法，给我拆开看里面哪些是事实哪些是观点哪些是编造"**。

这个目标差异导致五个根本不同：

| 维度 | 通用 AI 搜索（12 家竞品） | 专业核查 Agent（我们的产品） |
|---|---|---|
| **输入对象** | 用户的问题（开放域） | 用户的说法/截图/链接（待验证的命题） |
| **核心动作** | 搜索 + 总结 | 拆解 + 验证 + 评级 |
| **输出形式** | 一段流畅的综合答案 | **结构化证据链**：每条子命题 × 证据 × 可信度 × 评级 |
| **核心要求** | 答案的流畅性、覆盖度 | 论证的严谨性、来源的可靠性、断言的可证伪性 |
| **失败模式** | 编造（幻觉） | 不可证伪时回避（abstention） |

具体来说，我们在以下五个点上**必须**做到竞品做不到（或做得不够）：

1. **论证结构分解**：把"吸烟有害健康"这类混合命题拆成「事实层（吸烟有害健康有医学证据）/ 因果层（吸烟→肺癌的因果关系）/ 价值层（有害意味着要禁烟的政策含义）」三层分别评估。**12 家竞品没有一家做。**
2. **混合判断识别**：识别"中国男足没救了"这类「事实判断（男足表现差）+ 价值判断（没救）+ 因果推断（训练体系问题）+ 预测（未来也不会好）」一句话里的四类断言，并分别给证据。**12 家竞品不做。**
3. **相关 vs 因果区分**：明示"这两个变量相关，但本证据不足以支持因果结论"。**12 家竞品没有显式区分。**
4. **证据评级**：用 NATO Admiralty Code（来源可靠性 A-F + 信息准确性 1-6）或类似框架给每个证据打分；不只列 URL。**Grok Explain 在提示词里要求"信源批判"，但没输出评级；其他 11 家不做。**
5. **"能说/不能说"边界**：当证据不足时明确拒绝下结论（"在现有公开证据下，该说法既不能证实也不能证伪"）。**Perplexity 有类似的硬约束（"grounding 原则"），但它的目的是防幻觉，不是做证据等级评估；其他家做得弱或不做。**

### 4.3 我们的产品定位

综合上述差异，中文 AI 核查 Agent 的核心价值主张应是：

> **「不是替代 Perplexity 帮你搜答案，而是当别人（KOL / 朋友 / 营销号 / 截图里的「专家」）抛给你一个说法时，帮你 30 秒看清这条说法里有多少可信的、有多少是编造的、有多少是观点包装成的'事实'。」**

定位关键词：**论证拆解 + 证据评级 + 边界声明**。这是 12 家通用 AI 搜索在 2026 年仍没有的差异化能力，也是中文信息环境（短视频、微博、营销号、自媒体）里用户最稀缺的能力。

## 六、给产品的具体建议（基于竞品调研）

1. **核心差异化必须是「论证结构分解」**：这是 12 家竞品都没做的差异化点，且与核查场景强匹配。MVP 必须有。
2. **证据评级框架建议参考 NATO Admiralty Code**：来源可靠性 A-F + 信息准确性 1-6。Grok Explain 的提示词思路（"优先同行评审、对来源持批判态度"）印证了这个方向的价值。
3. **「能说/不能说」边界要做成产品特性**：当证据不足以支持断言时，明确说「不可证」而不是硬给答案。这是 Perplexity 验证过的产品体验（"grounding 硬约束"换来用户信任）。
4. **相关 vs 因果要在 UI 上明示**：在证据卡片里加「证据类型：相关 / 因果 / 案例 / 专家意见」标签，避免用户把相关关系当因果结论。
5. **中文场景优势**：秘塔、360、纳米、百度、Kimi、智谱、通义、文心这些国产玩家在「中文检索深度」上有天然优势（百度百科、中文新闻、社区论坛覆盖度）。但它们都没做论证拆解——这是我们的机会窗口。
6. **图片/截图能力是必选项**：12 家竞品都已支持图像/PDF/截图输入。我们的产品既然面向"用户截图发给我核查"，必须做好截图 OCR + 文本提取 + 多模态理解。
7. **商业模式参考 Perplexity + Comet**：订阅 + 出版商分成；可考虑"核查报告导出"作为付费功能。
