和 AICSS 同类的过程表达

看的是「思考 / 工具 / 正文」怎么分块，不是把调查做成聊天。对我们：过程贴在拆问题下面、问题列表上面；做完收成一行。

你点的原件

AICSS

Thinking 是 shimmer 标签。Thinking + Reasoning 工作时展开，结束后收成 “Thought for Ns”，还能点开。工具是单独一张卡（diff、出图），正文是另一块。

拿：分块、做完就折、工具出成果不出口令。

Vercel

AI Elements · Reasoning · Chain of Thought · Tool

Reasoning 流式时自动打开，结束后自动关上。Chain of Thought 是一步一步的步骤条。Tool 是调用卡，不是聊天气泡。

拿：工作时开、完成后关。几截可以当步骤，不是独白。

assistant-ui

assistant-ui GroupedParts

把 reasoning、tool-call、source 收进同一顶「Thinking」，正文留在外面。过程默认一团，答案单独读。

拿：拆开的几截和内部步骤共用一个可折的「过程」，问题列表不进这个折里。

产品里的一行

Scrim UI · beUI Agent Activity

工具是一行：search_docs 1.2s，点开才有参数和结果。Reasoning 也是 “Thought 4.1s”。beUI 的 Tool Result 做完收成短状态。Scrim 还有 Agent Console（步骤、费用、取消）——那是运维台。

拿：过程默认一行。 不拿：费用、token、运行控制台。

21st / Agent Elements

ThinkingTool · MCP Tool

思考也做成和工具同一排：shimmer「Thinking」→ 完成「Thought」。MCP Tool 有 pending / completed，参数和 JSON 输出可折。

拿：思考和动作同一套行，不要聊天气泡。JSON / search360 只进折里。

产品原件，不是组件库

Claude / ChatGPT 的 Thought for Ns · Cursor 的工具行

大家都在抄这一下：思考默认收着，工具是文件 diff、搜索结果这种成果，不是 “tool: skipped”。Cursor 把改文件画成 diff 卡，插在回复前面。

拿：成果当卡。对我们，拆开的几截就是这张卡；问题列表才是回复。
