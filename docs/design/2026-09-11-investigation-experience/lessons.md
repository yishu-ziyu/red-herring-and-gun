# 测试过程中失败经验的记录

用户原话：**「现在测试过程中失败的经验，就是我们之后任务成功的希望。」**

这份文件只记**跑出来的**失败——不是设计推演、不是「可能要注意」，是真跑红过、
真在现场看到过的东西。每条写清：检查项、失败值、根因、改法、怎么防止复发。

日期：2026-09-11。对应的验收契约在各条的「契约」行。

---

## 一、把「没实现」当成「已完成」

### F1 · 争点在完成态根本不渲染

- **检查项**：A15「同一个 claim 下双方各自可点」。
- **失败值**：写完两侧独立按钮后，测试仍然 5 条全红，`data-gp-conflict-side` 一个都查不到。
- **根因**：`ClaimSection` 里 `asResult ? <p>只有一句原因</p> : <>两侧按钮</>`。完成态走的是
  上面那一支——**结果页上争点从来就没有可点的地方**。我读代码时只看了 `else` 分支。
- **改法**：把两侧渲染提到分支外面，两种状态都渲染。
- **复发防线**：契约里写「完成态也要渲染这两侧」，测试直接断言 `data-gp-conflict-side`。

### F2 · `modelsListHandler` 被顺手改坏

- **检查项**：既有门禁。
- **失败值**：无（这次是靠 `tsc` 没有报错、但语义已变）。
- **根因**：用 `edit` 改一个只有一行上下文的函数头时，把 `if (req.method !== "GET") return next();`
  削掉了。方法判断不见了，逻辑不会报错但行为变了。
- **改法**：补回。
- **复发防线**：改函数头之前先 `read` 完整函数体；`oldText` 要包含整段要保留的行。

## 二、「看着完成了，其实是假的」

这一类最贵：界面看起来对，用户看到的状态是假的。

### F3 · 取消的终态帧到不了客户端

- **检查项**：D20 停止三态。
- **失败值**：真实浏览器里点停止 → 显示「正在停止」→ 10 秒后画面自己翻成「调查中断」，
  永远等不到「已停止」。DB 里 run 状态却是 `cancelled`。
- **根因**：`sendEvent` 直接把帧写进 `res`。取消是从**另一个请求**（POST cancel）发起的，
  那条路径不经过当前流的 `res`，所以终态帧没有任何出口。
- **改法**：把总线设成唯一出口——`sendEvent` 只负责 `runs.publish`，处理函数自己也订阅总线，
  由订阅回调统一写 `res`。取消端点在返回前 publish 一帧 `run_state: cancelling`。
- **复发防线**：契约里写「客户端不能靠 POST 回执猜流上的状态」；`run_state` 有专属测试。

### F4 · `writeFrame` 用错了信号，超时的中断帧一直没发出去

- **检查项**：既有超时路径。
- **失败值**：取消后流里没有 `error` 帧、没有中断快照、没有终态帧，只有 50 帧就断了。
- **根因**：写帧前的守卫是 `if (res.writableEnded || disconnect.signal.aborted) return;`。
  而 catch 块里第一件事就是 `disconnect.abort()`——那是「停管线」的意思，不是「别写了」。
  两者混用的后果：**abort 之后的所有帧全被丢掉**，包括超时路径里那条写了很久的中断帧。
  也就是说：**超时的时候前端从来就没收到过中断帧**。不是本轮引入的。
- **改法**：守卫只看 `res.writableEnded || res.destroyed`。
- **复发防线**：注释写清两个信号各自的意思；取消/超时路径的帧用真实 curl 验过再算数。

### F5 · 说了「重新调查一次」，却没有那个按钮

- **检查项**：A19 停止后的可操作性。
- **失败值**：截图里「已停止」下面写着「想看完整判断就重新调查一次」，页面上没有任何按钮。
- **根因**：`reviewAgain` 只在 `complete` 或 `interrupted` 时渲染；`stop === "stopped"` 时
  两条都不成立，于是文案有了、入口没有。
- **改法**：已停止的分区自带「重新调查」与「返回首页」。
- **复发防线**：加测试「说得出就必须点得到」。

### F6 · 同类问题的第二次：「同步失败，重试」也没有重试

- **检查项**：A21 保存失败可见且可重试。
- **失败值**：保存状态文案是「同步失败，重试」，但它是 `<span>`，点不动。
- **根因**：和 F5 是同一个病——文案先写了动作，动作没做。落库逻辑写在一个只在
  `finalReport` 首次出现时跑的 `useEffect` 内联 IIFE 里，没有可以再调一次的函数。
- **改法**：把落库抽成 `persistResult(report, localId, claim)`，失败时渲染成按钮；
  没有回调时渲染成纯文本并给测试，不允许出现可点的假按钮。
- **复发防线**：**凡是文案里出现动作词（重试 / 查看 / 重新调查 / 展开），测试里必须有对应的
  可点元素断言。** 这条已写成纪律。

### F7 · 用户点了停止，结果被报成「已完成」

- **检查项**：D13 终态不可逆。
- **失败值**：第二次真实取消时，管线刚好在写最后一份报告，run 被落成 `completed`。
- **根因**：`finish(runId, "completed")` 无条件接受调用方给的状态；`cancelling` 不是终态，
  于是被 `completed` 覆盖。
- **改法**：`cancelling` 永远不能变成 `completed`——用户点了停止，我们不报完成。
- **复发防线**：两条测试（点了停止的 run、没点停止的 run）。
- **注**：这个是**跑出来的**，不是推演出来的。第一次取消碰巧在阶段边界，看起来是好的。

## 三、测试自己的坑

### F8 · 跑测试会清空开发库

- **检查项**：无（是我自己发现不对）。
- **失败值**：`caseStore` 换成 SQLite 后，`DATA_DIR` 默认是 cwd 下的 `.data`；
  测试 cwd 是 `apps/`，于是 `beforeEach(clearCases())` **直接清掉了开发库的 cases 表**。
- **根因**：测试没有隔离数据目录。
- **改法**：`src/test/setup.ts` 把 `DATA_DIR` 指向本次进程的临时目录。
- **复发防线**：新加存储（SQLite / 文件）必须先确认测试落在临时目录。
- **代价**：`apps/.data/` 是被我删掉的（里面只有本次测试产生的库）。

### F9 · 测试里的 `requestCode` 有重发冷却

- **检查项**：S7–S9 的分享权限测试。
- **失败值**：`verifyAndCreate` 返回 `ok:false`，`sessionId` 是 undefined，
  于是 `reqWith(undefined, ...)` 造出一个 9 字符的 `"undefined"` cookie，
  所有断言都 404——看起来像权限逻辑坏了，其实是会话没建起来。
- **根因**：同一个邮箱反复 `requestCode` 会命中冷却，第二次拿不到新验证码。
- **改法**：测试内按邮箱缓存会话，一个邮箱只登录一次；`sessionFor` 里断言 `ok` 并抛错，
  不要用 `!` 把 undefined 蒙过去。
- **复发防线**：**测试里的 `!` 非空断言是掩盖失败的高发区**，能断言的先断言。

### F10 · 断言选到了错误的元素

- **检查项**：E3 点反驳侧打开反驳侧来源。
- **失败值**：断言 `document.querySelector("[data-gp-source-id]")` 拿到的是**证据行**的
  `data-gp-source-id`，不是抽屉里的那个，于是「点左边打开了右边」这个假象看起来像真 bug。
- **根因**：同一个属性名在多个组件上出现，选择器没限定作用域。
- **改法**：作用域限定到 `[data-gp-source-layer]` 内。
- **复发防线**：跨组件断言一律带作用域。

### F11 · jsdom 没有布局，「不抢滚动」测不出来

- **检查项**：C15 用户上滚时新发现不抢滚动。
- **失败值**：初次跑必然「通过」——因为 `scrollHeight/clientHeight` 都是 0，
  永远判定为「贴在底部」，那个「有 N 条新发现」的按钮永远不会出现。
- **根因**：jsdom 不做布局计算。
- **改法**：用 `Object.defineProperty` 把 `scrollHeight` / `clientHeight` 定死，
  再派发 scroll 事件，把「用户已经上滚」这个前提真的造出来。
- **复发防线**：任何依赖几何/滚动的断言，先确认前提在 jsdom 里成立。

## 四、环境与工具

### F12 · Chrome headless 截图挂死

- **失败值**：`--headless --screenshot=` 直接卡住 120 秒超时，不留文件。
- **根因**：默认 profile 与已存在的 Chrome 实例冲突；`pkill` 用的模式没匹配到子进程，
  第二次启动时 9222 端口上还挂着旧实例，`/json/version` 返回 404。
- **改法**：改用 CDP（`--remote-debugging-port` + `Page.captureScreenshot`），
  每次用新的 `--user-data-dir`，端口换一个，启动后先验 `/json/version` 再跑。
- **复发防线**：截图脚本共用一份（本文档同目录的流程），不每次现写。

### F13 · `node:sqlite` 在前端测试环境里解析不了

- **失败值**：`Cannot bundle Node.js built-in "node:sqlite"`，jsdom 环境直接红。
- **根因**：vitest 全局用 jsdom，静态 import 内置模块会被 vite 解析。
- **改法**：驱动改成运行时 `createRequire` 加载（同时天然成了降级点），
  类型用 `import type` 擦掉。
- **复发防线**：新增 Node 内置依赖一律走运行时加载 + 能力探测 + 回退。
