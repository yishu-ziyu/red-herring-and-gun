三种探索模式横向对比 (使用完全同构生产形态设计夹具)

统一消费生产形态夹具 (production-shaped design fixture，含 2 Claim, support, contradict, context-only, gap, conflict, directAnswer)

Mode 1 — Editorial Calm
参考：Nikoloz Zaalovich / CollectUI Blog
核心感官：严肃深度调查报道
彻底去除卡片盒子、阴影与圆角。依靠严格字阶比（12/14/15/18/26px）、大留白与 1px 发丝分割线。原话为 Quote，结论为首段 Lede，证据为 Citation Row，Gap/Conflict 为边注。静止截图即成立。
Mode 2 — Interactive Evidence
参考：Cuberto / CollectUI UI Interaction
核心感官：材料归位的物理连续性
仅借用 Cuberto 的“对象身份连续”机制。拒绝滚动劫持与炫技。实现真实 Persistent DOM Identity：材料从 ◌ 待核对 通过 FLIP 平滑移动至 ● 支持/反驳/相关，before === after 同一 HTMLElement 节点未销毁，无 innerHTML 擦除。
RECOMMENDED
Mode 3 — Hybrid / Red Herring
《红鲱鱼与枪》专属调查美学语言
核心感官：有生命的证据，答案自然长出
融合 Editorial 的文稿骨架 + Cuberto 式物理连续 + Edo 式克制文字动效。完整兑现三大签名交互（Claim Trace、Evidence Settling、Conclusion Emergence），无任何 Card-on-card 压迫感与彩虹色底块。

三大认知型签名交互 (Signature Interactions)

只保留具有强解释力的动效，坚决删除装饰性、表演性动画

① Claim Trace (命题回溯)
鼠标悬停或聚焦命题 01 时，原始说法中的“维生素 C 能治感冒”被精确高亮，悬停命题 02 时高亮“每次感冒都应该输液”。严格由纯函数 buildTraceSegments(quote, claims) 驱动，无 span 时不高亮，彻底废除手动 token 映射。
② Evidence Settling (证据归位)
材料初进场为 ◌ 待核对。核查完成后，同一个 DOM 节点平滑位移至对应结论组（before === after），Glyph 渐变为 ● 支持 或 ● 反驳。传达“调查桌上的同一叠材料被放到了它真正属于的档案袋”。
③ Conclusion Emergence (结论自然生长)
调查中结论区不占位。随着证据稳定，下方调查正文平滑向下让位，同一 directAnswer 大标题沉着浮现。不是系统在盖章宣布答案，而是用户肉眼看见答案从证据中自然长出。

Edo / kugiri (0.4.0) 孤立技术 Spike 裁决

裁决：不引入生产依赖（原生 CSS 语义 mark + 现有 Motion 胜出）

实测维度 kugiri (0.4.0) 表现 现代原生 CSS / 现有 Motion 表现 裁决结果
中文长句与标点禁则 基于 Intl.Segmenter 拆分后破坏标点挤压，跨 span 产生缝隙 排版引擎底层遵守 line-break: strict，无缝渲染 原生胜出
中英混排与 inline 标签 折行时克隆 <a>/<strong>，导致 DOM 节点膨胀与 ID 重复 DOM 节点保持单节点树结构，事件与外链天然完好 原生胜出
text-wrap: balance 原生交互 Actual Runtime (初始切分测量) + Structural Inference (动态重平衡受限推论)：Case 5 运行时实测读取 textWrap 并切出行数与行宽；结构推论表明硬拆分后原生 balance 算法无法跨独立 div 块动态重排（本测试未执行动态 resize 观察） 浏览器排版引擎在布局阶段一次性原生动态平衡 原生显著胜出
动态 Resize (1440/768/390px) 必须频繁调用 revert() 并重新 split()，引发掉帧 零 JS 介入，流式响应式排版，维持稳定 60/120 FPS 原生显著胜出

无障碍 (Screen Reader 语音朗读) Not tested（未跑实际系统级 TTS 语音合成）；根据 A11y 树结构审查，DOM 节点被打碎成数十个独立 span，若未深度加 aria-hidden 存在生硬逐字拼读风险（属于结构审查，非真实语音实测） 整句完整保留在 Accessibility Tree 中，语调连贯自然 结构风险高
kugiri 自身动画与 reduced-motion Not applicable：kugiri 仅为 DOM 拆分工具，自身不提供动画；原型业务层已通过 CSS prefers-reduced-motion: 0s 测试 外层纯 CSS 控制过渡与动画，无额外 JS 负担 原生统一控制

Quiet Editorial Evidence 视觉准则与灰度对比审查

结构决定层级，不靠颜色叫喊。灰度模式下排版、线框与层级 100% 成立

Quiet Editorial 来源抽屉（纸感背景 #FFFFFF，细线 #E7E5E4，深灰正文 #18181B，无彩虹高饱和底色）
全去色 Grayscale 审查：剥离所有颜色后，字阶比与留白仍清晰传递主次与下钻关系
四项硬性视觉准则：
  • 去语义彩虹 (No Semantic Rainbow)：严禁用红绿蓝紫整块底色区分支持/反驳/事实/争议，采用冷静符号（●、○、◌）与排版区分；
  • 纸感第一 (Paper-first Surface)：底色纯净白与极淡米灰（#F7F7F5），1px 发丝线（#E7E5E4），彻底消除重阴影与花哨卡片堆叠；
  • 自然文字表达 (No Stiff English Badges)：彻底删除小卡片上的大写英文标题（如 VERDICT OVERVIEW / CORE CITATION），使用自然中文调查记叙文风格；
  • 无障碍焦点闭环 (Modal Focus Containment)：Drawer/Sheet 弹层开启时背景设为 inert，Tab 键焦点严格闭环，Escape 即刻关闭并恢复主文档焦点。

12 项核心评审问答速查

点击可展开阅读详细工程理由

1. 最终入选了哪些外部参考？
入选 8 类高度聚焦的外部参考源：Cuberto、Nikoloz Zaalovich、Edoardo Lunardi/kugiri、CollectUI #Blog Post、#UI Interaction、#Tooltip/Drawer、#Empty States/Loading、#Quote。
2. 每个参考具体借了什么？
Cuberto：借对象身份连续性（FLIP）与微触觉物理阻尼；Nikoloz Zaalovich：借绝对排版层级与从容呼吸留白；Edoardo Lunardi：借文本克制进场与行级遮罩；CollectUI Blog：借严肃调查手记叙事流；CollectUI Drawer：借侧滑保留正文上下文；CollectUI Empty：借诚实平静的证据缺口展示。
3. 每个参考拒绝了什么？
拒绝 Cuberto 的营销滚动劫持与鼠标光标球；拒绝 Nikoloz 的低对比度灰字；拒绝 Edoardo 的打字机乱飞与逐字动画；拒绝常见 SaaS 的 Card-on-card 堆叠、Agent 头像、彩纸飞舞与报错红叉。
4. 哪一处已经真实映射到红鲱鱼与枪？
Evidence Settling：5 条材料从待核对平滑归入支持/反驳/相关；Claim Trace：Hover 命题时原话对应切片亮起；Conclusion Emergence：正文自然让位长出结论；Source Drawer/Sheet：点击证据展开包含 6 大字段的侧滑抽屉或底部浮层。
5. 三个模式最大的感知差异是什么？
Mode 1 (Editorial Calm)：一份静止已成立的严肃深度事实报道，毫无浮躁感；
Mode 2 (Interactive Evidence)：调查桌上的同一叠材料被整齐分拣到档案袋的物理因果感；
Mode 3 (Hybrid / Red Herring)：有生命的证据文稿，答案在眼前自然生长，原话与命题紧密互证。
6 & 7. 你推荐哪个？为什么？
推荐 Mode 3 (Hybrid / Red Herring)。
理由：Mode 1 虽美但调查中缺少对“正在发生什么”的解释；Mode 2 交互稍密集；Mode 3 兼具 Mode 1 的排版尊严与大留白，同时仅保留 3 个具有强认知解释力的签名动效，真正长出了《红鲱鱼与枪》专属的调查美学。
8. 哪些 Motion 是认知机制？
Claim Trace（一眼看清命题拆自哪几个字）、Evidence Settling（看清证据为何归为反驳）、Conclusion Emergence（视觉明确结论依赖于下方证据链）。
9. 哪些 Motion 只是装饰，因此被删除？
删除 Agent 节点连线发光、删除 AI 打字机逐字吐字、删除 Confetti 彩纸飞舞、删除骨架屏 Shimmer 狂闪、删除 3D 倾斜卡片。
10. kugiri 是否值得进入 production dependency？
结论：不值得。
技术缺陷评估（含实测与推论严格区分）：① CJK 标点挤压失效，跨 span 产生不自然字距空隙（实测）；② 折行复制 inline 标签导致 DOM 节点翻倍膨胀（实测）；③ text-wrap: balance 拆行硬封装为独立 div 块，破坏原生动态平衡引擎（初始切分实测 + 结构推论）；④ 动态 Resize 需频繁调用 revert() 并重新 split() 造成潜在掉帧（推论）；⑤ 屏幕阅读器无障碍：Not tested（未跑实际 TTS 语音合成），但结构审查显示 DOM 节点被打碎成数十个独立 span 存在断读风险；⑥ 字体加载时序：虽然支持就绪后测量（实测），但在 WebFont 未就绪前提前切行存在 font swap 错位风险（风险分析）。
因此，原生现代 CSS（语义 mark + line-break: strict）与现有 Motion 在 0 生产依赖下全面胜出。
11. Desktop / Mobile 是否都成立？
实测均完美成立：桌面 1440px 拥有 780px 黄金阅读中轴与 440px 侧滑抽屉；移动端 390px 单列流畅阅读，点击证据条自适应为原生手感的贴底 Bottom Sheet。
12. reduced-motion 后产品是否仍然成立？
完全成立：动画全部降为 0ms 即时生效，所有语义完全通过文字、字阶、符号（●、○、◌）与排版传递，无一处事实依赖动画。
