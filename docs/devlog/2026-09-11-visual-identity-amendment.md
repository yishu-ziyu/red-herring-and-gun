# 2026-09-11 · 视觉人格修正案

## 为什么改

用户裁决（原话）：「去他妈的产品宪法，我们就（改）宪法；但我觉得现在的展示真的比第一版垃圾太多了……哪怕后端好很多，我们的展示面却一直在退步。」

复盘成立的部分：第一版（v1.0.0，`mvp/public/agents/*.png` 四个像素角色 + Case Workbench）视觉上有角色、有层次、有动效；2026-09-05 Product Reset 之后，产品面收敛成一篇排版正确但没有表情的文档。视觉资产被当作「Agent 前台上脸」一起清掉，这是过度纠正。

根因不是执行，是设计文档失职：`docs/design/2026-09-06-design-reference-pack.md` 通篇是禁令（不玻璃、不卡片、不连线、最多三个动效母题、不因为有趣而加动效），没有一条正向目标。只有禁令的设计系统必然长成灰纸。

复盘不成立、需要顶回去的部分：第一版好看的来源分两半——一半是角色、层次、动效（要拿回来），另一半是假 Agent 面板、编造的五维可信度、演示态搜索（不能拿回来）。「后端好很多」在工程纪律上成立（真检索、逐条核查、证据追索、引用绑定闸门、公式评分、600+ 核心测试），在判断准确率上**没有被证明**（eval:gate 基线长期红、LIVE 未获批、真实用户路径未完整验收）。两件事不能混着说。

## 改了什么

1. `docs/PRODUCT_SPEC.md` 第六节：删掉「多 Agent 角色不是核心 UI」这条把视觉人格一并禁掉的表述。保留：执行过程（Agent 名、tool call、provider、模型推理、内部日志）不上前台；新增允许：产品可以有拟人化的视觉角色，条件是角色不出现在执行流程里、不伪装成判断者、不代表证据。
2. `docs/PRODUCT_SPEC.md` 第二节原则 2：补一条正面义务——视觉验收必须写正向目标（画面该长什么样、对照什么资产），不得只用禁令验收。
3. `docs/design/2026-09-06-design-reference-pack.md`：把「不重新引入 Mission Control / Agent stage / tool log」拆开——tool log 仍然禁止；角色与美术资产解禁，并要求补正向美术方向。

## 保留什么（不跟着一起废的）

- Evidence Auditability > Agent Observability：展示证据与判断，不摊执行日志。
- 支持 / 反驳 / 仅相关 / 尚缺 / 争议 必须绑定出处；无证据 ≠ 假。
- 不为演示制造冲突、不编造质询记录、不写模型记忆当事实。
- 角色要老实：出现位置与材料状态绑定，不表演「正在思考」。

## 后果

产品需要一份正向美术方向（角色系统、像素资产规格、动效预算），而不是继续加禁令。#53 的验收标准随之补正向项：截图对照第一版资产 + 人评观感。
