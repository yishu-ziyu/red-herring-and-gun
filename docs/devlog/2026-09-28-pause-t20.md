# 2026-09-28 暂停 T20，`apps/` 是生产唯一真相

用户 2026-09-28 裁决：暂停 T20（生产切到 `packages/` 脊柱）。ADR-007 的长期方向不撤销；撤销的是「T20 即将发生」这一现状判断，以及由此而来的「新逻辑两边都写」规矩。

## 为什么

按「代码松散度」口径（earendil.com/posts/measuring-code-sloppiness）复盘仓库时发现：

- 离切换很远。2026-09-17 `scripts/qa/check_t20_readiness.mjs` 退出 1：`packages/server` 缺模型列表、可用性、额度、账号接口（404），health 与历史接口形状不兼容。规模上 `packages/server` 768 行对 `apps/server` 28,250 行；`packages/web` 3,224 行对 `apps/src` 23,572 行，而现行 Golden Path 是在 `packages/web` 之后才写的。T20 实际等于重写，不是最后一步。
- 已无人推进。`packages/` 9-03 当天 80 个提交，此后约每周 1 个。
- 双写在收税且已漂移。`apps/server` 与 `packages/core` 之间 jscpd 测得 7,891 行重复；无守护的拷贝已分叉（`publicCopy.ts` 两边差 156 行，`agentProviders.ts` 584 对 606 行）。

## 现在的规矩

- `apps/` 是生产唯一真相。修 bug、改行为只改 `apps/`，不再同步到 `packages/core` 的无守护拷贝（`publicCopy`、`searchProviders`、`citationBinding`、`agentProviders` 等）。
- `investigation/` 字节镜像保留：它有 `mirror.test.ts` 双向守护，不会漂移。改快照仍两边一起改。
- `packages/` 冻结：不删，不再往里加功能，根目录测试与构建照跑。

## 代价与恢复条件

`packages/web`、`packages/server` 那套更干净的结构暂时用不上（复杂度集中度 0.22 / 0.08，`apps/` 为 0.62–0.70）。恢复 T20 时，要从当时的 `apps/` 重新同步领域代码，并先让 T20 兼容探针通过。
