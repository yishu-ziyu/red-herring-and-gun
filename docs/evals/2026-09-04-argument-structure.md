# 论证结构与核查义务

## Change

- 对包含多个事实、因果、条件、比较或预测的原句，系统把用户实际声称的命题、命题之间的推断关系、以及系统为了核查而提出的问题分开保存。
- 用户声称的前提、结论和推断关系都可被独立取证与裁决；一个前提成立，不能自动使推断关系或结论成立。
- 原句中的否定、程度、数量、时间、对象范围、条件和确定性必须保留。系统补出的核查条件不能显示成用户说过的话。
- 后续检索能根据尚未解决的命题或推断关系选择下一项核查动作；没有足够证据时停在还查不清。
- 普通单一事实仍走现有路径，不增加用户可感知的确认步骤。
- 真实案件页先直接回答原句，再让用户看见原句分别在哪一截得到支持、哪一步推不出来、还需要确认什么；每一截的出处就近出现。
- 用户原话与系统提出的待确认条件在视觉和措辞上明确不同。用户不需要理解命题、节点、边、核查义务等后台术语。
- 桌面和手机上的默认视图都保持一个清楚的阅读顺序；过程细节可以展开，但不能抢过直接回答。

## Not this

- 不是把一句话机械切成更多短句或项目符号。
- 不是把模型常识、隐含背景或搜索结果补写成用户原话。
- 不是只改提示词、界面标签或解释文案，却仍让整个复合句共用一个判决。
- 不是把相关性、时间先后或一个真实前提直接当成因果关系成立。
- 不是为了覆盖示例而硬编码连接词或具体句子。
- 不是节点图、Agent 控制台、思维过程直播或一屏卡片墙。
- 不是只在说明文档里解释拆解，实际案件页仍然只给总分和整段总结。

## Evaluator

- 机器评：协调者持有的独立论证样本检查原句命题覆盖、无增添、独立可裁决、关系恢复、限定词保留、核查义务来源隔离，以及后续动作是否由未解决项驱动；实现者不可见样本、权重和原始结果。
- 机器评：聚焦测试、`npm test`、`npm run build`、`npm run eval:gate` 全绿。
- 浏览器评：真实复合案件在桌面和手机路径中都按“直接回答原句 → 哪一截有问题 → 对应出处”阅读；用户原话与系统待确认项不会混淆。
- 人评：用户查看真实案件，能说清系统分别核了什么、哪一步推不出来、为什么继续查或停止，并确认界面足够清楚、克制和优雅。
