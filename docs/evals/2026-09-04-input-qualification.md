# 2026-09-04 · 首轮输入是否进入核查

一句话：只有包含明确、可核对说法的首轮材料才能进入检索；其余输入在检索前得到一次明确回应，并能在同一案件继续补充。

## Change

- 明确的可核对说法沿用现有核查路径。
- 缺少必要对象或上下文时先澄清，不启动检索。
- 没有具体说法或只有主观评价时说明边界，不生成事实判决。
- 用户补充后仍在同一案件继续，不丢失原材料。

## Not this

- 只改提示词或前端文案，后台仍然启动检索。
- 把短句、口语或“听说”一律拒绝。
- 为通过少量样例硬编码词句。
- 破坏现有正常立案、拆题、来源和报告路径。

## Evaluator

- 独立评估工具由协调者在实现上下文之外维护；执行者不接触具体案例、权重和原始结果。
- 协调者检查搜索调用边界、案件事件、用户可见回复、补充后的连续性，以及正常路径回归。
- 仓库公开门禁：`npm test`、`npm run build`；行为变更再跑 `npm run eval:gate`。
- 人评：澄清问题是否具体、自然，正常用户是否被增加了不必要步骤。

## Goal / Hard bar / Improve

- Goal：先判断有没有明确的可核对说法，再决定是否搜索。
- Hard bar：独立评估中的阻断、继续和回归三类行为全部通过；公开门禁全绿；真实浏览器路径与代码行为一致。
- Improve：在不增加正常路径确认步骤的前提下，减少无效检索与错误立案。
