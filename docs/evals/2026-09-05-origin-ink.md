# 案件页用句内三层墨读论证结构

## Change

- 有结论的案件页上，用户先看到对原句的直接回答，再看到完整原句，原句仍是一句。
- 原句从 `current.text` 与用户消息中选出：必须能唯一、完整承载当前可核命题；多条都符合时用最新一条。不把多条消息拼成假原句。
- 没有单一明确来源时不启用句内涂，仍用命题列表。
- 原句里只涂 `source.slice(span)===claim.text` 或该原句内唯一精确出现的用户命题；span 对不上且出现多次或不存在则不涂。
- 该命题的出处编号紧跟在这截字后面，能点开。
- 主库没有明确 relation/cueSpan 时，不把命题间隔标成推断，也不生成「系统还要核」。
- 命题墨色中性，不暗示真假。

## Not this

- 把原句拆成卡片墙或节点图。
- span 只检查下标合法就涂色。
- 同一句有两条命题就当推断或系统义务。
- 可核命题一律绿色底。
- 合并未验收的后端 worktree。
- 只改选择原型 HTML。

## Evaluator

- 机器评：`locateClaim` 测 span 切分必须等于 claim.text；不一致时唯一出现可定位，多处或不存在不涂。
- 机器评：`pickOriginSource` 测「这个靠谱吗？」加后续完整说法时选最新完整消息；命题分落两条消息时不选、不拼接。
- 机器评：`originInk` 测复合句仍保留完整原句、出处跟在命题后、间隔为 plain、并列事实不生成推断；立场型不涂。
- 机器评：`ReportCard` 渲染测多轮用后续用户消息作原句、找不到单一来源时退回命题列表、无 glue、无「系统还要核」。
- 机器评：`npm test -w @rhg/web` 与 `npm run build -w @rhg/web`。
- 人评：窄屏换行后色块仍贴着字；墨色读不出真假。
- 页面：fixture `/cases/fx-followup` 原句仍是首条完整说法，不是「顺着这条出处再查」。
