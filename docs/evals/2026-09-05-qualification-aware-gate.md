# 2026-09-05 · 门禁识别资格停止与运行故障

一句话：门禁先确认本次运行有效，再分别评价「该不该进入核查」和「进入后判得怎么样」，不能把正确停止或基础设施故障混进判决分数。

## Change

- 每个评估案例先有独立的资格期望：`proceed` 或 `stop`。
- `stop` 案例在检索前给出可继续补充的回应即算资格正确，不要求生成真假判决。
- `proceed` 案例没有进入最终判断时，资格覆盖和结果指标都记失败，不能以 `null` 从分母消失。
- 结果指标只比较同一组 `proceed` 案例，基线与当前运行的分母必须一致。
- 运行报告单列模型失败、内容审查、超时、搜索源失败和实际贡献来源；基础设施不满足最低条件时标记本次运行无效，不归因成产品判断错误。

## Not this

- 继续拿旧的全量判决分母评价新增的资格停止行为。
- 因为只剩一条搜索通道仍能返回结果，就把其他已配置但失效的通道记成正常。
- 把模型内容审查、供应商超时或额度耗尽算成资格逻辑错误。
- 为了让汇总数字变好而删掉失败案例、改成 `null`，或放宽既有判决区间。

## Evaluator

- 单元测试：`proceed` 缺少 `judge` 时，资格覆盖和对应结果项必须失败；`stop` 在检索前结束时不得要求 `judge`。
- 单元测试：基线与当前运行的案例集合或资格分组不一致时，门禁拒绝比较。
- 单元测试：模型任务失败、整体超时、没有健康搜索源时，运行有效性失败，并保留原始失败类别。
- 集成检查：一次真实运行输出资格混淆矩阵、固定分母的结果指标、模型候选实际尝试、各搜索源成功/失败/结果数。
- 人评：`proceed` / `stop` 标签属于价值函数，由人确认；执行者不接触具体案例、权重和逐例结果。

## Goal / Hard bar / Improve

- Goal：门禁失败能回答到底是资格决定、下游判断还是基础设施出了问题。
- Hard bar：运行有效；资格案例全部符合期望；应进入核查的案例全部产生最终判断；同分母结果指标不低于容差线。
- Improve：在不暴露隐藏案例的前提下，让每次迭代只收到能力级反馈。
