# 2026-09-05 · 搜索健康反向约束调度

一句话：已经观测到的重复查询和已知停用来源不得继续消耗一次案件的搜索预算。

## Change

- 同一命题的一轮初始检索中，文本完全相同的查询只执行一次；不同 purpose 生成同文时保留排序更靠前的一条。
- 运行环境可以用明确的停用列表排除已经欠费、鉴权失效或暂不使用的搜索源；有密钥不再等于本轮必须调用。
- 未知停用项不影响其他来源；AnySearch、MiniMax Token Plan、Step Plan 不因停用旧收费源而被误删。

## Not this

- 删除用户保存的密钥。
- 根据某个案例或某句查询写特判。
- 把失败来源伪装成成功，或从历史失败推断当前一定失败。
- 在没有持久健康状态的情况下发明自动熔断。

## Evaluator

- core 单元测试：exact 与 entity 产生相同 query 时只返回一条；其余高优先级不同 query 仍保留。
- core 单元测试：停用列表中的已配置来源不进入 `defaultSearchProviders`，未知 ID 不影响已启用来源。
- 真实回归：RUMOR-005 的 JSONL 中，同一 claim/query/provider 组合只出现一次 started；本机已停用的旧收费源不再出现，三条当前可用来源均有终态。
- 回归：core 全量测试、eval 全量测试、根测试与构建通过。

## Goal / Hard bar / Improve

- Goal：失败数据实际改变下一次调度，而不只是多一张统计表。
- Hard bar：不重复搜、不调用明确停用源、不误伤可用源。
- Improve：以后有跨运行健康存储时，再按连续失败次数和冷却窗口实现自动熔断。
