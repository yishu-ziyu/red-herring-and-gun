# 结果页：问题定义和体验

## 人要干什么

拿来一句话，问它站不站得住。读完要带走两件事：判断，以及可以点开核对的材料。不要带走一份分类档案。

## 现在错在哪

完成态把调查内核的字段摊成表：每行「反驳 / 支持 / 相关」+ 片段 + 标题 + 域名。那是数据库导出。眼睛被关系标签和分割线拽着走，读不成论证。

顶尖同类产品不是这样排的。

- Snopes / PolitiFact / AFP：先判断，中间是文章，来源在文末 Sources。
- 腾讯较真：流传说法 → 查证要点（论点）→ 结论 → 参考文献。
- Perplexity：回答是正文，`[1]` 打开来源面板。关系不进阅读列。

共同点：论证是文章。来源是脚注。分类（真/假、支持/反驳）不是每一行的骨架。

## 体验（完成态）

1. 判断：一句回答，必要的解释和限制。
2. 依据：按论点读。每段先是整理过的那句话（finding），下面是收据（片段）和出处（一行、小字）。
3. 点收据或出处，打开原来的来源抽屉。抽屉里才写这条材料对命题是反驳、支持还是相关。
4. 分歧、缺口各用一句接在相应论点后面。

调查中仍按「找到了哪页」来读。那是过程，不是结果。

## Change / Not this / Evaluator

Change：完成态阅读列不再出现「反驳 / 支持 / 相关」标签和彩色圆点。依据按论点分段，片段是收据，出处一行。

Not this：不编 finding。不把关系从抽屉里删掉。不拆证据 DOM 身份。

Evaluator：完成态截图阅读列无「反驳」「支持」「相关」；finding 在片段前；点片段仍打开抽屉。`goldenPath.test.tsx` 既有摘录诚实、identity、抽屉关系仍绿。
