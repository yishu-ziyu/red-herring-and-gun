# 结论页立体结构与追问区呈现 · 验收契约

- 日期：2026-09-12
- 用户原话：最后这个结论页展示的依然很糟糕。从全栈思维来看，我们最终要展示给用户的结论是什么呢？以及，我们追问的位置又在哪呢？你从这个结论页看，根本看不到追问的位置在哪。

## Change

1. **立体结论大卡（Conclusion Verdict Card）**：
   - 告别单调纯文本白板。结论区整合为结构化的裁决大卡：
     - 穿透性直答判定词（Direct Answer Headline，衬线大字）
     - 定性判断徽标（Verdict Badge），具备语义化色彩（红/绿/琥珀），明确判定结论（如「不支持」「属实」「存疑」）
     - 结构化核心事实与证据基底（Rationale / Trust Meta：核验争点数、出处数、核对时间戳）
     - 边界与安全警示卡片（Boundaries / Advisory Callout），醒目标注适用边界与反常识注意点
2. **追问探索系统（Follow-Up Section）**：
   - 在结论卡正下方、证据深入展开之前，提供明确的追问系统：
     - 推荐追问建议胶囊（Suggested Follow-up Chips）：基于调查边界与高频延伸点提供一键追问（如蔬菜类别差异、二次加热风险、安全限值）
     - 追问输入框（Follow-up Input Box）：支持自由键入、回车提交、发送按钮与聚焦动效
     - 操作整合区（Canvas Actions）：精致的「重新调查」「复制结论」「分享」动作按钮，告别孤零零的下划线
3. **全栈事件联动**：
   - 点击追问胶囊或输入提交时，触发追问回调（`onFollowUp`），可在前台与后台无缝衔接新一轮深入调查

## Not this

- 不是把所有内容塞在同一个大长段落里
- 不是只在底部放一个不起眼的搜索框
- 不破坏既有测试中对 DOM 顺序（answer 先于 judgment）与衬线字体的要求
- 不使用 `transition: all`
