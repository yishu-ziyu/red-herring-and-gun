# Golden Path 六步流畅度逐步验证

契约依据：用户要求 2026-09-12「主路径六步顺序完全流畅，一步一步确认，不打马虎眼」。本契约是纯验证任务：**不改任何代码**，发现问题列清单另行裁决。

## 六步的「流畅」标准（用户视角，可观察）

1. **贴东西**：粘贴一句话和粘贴一个链接都能提交；提交后 1 秒内有可见反馈（不是死屏）。
2. **看拆题**：调查进行中能看到思考披露和拆题结果；原句里被拆出的短语有标定；能数清拆成了几个问题。
3. **看证据**：证据逐条进来，每条带角色标识（拆问题 / 找出处 / 核语境 / 作判断）；支持、反驳、只是相关、还缺四类语义可分辨；来源胶囊可悬停预览。
4. **看冲突**：存在证据冲突时，争点支持侧与反驳侧各自成组摆出来；点击分歧条目能定位到争点。
5. **拿结论**：完成态第一句话直接回答原句；有判断标签、适用边界；来源能点开抽屉、再点开原文。
6. **追问或再查**：点推荐追问胶囊只是把问题填进输入框（不发）；按 Enter 或点「追问」才发新一轮；全页只有一处「重新调查」入口。

## Not this

- 不改代码；发现的问题登记清单， severity 排序，另开任务修。
- 不评估调查结论本身准不准（准确性是另一条线）。
- 不做性能压测、不测多人并发。
- 真实一轮烧的额度：1 次调查 + 1 次追问（用户已默许本轮取证成本）。

## Evaluator

1. **离线回放走查（零成本）**：`?fixture=first-beat` 自动播放全流 + `?fixture=complete` 完成态，1280px 与 375px 双端逐步截图，每步一张、标注步骤名，存 `docs/reports/2026-09-12-golden-path-walkthrough/step-N-*.png`。【命令 + 人评】
2. **真实走查（烧 1 调查 + 1 追问额度）**：真实浏览器贴隔夜菜微博链接跑完整一轮逐步截图；完成后点推荐追问胶囊、按 Enter 发一轮真实追问；确认追问页面上一步的六步标准仍成立（追问轮同样走完整六步）。【命令 + 人评】
3. **逐步断言**：Playwright 对六步各至少一条自动断言（提交反馈出现、拆题结果出现、活动流条目增长、争点两组渲染、结论第一句存在且非空、追问入口唯一且胶囊只填不发）。【命令】
4. **摩擦清单**：走查中任何「空白超过 2 秒、报错、点了没反应、文字挤出屏幕」逐条记录，附截图与复现步骤。【命令】
5. 走查期间 `cd apps && npm test` 保持全绿（证明没动代码）。【命令】

## 分工（swarm）

- 分身一：离线回放逐步截图（Evaluator 1）。
- 分身二：六步的代码接线核对——每一步的触发到渲染链路是否闭环、有无死路（只读，用 codegraph 辅助）。
- 分身三：真实走查（Evaluator 2、3、4）。
