# 主路 P0 修复：链接抓取可见 / 拆题兜底 / 超时竞态

契约依据：Golden Path 六步真实走查（`docs/reports/2026-09-12-golden-path-walkthrough/`）暴露的三个阻断问题；用户 2026-09-12 裁决：不计额度成本，每批以真实走查收口。

## Change

### A. 链接抓取失败对用户可见（文件：apps/src/lib/linkScraper.ts、apps/src/lib/caseIntake.ts、apps/src/goldenPath/InputStage.tsx）

- linkScraper 判定抓取失败：返回内容为空、少于 200 字、或命中通用登录墙特征（关键词集：「Sina Visitor System」「登录后查看」「登录可见」「passport」类跳转；实现时维护成列表）。失败链接标记 `scrapeFailed`，不再把 `【链接抓取内容】--- 链接 1 … --- 结束` 空信封拼进 claim。
- InputStage 提交前后：存在抓取失败链接时给用户可见提示「链接打不开（可能需要登录），已按你输入的文字继续」；用户只贴链接而抓取失败时允许继续，但提示必须出现。
- 不做微博专门 hack，不用绕过登录墙的手段。

### B. 拆题自证全丢时兜底（文件：apps/server/src/lib/casePipeline/runCasePipeline.ts）

- self-proof（约 :365-370）kept=0 且拆题候选非空 → 自动重试一次 self-proof；仍为空 → fail-open 保留全部候选（记日志），管道继续。报告与 UI 无需新增特殊标记，命题透明照常呈现。
- 首轮与追问轮同规则。

### C. 超时与晚完成竞态（文件：apps/server/src/handlers.ts、apps/src/goldenPath/useInvestigationRun.ts、apps/src/App.tsx）

- 管道总时限 210s → 300s，并复核内部预算闸（composer 预留、补查下限）在新时限下不自相矛盾。
- 超时不再一锤定音：客户端超时分支显示「还在查，可以离开页面，稍后回来或刷新能看到结果」；服务端此时**不写死 interrupted**——管线晚完成后把 run 落为 complete，结论经既有「刷新恢复」通道可取回。
- 管线超时后最终也失败 → run 落 interrupted，用户看到现有中断文案与重查入口。

## Not this

- 不处理「微博登录墙如何绕过」；不做抓取验证码/登录态。
- 不改拆题 prompt 与自证的判定标准，只加「全丢后的兜底」。
- 不碰 P1 项（争点过程渲染、结论明细、追问顶部指令、历史 404）——另批。
- 不动证据库/记忆功能——另批。

## Evaluator

1. A：单测覆盖三类抓取返回（空 / 短文本 / 登录墙 HTML）→ 判定失败、提示文案出现、claim 不含空信封；`cd apps && npx vitest run src/lib src/goldenPath` 相关文件全绿。【命令】
2. B：单测模拟 self-proof 两次均返回空 → claims 非空、管道继续、日志有记录；相关 server 测试全绿。【命令】
3. C：单测覆盖两条时序（超时后晚完成 → run complete 且可恢复取回；超时后最终失败 → interrupted）；相关测试全绿。【命令】
4. 批次收口（主会话派真实走查分身执行，真实额度）：贴同款微博链接跑完整一轮——抓取失败提示可见、拆题结果出现（claims>0）、结论送达用户手中；随后一轮真实追问走通。六步逐步截图存 `docs/reports/2026-09-12-mainpath-p0/real-*.png`。【命令 + 人评】
5. 本批机器门禁：`cd apps && npm test` 全绿、双 `npm run build` 零错误（主会话统一跑）。【命令】
