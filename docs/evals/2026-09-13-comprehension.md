# 2026-09-13 · 「看不看得懂」验收（赛题 #54）

产品说明书里挂着的交付项：没有技术背景的真实用户，看不看得懂判断理由和证据来源。

本文件是独立验收契约。走查材料在 `docs/reports/2026-09-13-comprehension/`。

## Change

一个没有技术背景的人，贴上一句流传说法，看完结果页后，能自己指出三件事：

1. **结论第一句在直接回答那句说法**（会不会、是不是、哪一层成立），不是盖「能信 / 不能信 / 只能信一部分 / 还查不清」四个内部词。
2. **判断依据在哪里**：能指到解释、问题点或命题上的理由，说得出「它凭什么这样判」。
3. **出处能打开**：能点到至少一条来源，看到标题或域名，并能打开原文链接。

可见路径仍是产品既定顺序：对原句的直接回答 → 问题点 → 出处。

## Not this

- 不把「测试绿了」当成用户看得懂。
- 不把内部类型词（能信 / 不能信 / 只能信一部分 / 还查不清）写成给用户看的第一句。
- 不要求用户读懂模型名、工具名、检索通道、token、Agent 角色。
- 不假装已经找过真人。找真实用户本人做访谈，本实施者做不到，停在材料齐备。
- 不为此改追问快路径，不改评测黄金集。
