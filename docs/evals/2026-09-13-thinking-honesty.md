# 思考区诚实 + 阶段过渡

Date: 2026-09-13
来源：用户选中调查中思考披露区，等了 31.2s 仍停在「01 结构解析」往原文上贴字，并问这三步是不是装的。随后补两张现网截图：拆问题到找出处像瞬移；来源胶囊和活动行一帧铺开；「开始查找」跟的是整段原文切片。

坐实（改前）：
- 思考三步文案是前端固定模板，按挂载后 0.5s / 1.2s 解锁，不是模型流、也不是拆题/自证输出（`ThinkingDisclosure.tsx`）。
- 01 把 `originalClaim` 整段塞进「分析「…」的主谓推论」。
- 快照在拆题+自证跑完前一直是 `received`、claims=0；Golden Path 不消费 `agent_thought`。31s 时画面假三步早已走完，后端最可能卡在拆题或自证（自证阶段预算 45s / 单次 25s）。
- 角色条 `decomposed` 只留拆问题，一进 `investigating` 后三人 70ms 错开入场，肉眼像切场景。

不在本契约：拆题把长文切成多条「命题」、结论第一句、命题卡空态「检索预算未覆盖」——由其他任务做。

## Change

1. **思考区只展示真实发生的工作。** `received` 且还没有命题：一句话说明正在把原句拆成可以单独核对的问题，并核对这些说法是否站得住。不出现 01 结构解析 / 02 证伪边界 / 03 确立议程。命题一旦出现：标题与正文对应已拆出的条数和问题（短句），不再用假三步假装进度。不要第四步假思考，不要把等待拉成打字表演。
2. **不要把用户整段原文回声进思考区。** 思考区正文不得出现与 `originalClaim` 相同的整段。
3. **阶段切换要有过渡，不要切场景。** 复用已有 `gp-role-emerge` / `gp-find-in` / 活动脉冲 / `prefers-reduced-motion`。拆问题结算后找出处开始；找出处完成后核语境开始干活（`judging` 时核语境为进行中）。新命题、新来源胶囊、新活动行顺序淡入或短位移；存量不重闪。不为动效延长真实等待。不新动画库，不用 `transition: all`。

## Not this

- 不编更花的假打字、假三步、假四步来填 31 秒。
- 不把 `agent_thought` 接进 Golden Path 当产品真相。
- 不改拆题模型提示、不改报告第一句、不改命题卡空态文案。
- 不拉长自证/拆题的真实预算。
- 不把四人空位先画好再填。

## Evaluator

1. 思考区：`received` 等 2 秒仍不得出现「结构解析」「证伪边界」「确立议程」；长原文不得整段出现在 `.gp-thinking-body`。命题出现后思考区含真实命题短句与条数，仍不得出现上述假三步标题。【命令】
2. 入场：调查中（`live`）新命题 / 新来源胶囊带 `is-enter`；同一批 id 再渲染不重新加上；`prefers-reduced-motion` 块关掉这些位移。`judging` 时核语境为 doing、找出处为 done。【命令】
3. `cd apps && npx vitest run src/goldenPath` 全绿。【命令】
4. 浏览器：拆题完成到第一条检索活动之间能感到角色/命题过渡；来源胶囊不是一帧全出现。`?fixture=first-beat` 或本地调查中画面。【命令（浏览器）+ 人评】

人评：措辞是否像在报真工作；过渡是否跟得上、是否吵。
