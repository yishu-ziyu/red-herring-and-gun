# 思考区等待句跟真实阶段对齐

Date: 2026-09-13
来源：高压走查记下「拆题超过一分钟思考区仍停在同一句」；用户批准：命题出来之前始终只有一句真话，但这句话跟后台真实阶段对齐，并带已经等了多久。

坐实（改前）：
- 思考区在 `received` 且无命题时只有拆题这一句；拆题跑完、自证开始时服务端不发新快照，前端收不到「进入自证」。
- 秒数是组件挂载后的真实经过时间，但文案不跟阶段走。
- 禁止用 0.5s / 1.2s 假装解锁（契约 `docs/evals/2026-09-13-thinking-honesty.md` 已拆假三步）。

## Change

思考区在命题拆出来之前，始终只有一句真话，这句话跟后台真实阶段对齐，并带已经等了多久：

- 刚贴上：正在把这句话拆成可以单独核对的问题（已等 12 秒）
- 拆完、开始自证：正在核对刚拆出的说法站不站得住（已等 48 秒）
- 自证过了、命题出来：换成已有的「已拆出 N 个待查问题」，进入找出处

没有真阶段变化时，不另起一句新话，只更新秒数。秒数用真实经过时间；阶段切换必须来自服务端真实事件/快照。若客户端收不到「进入自证」，最小补一条公开活动或快照字段，不要新协议栈。

## Not this

- 不恢复假三步，不假打字。
- 不延长自证预算、不为动效拉长等待。
- 不改访客追问快路径。
- 不 commit。
- 前端不得用 0.5s / 1.2s 假装解锁到自证句。

## Evaluator

1. `received` 且无 `preClaimWork`（或值为 `splitting`）：思考区标题是拆题句，带「已等 N 秒」；推进 2 秒后仍是拆题句，秒数变大；不得出现「结构解析 / 证伪边界 / 确立议程」。【命令】
2. 同一份 `received` 快照只推进时间：不得出现「正在核对刚拆出的说法」；只有服务端快照带上 `preClaimWork=checking` 之后才换成核对句，秒数继续累加、不另起第三句。【命令】
3. 命题出现（`decomposed` 且 claims>0）：标题为「已拆出 N 个待查问题」，不再写「已等」。【命令】
4. 管线：`rumor_detector` 返回后、自证模型返回前，发出 `phase=received` 且 `preClaimWork=checking`、claims 仍为空的快照；拆题失败 fail-open 不发 checking。【命令】
5. `cd apps && npx vitest run src/goldenPath` 相关面绿。【命令】

人评：等拆题/自证时，那一句是否像在报正在发生的事；秒数是否像真的在走。
