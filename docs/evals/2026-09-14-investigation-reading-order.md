# 调查中阅读顺序：空等第一拍 + 命题只出现一次

Date: 2026-09-14
来源：用户走查盐说法。第一张：拆问题空等 29 秒，思考卡只有光标和「已等 N 秒」。第二张：同一份四个命题出现在思考卡、活动流、命题列表三处，空命题写「还没有可展示的材料。」用户问这块怎么设计、给用户看什么、按什么顺序。

坐实（改前）：
- 产品宪法阅读顺序是原句 → 命题 → 证据 → 缺口/冲突 → 判断。拆分过程不上脸。
- `take.html` 第一拍思考卡默认展开、有正文；命题出来后思考默认折叠。活动流是「已确立 N 条子命题」一句，不是把每条命题再抄一遍。
- 生产把假 01/02/03 抽空后，等待只剩标题秒数和空光标。命题出来后思考卡仍展开并列四条，活动流再写四次「拆出问题：」，下面主列又是这四条。

## Change

1. **空等不是干等。** 命题还没出来时，思考卡是主工作面：标题是真实阶段句（拆题 / 核对），秒数只在旁边小字，不进标题。正文是可读的阶段说明，下面三条灰槽表示即将出现的待查问题。不出现 01 结构解析 / 02 证伪边界 / 03 确立议程，不把用户原句整段回声进思考区。角色条跟同一阶段：拆题时「拆分问题中」，核对时「核对拆出的说法」。没有命题时不另写「已收到这个说法，准备开始。」跟思考卡抢状态。

2. **调查中命题只出现一次，主列是命题卡。** 阅读顺序上→下：原句 → 谁在干活 → 一句阶段 → 已折叠的思考（「已拆出 N 个待查问题 · 耗时」，点开不列完整命题）→ 命题列表（这句话被拆成了什么，每条下面接材料）→ 刚刚发生（只增量：开始查找、带回材料、判定、分歧）。`claim_decomposed` 不再在活动流复述已上屏的命题。调查中空材料写成「正在查找这一条的出处。」或「还没轮到查找这一条。」，不写成死空。

## Not this

- 不恢复假三步、假打字、模型私有推理。
- 不把等待拉成表演，不为动效延长拆题/自证。
- 不改拆题模型、自证预算、结论第一句。
- 不把活动流删掉；只去掉与命题列重复的拆题行。
- 不 commit。

## Evaluator

1. `received` 且无命题：思考卡默认展开；标题是拆题句，不含「已等」；旁有秒数且推进时间只改秒数；正文有阶段说明和灰槽；无「结构解析 / 证伪边界 / 确立议程」；原文不整段出现在思考正文；画布无「已收到这个说法，准备开始。」【命令】
2. 同一快照加上 `preClaimWork=checking`：标题换成核对句；角色条是「核对拆出的说法」不是「拆分问题中」；仍无假三步。【命令】
3. 命题出现（调查中）：思考卡默认折叠，标题含「已拆出 N 个待查问题」；每条命题全文在 `.gp-claims` 出现一次，不在思考展开正文、不在活动流以「拆出问题：」复述；空材料文案是查找中/排队，不是「还没有可展示的材料。」【命令】
4. `cd apps && npx vitest run src/goldenPath` 相关面绿。【命令】
5. 浏览器：空等能读到阶段说明；命题出来后一眼先看到原句和命题列表，不是三份相同的四条。【命令（浏览器）+ 人评】

人评：空等像在做事还是在数秒；调查中能不能一眼找到「这句话被拆成了什么」。
