# 盐说法走查 P1/P2

Date: 2026-09-14
承接：`docs/evals/2026-09-14-salt-walkthrough.md`。P0 中断文案已落地。本文件收 P1 与 P2。

## Change

1. **谣言跳跃必须进命题。** 原句「所以 / 因此 / 于是 / 这说明」之后的结论单独成条。背景数字事实不得把它们挤掉。盐说法里「高血压全是吃盐造成的」「全家换成低钠盐就能预防中风」「肾功能不好的老人也完全适用」必须出现在 `claimAtoms`。
2. **同一出处同一摘录不得同时当支持和反驳。** 同一 `sourceId` 在一条命题下只保留一个角色。
3. **中断且已有分条判断：说清差收束。** 中断条在已有 `judgment` 时写明「分条判断还在，整句总判断没写成」。不编造总结论。
4. **拆题一出来就上屏。** `rumor_detector` 返回并收窄后立刻发 `decomposed` 快照（claims>0），不等自证跑完。
5. **相关材料默认收起。** 调查中 / 中断态，`context-only` 不铺在主列；点「相关材料」再展开。支持和反驳仍直接可见。

## Not this

- 不恢复假三步，不延长自证预算。
- 不把中断伪装成已完成结论。
- 不把课文长文的 4 条上限改成无限。
- 不 commit。

## Evaluator

1. `ensureLeapAtoms`：盐说法在只有 4 条背景原子时，输出含上述三截跳跃。【命令】
2. `buildInvestigationSnapshot`：同一 URL 同时进 supporting 与 contradicting 且 finding 相同时，该命题 evidence 里该 sourceId 只出现一次。【命令】
3. 管线：`rumor_detector` 返回后、自证模型返回前，发出 `phase=decomposed` 且 claims>0 的快照。【命令】
4. 中断且 claims 带 judgment：中断条含「分条判断」或「总判断」；无 judgment 时不出现这句。【命令】
5. 调查中 `context-only` 默认不在证据主列展开；有支持和反驳时它们仍可见。【命令】
6. `cd apps && npx vitest run` 相关面绿。【命令】
7. 浏览器走查：空等能看到拆出的问题（fixture 或本地调查）；相关材料默认收起。【命令（浏览器）+ 人评】
