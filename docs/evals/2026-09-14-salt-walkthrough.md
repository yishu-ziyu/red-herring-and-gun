# 盐说法走查：问题定义

Date: 2026-09-14
来源：用户用混真假低钠盐说法走查。截图三张：空等、调查中信息墙、中断完成态。后台 run `14a567df-4203-4ee7-b0c1-4d889de113e1`。本文件只定义问题和优先级，不代替实现契约。

## 这一轮实际发生了什么

提交 22:50:17。约 60 秒后才拆出 4 条命题并开始检索。77 秒材料入库。130 秒四条都有判断，进入 `judging`。319 秒时进程重启，`markInterruptedOnBoot` 把未完成 run 标成 interrupted。快照停在 `phase=judging`，没有 `conclusion`。用户刷新后看到「这次调查没有完成」。

拆出的 4 条全是原句前半截真背景。原句后半截谣言跳跃没有进命题：高血压全是吃盐造成的；全家换成低钠盐就能预防中风；肾功能不好的老人也完全适用。

## 用户提出的三件事

1. **空等。** 拆问题阶段只剩角色转圈、一句状态、思考卡空光标和「已等 N 秒」。不是原设计。原设计思考卡有正文；后来拆掉假三步，变成干等。
2. **调查中信息怎么排。** 同一份命题出现在思考卡、活动流、命题列表。阅读顺序没当成一屏信息架构定过。
3. **「这次调查没有完成」。** 用户问「什么叫资质调查没有完成」。页面原文是「这次调查没有完成」。意思是：还没对整句话下结论。本轮原因是服务在写总判断时被重启，不是用户点了停止，也不是材料为零。

1 和 2 的界面改动已在契约 `docs/evals/2026-09-14-investigation-reading-order.md` 落地。60 秒内仍没有真命题，那是管线还没把拆题结果提前发出，不是这一屏排版。

## 复盘另外看到的问题

4. **原句里真正像谣言的三截没被查。** 产品只核了对的前提，没核错误结论。用户拿来试产品的那部分，调查对象里没有。
5. **同一条出处、同一段话，同时标支持和反驳。** claim-3：`anyang.gov.cn`「高血压的病因」finding 相同，一边 support 一边 contradict。画面上「反驳 · 高血压的病因」和「支持 · 高血压的病因」摘录一样。
6. **相关材料墙。** 20 条来源里大量 `context-only`、同文转载（「快让爸妈换盐」三份）、同一政府站 http/https 各一份。主列被铺满，争点被埋住。
7. **中断条和原句栏都有「返回首页」。**
8. **四条命题已经有判断（支持 / 支持 / 有对有错 / 支持），总判断没写。** 中断把「还差收束」说成整次没完成。

## 优先级

P0 用户第三问：中断要说人话（中途停了、没有总判断、材料还在）；同一屏不要两个「返回首页」。
P1 查该查的：谣言跳跃必须进命题；同一出处同一摘录不得同时当支持和反驳。
P2 空等不只灰槽：拆题一出来就上屏，不等自证 60 秒；相关材料默认收、转载去重。

## Change（本文件只收 P0）

中断条标题和正文让人读得懂：调查中途停了，还没有对整句话下结论；已查到的问题和材料留着。原句栏在中断态不再重复「返回首页」。不把中断说成「资质」。不在本文件改拆题模型。

## Not this

- 不把中断伪装成已完成结论。
- 不在本文件改自证预算、不恢复假三步。
- 不 commit。

2. 中断画布「返回首页」只有一处（中断条动作），原句栏不再重复。【命令】
