# 方案二：同一份调查，先回答主要疑问，再按需要深入

## Change

用户在本轮确认方案二为默认产品逻辑。直接实施，不委派、不另做平行产品。新增的语义优先级只影响检索顺序；证据、引用、真假判断和取消门槛不放松。

1. 输入后自动开始；本轮范围来自已保留命题及实际检索计划，明确区分计划核查、未覆盖与不适用真假判断。不能以字符串剩余片段推断全文已查或未查。
   唯一材料是打不开的链接时，请用户补正文/截图，不发起没有可读对象的调查；有附带文字时继续查文字并保留链接失败说明。
2. 首轮结果继续直接回答问题。查看已有证据只展开/定位现有材料，不发新调查。补查需用户明确发送，在同一份调查内保留前轮快照、原日期和问题。
3. 追问、失败、停止、刷新与历史重开不清掉已完成的前轮；历史把同一调查的后续轮次归组，不把旧判断改成新日期。跨账号不继承私有调查。
4. 首页、范围说明、继续补查入口采用当前纸张/细边框/清晰字阶；390px 无横向溢出，键盘可切换轮次与查看来源。

## Not this

不加「思考强度」滑条。方案一至三同时改变范围、交付形式和等待成本，当前没有经验证的一维深度政策；不增加一个只改变时限或降低证据要求的控件。以后做深度控制必须先验证各档真实范围与代价。此轮不切 T20、不改模型套餐、不部署、不覆盖已有工作区修改。

## Evaluator

- 单测：优先核查列表只接受已保留的命题；未纳入的命题不得被写成已核查；旧快照兼容；线程快照可序列化、保留日期、不递归嵌套报告、不接受损坏历史。
- App 集成：首轮完成 → 查看来源无 POST → 发送补查仅一个新 POST → 过程可查看前轮 → 新结果与前轮并存；重开/刷新只读；停止补查不丢前轮；原件/旧轮次不被后续保存覆盖。
- 构建与回归：根工作区及 apps 测试/构建、API 构建、相关镜像测试、git diff --check。在线 eval 另记执行范围，不用离线打桩声称真实判断质量提高。
- 浏览器：固定构建、非 watch API、独立测试数据；输入→范围→答复→已有依据→补查→前轮切换→历史恢复；桌面/390px、控制台、请求数量和截图分别留证。固定材料回放只证明交互，不冒充真实联网调查。
- 人评：普通人能否复述主要结论及覆盖边界；专业用户能否检查原文与推断。未进行就标未验收。

## 实施结果

- 产品规范已写入方案二；默认界面不是三个模式入口，不提供假深度滑条。
- `priorityClaimAtoms` 是可选排序工单，不改变可核查资格、来源绑定和真假门槛。未填写时保持原有排序。`scope` 是向后兼容的快照字段，两侧 schema/build 字节镜像一致。
- 调查线程保存已结束轮次的快照，不递归嵌套整个报告；幂等保存不覆盖已记录轮次。当前仍使用原有本机/账号存储容量与 API 报告大小限制，超限会明确同步失败，不宣称无限轮次或永久保存。
- 本机保存、账号摘要、恢复指针保持线程信息；迟到的旧保存结果不覆盖新轮的保存状态；指针按账号范围恢复。
- 私有历史不随本轮分享出去：排除 investigationThread，清除公开 claim/originalClaim/claimReviewed 中的追问上下文信封。共享页与复制简报都保留本轮范围。
