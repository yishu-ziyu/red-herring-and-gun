# 取消、输出预算与迁移验收

## Change

用户 2026-09-17 授权直接实施 `docs/tasks/2026-09-17-runtime-reliability-plan.md`。先完善生产请求的取消、截止时间、输出校验，再以行为兼容为门禁收敛 packages 架构。当前界面和历史/账号/分享/额度行为不能因迁移退化。

## Not this

- 不改模型、套餐和并发备用策略，不部署、不推送、不启动子 Agent。
- 不用丢弃 Promise 的结果代替取消底层请求，不把取消转成供应商回退或 JSON 修复。
- 不编来源/判断，不改既有 eval 期望为本次获取绿灯。
- 不覆盖用户及其他本地工作流已有变更。变更前读取最新文件。

## Evaluator

1. 可控本地 HTTP 响应挂起时，显式取消须关闭连接；取消后不得新增模型、检索或修复调用。覆盖响应头前/流读取中/重试间隔与预先取消，验证计时器/监听器清理。
2. 首次响应消耗预算后输出坏 JSON，修复只剩剩余时间；到期中断修复，并且不得继续回退。JSON 语法合法但 schema 不合格不作为成功返回。
3. 取消/完成竞争、重复取消、断线恢复、BYO fail-closed 保持已有契约；显式取消后迟到输出不得写成完成或进入记忆。
4. 根目录、apps 与 apps/server 的相关测试和构建；相关 eval gate 先核对基线与调用成本。所有执行结果如实记录，未运行不得写通过。
5. 固定代码，使用非 watch 服务和隔离数据副本完成页面输入→调查→证据→结果/停止→历史恢复。API 成功和离线 DOM 测试均不代替此项。
6. T20 切换前须通过功能差异表、数据副本迁移及回滚验证；原生产界面不能被另一套试验界面替代。未满足则不改生产发布入口，并明确剩余障碍。
