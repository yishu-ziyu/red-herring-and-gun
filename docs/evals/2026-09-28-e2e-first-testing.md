## 录音回放层会怎样失败（先列，再写）

1. **请求里有易变内容**（时间、截止时刻、随机编号）→ 回放时对不上录音。处理：按「方法 + 地址 + 请求体」做指纹，指纹前去掉已知易变字段；对不上时不偷偷连外网，而是返回一个失败回复（等同供应商报错），并在产物里计数、列出。
2. **同一请求录到多次不同回复**（重试、并发）→ 按录制顺序依次回放，用完后重复最后一条。
3. **回放漏连真实网络** → 回放模式下除本机地址外一律拦截；每次拦截计入产物。
4. **密钥泄进录音** → 不保存请求头；地址里名为 key / api_key / token / access_token 的参数改写成 `REDACTED` 再算指纹。
5. **流式回复**（SSE）→ 录完整正文，回放时一次性返回同样的正文和 content-type。
6. **读取正文破坏原请求**（正文只能读一次）→ 录音时读克隆的回复，原回复原样交还调用方。
7. **回放太快走了不同分支**（录制时因超时跳过写报告，回放时有时间就去写）→ 这些请求没有录音，按第 1 条返回失败回复，结果仍然确定，只是会走兜底；产物里如实列出回放未命中的请求数。
8. **录音目录不存在或为空** → 回放启动即报错退出，不静默降级成真实网络。
