# 2026-09-28 实机跑出的四个缺陷

来源：用户截图 + 本机 `大剂量维生素C有利于预防感冒。` 完整一轮（约 395s）。

## Change

1. 调查中右栏不再有空白：逐条核查区紧跟四个头像，不再等左侧「调查动态」排完。
2. 头像进度与动态一致：进入判断阶段且已有命题形成判断（动态出现「形成判断」）时，「作判断」是当前角色，「核语境」打勾。
3. （2026-09-29 更新：这条修法用的短谣辟谣通道已删除，见 `2026-09-28-judgment-refactor.md`「第二轮」。现在辟谣只能经逐条判词与关系审核算反驳；结论、子命题、徽章说同一件事由整句规则表保证。下面是当时的记录。）短句辟谣通道判「不能信」时，结论、子命题、徽章、出处角色说同一件事：
   - 单条可核查命题：该命题判为站不住，存活的对题辟谣材料标「反驳」，结论不再写「尚未查清，未计入该判断」，徽章不是「证据不足」。
   - 多条可核查命题：不走无绑定的整句「不能信」，按收权门收为「证据不足」（`unverified`）。
4. 来源探活超时不再算「打不开」：只有 404/408/410/5xx 或连接失败才判死；单条请求超时视为未知，不剔除。
5. 复验中发现：「这条说法查过」提示的样式在 Reset 4A（9-06）被整段删除，提示裸贴在页面左上角。恢复为与全局提示同列对齐的卡片。
6. 复验中发现：收权后重建结论时，有源判词 evidence 被硬截 120 字，半句话直接接上下一句（「结论同样显「大剂量…」尚未查清」）。改为截在 120 字内最后一个句末（连同引号与 [n]），一句都没完时补「…」。

## Not this

- 不把关键词辟谣的出处伪装成 SourceValidator 审过的关系：不写 relationReason 审计理由，理由写在命题 evidence 里，明说是「检索到针对这句话的辟谣」。
- 不改供应商配置；最终写作服务不可用走兜底是环境问题，本轮不处理。
- 不改「补查后仍缺：当事方、地点」这类缺口措辞与推荐追问（另开）。

## Evaluator

- 机器：`cd apps && npm test`、`npm --prefix apps run build`；新增回归先红后绿：
  - WorkRoles：judging + 有 judgment 的命题 → `judgment` 为 doing；无 judgment → `context` 为 doing。
  - 服务端：tiny 通道单命题 → subclaim `false` 且 contradictingSources 非空、conclusion 不含「尚未查清」；多命题 → `unverified`。
  - 探活：fetch 超时 → `alive`；连接错误 → `dead`。
  - 样式契约：App 用到的每个 `gp-same-claim*` 类在 CSS 里都有规则。
  - 结论重建：长 evidence 截断后，「尚未查清」一句之前以句末标点结尾。
- 浏览器（Ego）：`/?fixture=judging` 下 `.gp-claims` 顶部与 `.gp-roles` 底部间距 < 80px；`judgment` 角色 `data-gp-role-state=doing`。
- 人评：真实跑一轮同句，看结果页结论是否不再自相矛盾（依赖供应商，是否复现兜底路径不可控）。
