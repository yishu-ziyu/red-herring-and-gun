# 先查已有档案，判断必须有原文

Issue：[#129](https://github.com/yishu-ziyu/red-herring-and-gun/issues/129)

## Change

现有调查先找辟谣档案；同一说法且有适用原文则提供给当前判断模型，不直接继承旧结论；不足时用现有搜索补查。确定判断必须对应取得的网页正文或可追溯的存档正文，模型引用须在正文中核对。结果仍用现有页面展示对应判断、原文、出处。网页当前打不开不否定已保存原文。

## Not this

不建新数据库、不建通用评测框架、不重跑40道全量联网基准、不改账号/配额/模型路由、不替换模型报告、不删除角色头像/动态/思考展示、不发布。八档措辞和重排版不在本次。历史结论或搜索摘要不能单独充当原文。不能按题库答案挑资料或硬编码两道示例。

## Evaluator

- 合成边界与真实档案测试：库内有匹配正文可进入判断；空库、仅摘要、不同人物/日期/范围不能直接继承结论且可补查。
- 管线测试：新模型仍做判断和报告；引句不在正文中则不能作为支持或反驳；正文不够显示「目前的材料不足以判断」并说明具体缺口。
- 已存正文的URL即使当前不可访问也不能被单纯探活剔除；只有旧结论的记录不能绕过原文要求。
- 充电宝、苏打水经真实应用提交，看到总答→问题点→出处；点击对应依据看到匹配的原文段落，不把其他小节摘要冒充该命题原文；记录模型/抓取受阻的实际状态，不用模拟结果称真实通过。
- 浏览器用 Ego 脚本定量验收，再真人式滚动点击走查；新功能/展示取舍不确定时与用户讨论。
- 根 npm test、npm run build；apps npm test、npm run build；行为变更 npm run eval:gate。相关检查先行，全量只收尾一次，失败只复测受影响项。
- 阅读最终diff，删除本次产生的重复与无用分支；检查原工作区文件指纹无本次写入。

### 本次修掉的关键问题

- 历史摘要不得挡住查档案/联网；同一句原话才免首搜，换人物、日期、范围仍要补查。
- 合集原文按命中的条目限定可引用范围，不能用同URL其他小节证明当前命题。
- 模型和搜索服务不能自报「已核」或原文正文；只有本地取得、逐字核对的引句可进入方向性证据。
- 删除核验后回写搜索摘要的动作，避免它反过来触发重复模型审计。
- 没有依据的判词同时清掉肯定解释，不能只改徽章；统一材料不足文案，清掉报告边界里的内部流程词。
- 保留模型报告、调查角色与动态；界面仍为现有生产布局。
