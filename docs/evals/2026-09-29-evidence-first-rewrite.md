# 2026-09-29 以「摊开依据」为目标重写判断与结果页

## 目标

用户打开结果，第一屏就能核对：原句被分成几截，每一截用八档用词说明站不站得住，下面是证明它的原文句子（抓到网页后逐字核对过）、来源类型与日期、独立来源几家，点一下跳到原网页的那一句。样例：`outputs/evidence-first-mock.html`；用词与条件：`docs/PRODUCT_SPEC.md`「每一截的用词」。

## 为什么要重写而不是修补

- 数据层没有「这一截 → 哪句原文 → 属实/不属实」：出处与命题是两张清单，引文是搜索摘要（会漏出 `<mark>`），关系审不清一律降为「相关材料」。
- 判断之后约 5k 行事后纠错（引用绑定、探活、事后修正、语境交叉、来源审核、第二意见、整句审核、报告审稿、兜底稿、公开文案清洗）。每修一个错加一层，不回到决定点。
- 结果页的力气花在过程表演（角色头像、调查动态、思考区），证明结论的一环为空。
- 基线（current-v1）：判对 24/37，走兜底 14/40，中位 244 秒。

## 新的七步（每步一个模块）

```text
① 读材料    文字 / 链接正文 / 截图文字（保留现有实现）
② 拆题      每截：原句片段、角色（主要主张/必要前提/背景细节）——今天已做
③ 找证据    辟谣档案 → 定向权威站点 → 多引擎广搜；转载归并为证据链；
            排名靠前的来源抓全文（新增），存页面正文
④ 逐截判断  每截一次模型调用，输入是抓到的页面正文段落；输出：八档用词、
            逐字引句、被反驳的成分、来源编号。代码回查引句确在页面正文中，
            查不到的引句丢弃；没有核实引句的截只能是「查不到」
⑤ 下结论    判定表单一函数（今天已做：domain/verdict.ts）
⑥ 写回答    保留模型写报告；判定表给出结论，模型根据核实后的材料组织文字。
            保留失败回退；不把模型写作或调查过程的删除列为任务。
⑦ 留存      案件库（现有）；共享档案写入另立任务
```

结果数据只有一份：`{ 原句, 截[{片段, 角色, 用词, 理由, 引句[{来源, 原句, 已核实, 关系, 被反驳成分}]}], 来源[{类型, 日期, 证据链}], 结论, 首句, 独立来源数 }`。调查中的进度帧、结果页、历史、分享都读它。

## 删什么

| 删 | 约行数 | 被什么取代 |
|---|---|---|
| 判断后的纠错层：citationBinding、factDeskPostProcess、contextCrossCheck、sourceRelationAudit、wholeClaimAudit、evaluateWholeClaim、crossExam/crossExamine | ~2.4k | ④ 的逐字引句回查 + ⑤ 判定表 |
| 报告相关纠错中被前置核查替代的重复逻辑 | 待核对 | 保留模型写作与失败回退；逐项证明等价后才删 |
| 可信度分数：credibilityScore、formulaScore | ~0.4k | 不上屏，八档用词取代 |
| 没用上的：记忆候选（memoryCandidate*）、语义召回 | ~1.1k | 无（每次都是 0 条） |
| 调查中的角色头像、动态、思考区 | 不删除 | 用户明确保留；完成后证据优先的布局在 P3 验收 |

每组删除都要通过下面的检查；数字以删完实测为准。暂不动：模型接入层、账号额度、追问、分享、以图搜图（能用，不在这次目标里）。

## Not this

- 不改拆题以外的输入环节，不改账号、额度、追问、分享。
- 不做共享档案自动写入、提速的多厂商分担、安全审计（各自另立任务）。
- 不为凑数改题库标准答案。

## 已知风险

- 抓全文会失败（登录墙、脚本渲染页）：失败的来源只能进「相关材料」，不能支撑判断，可能让「查不到」变多。P1 的数字会说明代价。
- 保留模型写作意味着超时与写作错误仍需解决；不能提前承诺兜底归零。
