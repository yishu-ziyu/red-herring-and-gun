# 2026-09-29 R10：带截图的调查在本机配置下必然失败

问题记录：`docs/rewrite-issues.md` R10。用户 2026-09-29 认可的方向：图片解析请求打到对的地址；图片解析仍失败时不让整次调查失败，按用户输入的文字继续并留一条常驻提示。

## 先列会怎么坏

1. 地址拼错：`STEPFUN_BASE_URL` 指向 step_plan（Token Plan 端点，图片和文字都走同一套 key）时，图片请求拼成 `.../step_plan/chat/completions`，返回 404。健康探针拼同一个地址，同样 404，把 StepFun 误报成不可用。
2. 修了地址仍会坏：网络断开、超时、4xx/5xx、模型返回的不是 JSON、返回空文本。现在这些全部被 `throw`，整次调查按服务端错误收尾，用户看到的是通用的「这次核查没能完成」。
3. 修成「失败就跳过」后的新坏法：
   - 用户看不出图被跳过了，以为图里的内容已经被核查过。（必须有常驻提示。）
   - 用户只发了图、没有任何文字，跳过后拿占位句「请核查用户上传的 N 张图片材料。」去查，会得到一个假装查过的结论。（必须明说图没读出来，并且不开始核查。）
   - 只发图且读不出来，却计入当天免费次数。（必须退还。）
   - 用户点了停止、或断开连接：不能被当成「图片读不出来」而继续往下跑。
   - 提示帧被公开流清洗吞掉，或被模型 ID、服务商名污染。
4. 图片解析失败的原始报错（含服务商名、状态码）不得出现在用户可见的流里（现有 `tool_error` 清洗保持）。

## Change

1. 图片解析与 StepFun 健康探针使用同一个「StepFun 聊天补全地址」函数：基础地址含 `/step_plan` 时用 `<基础地址>/v1/chat/completions`，否则 `<基础地址>/chat/completions`。2026-09-29 用本机 key 实测：三种候选（step_plan Anthropic 协议带图片块、`api.stepfun.com/v1`、`step_plan/v1/chat/completions`）都返回 200 并读出了中文截图上的字；选最后一种，因为它与本机文字调用同属 Token Plan 额度、请求格式与现有代码一致。
2. 图片解析失败（除用户取消/断开外的任何原因）时：
   - 有文字（`intake.text` 非空，或有抓到正文的链接）：调查照常进行，不带视觉材料；流里发一条 `notice` 帧（`code: "image_unreadable"`，文案「图片没能读出来，已按你输入的文字继续」）；前端在页面顶部 `gp-global-notice` 位置常驻显示，样式与「链接打不开…已按你输入的文字继续」相同。额度按 `completed` 正常结算。
   - 没有任何文字：不开始核查，发 `error` 帧，`code: "image_unreadable"`，文案「图片没能读出来，这次没法核查。请换一张更清晰的图，或把图里的文字打出来再试。」该文案不被通用文案覆盖。结局按服务端错误处理，额度退还（`QUOTA_SETTLEMENT["server-error"] = release`）。
3. 用户取消与断连仍走原有 `cancelled` / `client-gone` 结局，不被图片失败盖掉。

## Not this

- 不换视觉模型、不改提示词、不改解析结果的结构、不动 `composeClaimWithVision`。
- 不做多图部分成功的处理（有一张读不出来就整批视为读不出来，与现在一致）。
- 不改额度结算表，不改其他结局的行为。
- 不动线上配置；不猜线上 `STEPFUN_BASE_URL`。
- 不动 `apps/server/eval/*`、`debunkArchive/*`、`outputs/*`。

## Evaluator

机器项（`cd apps && npm test`）：

- E1 `stepFunChatCompletionsUrl`：`https://api.stepfun.com/step_plan` → `https://api.stepfun.com/step_plan/v1/chat/completions`；`.../step_plan/v1` 同上；`https://api.stepfun.com/v1` → `.../v1/chat/completions`；尾部斜杠不影响。
- E2 图片解析请求实际发往 E1 的地址（stub fetch 记录 URL）。
- E3 健康探针发往 E1 的地址。
- E4 整条流（真处理器，管线打桩）：图片解析返回 404，有文字 → 流里有 `notice`（`image_unreadable`）、管线仍被调用且收到的 claim 是用户文字、以 `complete` 结束、无 `error` 帧、额度已提交。
- E5 同上，模型返回非 JSON 文本 → 行为同 E4。
- E6 只有图、没有文字，解析失败 → 管线未被调用、`error` 帧带 `code: "image_unreadable"` 且文案为上述专用文案（经公开流清洗后仍在）、额度已退还。
- E7 图片解析成功 → 无 `notice` 帧，行为与改前一致。
- E8 前端：`notice` 帧进入运行状态，页面出现该文案（`role="alert"`，`gp-global-notice`），调查完成后仍在。
- E9 `toPublicStreamEvent`：`code: "image_unreadable"` 的 `error` 保留原文案；无 code 的 `error` 仍被改成通用文案。

golden：`npx tsx golden/golden.ts replay r10 && npx tsx golden/golden.ts compare base r10`，只有 `g07-image`（及健康探针）应变化，逐条解释。
