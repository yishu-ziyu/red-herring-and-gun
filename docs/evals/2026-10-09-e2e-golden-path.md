# 2026-10-09 真实端到端测试：主路径

## Change

增加一个真实端到端测试。它用真实浏览器打开本机运行的产品，用真实模型和真实搜索完成一次调查，然后检查用户能看到的结果。

这个测试是后续两步的安全网：删除全部单元测试和集成测试，以及简化代码。所以它必须先能通过，并且必须能发现故意造成的破坏。

## Not this

- 不模拟模型、搜索或后端。用 mock 的测试不算端到端测试。
- 不检查模型写出的具体文字。模型每次的措辞不同，所以测试只检查结构：有没有结论、有没有判断、来源能不能打开、历史能不能重开。
- 不覆盖追问。追问会再跑一次真实调查，耗时和费用翻倍。主路径稳定后再加。
- 不在 CI 上运行。CI 上没有真实密钥。

## Evaluator

前提：在 `apps/` 里运行 `npm run dev`，并且 `apps/.env.local` 里有真实密钥。

```bash
cd apps && npm run e2e
```

退出码 0 表示通过。每次运行在 `out/e2e/<时间>/` 留下 `result.json` 和每一步的截图。

每次运行都把过程录成 `run.webm`，放在同一个证据目录里。测试不弹出浏览器窗口，因为窗口会打断用户的注意力。用户看完视频后删除它，不让视频堆积。

为什么不在 cmux 内置浏览器里跑：cmux 0.65.0 的内置浏览器用的是系统 WebKit（Safari 的内核），测试用的是 Chromium（Chrome 的内核），两者不同。另外，用 `cmux browser` 命令看不到网络请求，所以第 3 项和第 8 项（只发出一次调查请求）没法检查。

测试检查这些用户看得到的结果：

1. 首页显示输入框。
2. 提交说法以后，调查进入完成状态，不是中断或停止。
3. 整个过程只发出一次调查请求。
4. 结论区有对原句的直接回答。
5. 命题有判断。
6. 展开「收集到的来源」，点第一个来源，会打开来源抽屉，抽屉里的「打开原文」链接指向 http(s) 网址。测试不走「关键依据」，因为证据不足时「关键依据」按设计不显示。
7. 刷新页面以后，「历史记录」里有这次调查。
8. 从历史重开，显示的结论和第一次相同，并且不发出新的调查请求。

已知限制：调查运行期间不要改后端文件。开发服务器在保存文件时会自动重启，正在进行的调查会被打断。

## 结果

2026-10-09，本机，说法「隔夜菜会致癌，等于吃毒药」：

- 正常运行：10 项全部通过，用时 413 秒。证据在 `out/e2e/run2-baseline/`。
- 破坏验证：删掉来源抽屉「打开原文」链接的 `href` 以后再运行，只有第 6 项失败（no link），其余 9 项通过，用时 321 秒。证据在 `out/e2e/run3-broken-source-link/`。破坏已恢复。

运行中发现的产品问题（测试没有检查这些问题）：

- 同一句话 3 次调查得到 2 种结论：2 次「公开材料不支持这条说法。」，1 次「公开材料还撑不住判断。」。「隔夜菜等于吃毒药」一次被标成立场表达，一次被标成尚未查清。
- 首页案例卡片向用户显示内部用词「生产 fixture」。
