## 书要解决什么
第一稿往往不准、不全，不能直接交给用户。
要先评估，再按评估补证据或改结论，不能一轮定生死。
书把这件事做成模型再看自己的输出，或另雇一个评审模型循环改到「完美」。

## 我们有没有
有但形状不同。
核查业务要的是「初稿出错还能拦住」，不是模型对着自己的判词反省。
对应路径：`mvp/server/src/lib/casePipeline/runCasePipeline.ts` 把下面四段串进生产管线。
`mvp/server/src/lib/evidenceLoop/evidenceLoop.ts` 的 `findLoopTargets` / `runEvidenceLoop`：核查后判词是未证实，或支撑与反证同时非空，代码才补搜；停因只有 `evidence-found` / `no-new-evidence` / `rewrite-empty` / `search-failed`。
同一文件里模型只改写检索词，失败回退 `fallbackRewriteQueries`；同站转载不计入有效增益。
`runCasePipeline.ts` Phase 2a：补到有效新证据才重跑 `fact_checker`；每原子最多 2 pass × 每 pass 2 轮；重判失败保留原判，补查来源仍进报告。
`mvp/server/src/lib/crossExam/crossExam.ts` 的 `findCrossExamTargets` / `runCrossExam`：仍冲突才叫第二模型看一次该条；`compareVerdicts` 后不改判词，只按分歧降可信度（每次 -10，封顶 -20）并写入 `finalReport.crossExam`。
`mvp/server/src/lib/reportAssembly/assembleFinalReport.ts` 的 `deriveOverallVerdict`：有据之真（bind 过的真实 URL）加上有假，代码把整句从「不能信」改成「只能信一部分」。
`mvp/server/src/lib/reportReviewer.ts` 的 `reviewAndRepairReport`：ReportComposer 写完后代码查契约；前序未支持却写成能信则降成「还查不清」；补链、压过满措辞；审稿者是代码，不是模型改稿。
依据：`docs/adr/ADR-004-evidence-sufficiency-loop.md`、`docs/adr/ADR-003-production-case-pipeline.md`、`docs/PRODUCT_SPEC.md` 第四节与第八节。
故意不做：书里的 LangChain 反思循环、ADK 生成器-评审者互相改稿、模型自己说 `CODE_IS_PERFECT` 才停、无界自我反思。
依据：`docs/PRODUCT_SPEC.md` 第六节「不是自治 Agent」；`docs/adr/ADR-002-deepagents-evaluation.md` 不迁 LangGraph / DeepAgents；ADR-004「不做 LLM 决定下一步」「不做无界递归搜索」。

## 对能信/不能信的意义
第一轮没搜到，不会立刻写成「不能信」；代码换问法再查，仍没有就说「还查不清」。
一句里真假搅在一起时，整句守门拦住模型把整句打成「不能信」，用户看见「只能信一部分」。
报告缺字段、或把未核的写成「能信」，审稿器降级或补边界，用户不会拿到空壳或过满结论。
