# 第 5 章 · 工具使用

## 裁决
done-in-our-form

## 分数
5 / 5

## 书要解决什么
模型训练数据是死的，不能上网、不能读图、不能对着公开出处核。
这一章要解决的是：核查必须用上训练数据之外的材料。
书把这件事做成模型自己决定调不调工具，再用 LangChain / CrewAI / ADK 去执行。

## 我们有没有
有但形状不同。
核查业务要的是「结论能对着可点开的外部材料核」，不是模型自己挑下一步调哪个工具。
对应路径：`mvp/server/src/lib/casePipeline/runCasePipeline.ts` Phase 1b 在拆题和自证之后、核查之前，代码先检索。
`mvp/server/src/lib/atomSearch.ts` 的 `retrieveForAtoms`：只对可核查原子搜，上限 `MAX_ATOM_SEARCHES`（6）；`mvp/server/src/lib/claimAtom/merge.ts` 的 `splitVerifiableAtoms` 把 `verifiable: false` 挡在门外。
`mvp/server/src/handlers.ts` 的 `makeSearchOneAtom` → `retrieveAtomSources`：每个原子 2–3 路查询，并行打 360 mweb / AnySearch / Metaso / Tavily / Exa；没 key 或失败不阻断整次。
`mvp/server/src/lib/atomSearchQuery.ts` 的 `buildAtomSearchQueries` / `mergeParallelSearchPayloads`：查询组合与多路 RRF，不是模型现场发明函数名。
`mvp/server/src/lib/atomSearch.ts` 的 `buildAtomSearchBundle` 过 `mvp/server/src/lib/retrievalFilter.ts` 漏斗：无 URL 丢掉、去重、按条 top-k。
`mvp/server/src/handlers.ts` 的 `makeRunAgent`：把 `search360` / `atomSearches` 注入 `fact_checker`、`source_validator`、`report_composer`；状态栏 `tools: []`，模型看不到工具列表。
`mvp/server/src/lib/evidenceLoop/evidenceLoop.ts` 复用同一 `searchOne` 补查；代码判触发与停因，模型只改写检索词。
`mvp/server/src/handlers.ts` 的 `callStepFunVisionForIntake`：有图才读图，只抽可见文字和来源线索，不判真假；`composeClaimWithVision` 再把结果拼进待查材料。
用户丢链接时，客户端 `mvp/src/lib/linkScraper.ts` 先抓正文，再随 intake 进管线。
`mvp/server/src/lib/atomSearch.ts` 的 `bindAtomEvidenceToVerdicts` 与 `mvp/server/src/lib/citationBinding.ts`：模型写出的 URL 必须在本轮检索里出现过，否则剥掉。
`mvp/server/src/lib/agentSkills.ts` 的 `skill.dual-search`：无检索来源不得判真假；引用必须来自输入材料。
依据：`docs/PRODUCT_SPEC.md` 第四节检索与第六节、第八节；`docs/adr/ADR-003-production-case-pipeline.md`；`docs/adr/ADR-004-evidence-sufficiency-loop.md`；`docs/adr/ADR-005-evidence-pursuit-search-policy.md`。
故意不做：书里的 function calling、LangChain `create_tool_calling_agent`、CrewAI 工具、ADK 预置搜索/代码解释器、模型自选何时搜。
依据：`docs/adr/ADR-002-deepagents-evaluation.md` 评估 React Agent（LLM 自选工具）与流水线不兼容；`docs/PRODUCT_SPEC.md` 第六节「不是自治 Agent」、第八节「LLM 自选工具经 ADR-002 评估后主动不做」；`docs/adr/ADR-001-agent-architecture-upgrade.md` Phase 2 未启动；ADR-003 明确本迭代不把工具改成 function-calling。
`mvp/server/src/handlers.ts` 的 `callOpenAI` 在 Canvas 节点 `mode === "search"` 时带 `web_search`，那不是生产 Case Pipeline，不计入本章完成度。
书里的发邮件、控灯、沙盒跑代码与核查无关。

## 对能信/不能信的意义
用户看见的能信 / 不能信，必须对着检索到的可点开链接，不是模型背课文。
搜全挂了不会编一段流畅解释；空结果走「还查不清」，没搜到不等于假。
截图先抽出可见文字，再按句检索；图里的提取不是结论。

## 缺口
无。
模型不自选工具是有意的：编排层先搜再注入，同一说法可以复测。
类型闸标错会变成「立场型 / 不适用真/假判断」而不去搜；那是已知不满，不是本章欠一层 function calling。
本章不建议打开 ADR-001 Phase 2。
