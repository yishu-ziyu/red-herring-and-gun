# 第 10 章 · 模型上下文协议 (MCP)

## 裁决
done-in-our-form

## 分数
4 / 5

## 书要解决什么
模型不能只生成文字，必须能跟外面的系统说话：取实时材料、调工具、拿回结果。
书要把这件事收成一套公开约定，让任何兼容客户端都能发现并调用服务器上的工具、数据和提示，而不用每个模型各写一套私有调用。
书还把这套约定当成智能体自己选下一步的底座。

## 我们有没有
有但形状不同。
MCP 在本产品里是两面，不能合成一句。

一面：我们当服务器，给 360 / MiXer 调。
`mvp/server/src/lib/mixerMcp.ts` 实现 JSON-RPC `initialize` / `ping` / `tools/list` / `tools/call`，只公开一把工具 `red_herring_truth_check`，入参只有 `claim`。
`mvp/server/src/index.ts` 把 `app.all("/mcp", …)` 接到 `mcpHttpHandler`。
`tools/call` 经本机 `POST /api/agent/orchestrate` 进入 `mvp/server/src/handlers.ts` 的 `orchestrateHandler`，再跑 `runCasePipeline`。
`mvp/server/src/lib/mixerMcp.test.ts` 覆盖握手、列工具、带 `claim` 回结构化结果、缺参报错。
`mvp/tasks/todo.md` 写明目标 URL 是 `https://gun.yishuziyu.cn/mcp`、无鉴权、平台待注册；部署勾选停在 2026-06-15 的 ECS 无响应，以代码为准，公网是否已挂上未在本审查里复验。

另一面：我们当客户端，去调搜索。
`mvp/server/src/handlers.ts` 的 `callAnySearchSearch` 向 `https://api.anysearch.com/mcp` 发 JSON-RPC `tools/call`，工具名写死为 `search`，不先 `initialize`，不按清单发现。
它只是 `callParallelSearchProviders` 五家里的 `any_search`；另四家（360 / Metaso / Tavily / Exa）走各自 HTTP，不是 MCP。
`makeSearchOneAtom` → `retrieveAtomSources` 把并行检索注进 `runCasePipeline` 的 `searchOne`。
AnySearch 挂了，别家成功仍有来源；五家全失败才报检索失败，不把空来源写成假。

内部核查管线不依赖 MCP。
`mvp/server/src/lib/casePipeline/runCasePipeline.ts` 不引用 MCP；搜不搜、搜几轮，由拆题字段、`evidenceLoop`、`evidencePursuit` 的代码决定。
赛题「360 生态 / 可被调用」和「管线是否靠 MCP 编排」不是同一件事。
360 智搜是普通检索源，不是 MCP；MiXer 的 `/mcp` 是把整次核查暴露出去，不是管线骨架。

故意不做：书里的 ADK `MCPToolset`、FastMCP、动态发现后由模型自选工具、用 MCP 编排多步工作流。
依据：`docs/PRODUCT_SPEC.md` 第六节「不是自治 Agent」、第八节工具对照「LLM 自选工具经 ADR-002 评估后主动不做」；`docs/adr/ADR-002-deepagents-evaluation.md` 不迁 React Agent；`docs/adr/ADR-003-production-case-pipeline.md` 生产真相是 Case Pipeline。

## 对能信/不能信的意义
能信 / 不能信 / 只能信一部分 / 还查不清，来自 Case Pipeline 的分截判决和来源绑定，不是来自 MCP 协议。
对外当服务器，只让 360 侧用户能把同一条核查叫起来；叫起来之后仍走同一条管线。
对内 AnySearch 只多一家可点开的来源；这家不是唯一依据，没搜到仍应说还查不清，不能写成不能信。

## 缺口
MiXer 入口的工具只收 `claim` 字符串。
截图和链接走 `orchestrate` 的 `intake`，MCP 回环不传 `intake`，360 侧若只丢图或只丢链，图里的说法和页面正文可能进不了本案。
回包摘要带上 `agentCount` 和 `models`。
若宿主把模型名单当第一眼，用户会先看见过程，而不是能信 / 不能信。
`/mcp` 无鉴权，回环打 `127.0.0.1` 的 `/api/agent/orchestrate` 也不带用户身份。
额度按回环地址记时，360 侧用户可能互相挤掉次数，或被滥用打满，看见的是调用失败而不是判决。
以上伤的是 360 通道，不是「内部管线要改成 MCP 编排」。
书里的物联网、生成媒体、智能体自己发现新工具，与核查无关。
