# 第 11 章 · 目标设定与监控

## 裁决
done-in-our-form

## 分数
5 / 5

## 书要解决什么
智能体要先说清楚「做成什么样算成功」，再盯进度判断有没有做成。
没做成就改做法或停下来，不能反应完就算完，也不能永远跑。
书的示例用模型自己打 True/False 当成功，并用最大迭代次数当笼子。

## 我们有没有
有但形状不同。
成功标准不是 Agent 自己立考核指标。
成功标准是：这条可核查判断有没有足够能点开的证据，来下能信、不能信、只能信一部分、或还查不清。
`mvp/server/src/lib/evidencePursuit/evidencePursuit.ts` 的 `assessEvidenceGap` 按槽位看还缺原始来源、反证、时间、当事方、独立来源等，并写出本跳目标（如「找原始发布」）。
同一文件的 `computeInformationGain` 把新的非转载来源、缺口收窄、新站点计入增益；同站或近标题转载增益视为约 0；`GAIN_STOP_THRESHOLD` 以上才算够了可停。
`mvp/server/src/lib/evidenceLoop/evidenceLoop.ts` 的 `findLoopTargets` 只挑 unverified、或支撑与反证同时有的原子。
`runEvidenceLoop` 的停止原因只有四类：`evidence-found`、`no-new-evidence`、`rewrite-empty`、`search-failed`。
预算写在代码里：原子最多 3、每 pass 最多 2 轮、每轮最多 2 条查询。
`mvp/server/src/lib/casePipeline/runCasePipeline.ts` 的 Phase 2a：有效新证据才重跑一次事实核查；重判后仍有缺口且上一 pass 还在产证据，才再续 1 个 pass，总轮不超过 4。
循环只补证据，不写能信或不能信。
查询改写只换检索词，提示写明「不判断真假」；下一步问什么、何时停，由缺口与增益函数决定，不由模型宣布成功。
`mvp/server/src/lib/reportAssembly/assembleFinalReport.ts` 的 `faceVerdictFor` 把整句收成「能信 / 不能信 / 只能信一部分 / 还查不清」；对不上的类型一律「还查不清」。
立场型判断不进真假清单，界面是「立场型 / 不适用真/假判断」，不为它设证据目标。
`mvp/server/src/handlers.ts` 把四类停止原因写成中文 `reasonText` 随 SSE 发出（搜到 → 缺口收窄转入重判；没新证据 / 问法用完 / 搜索挂了 → 判停）。
`mvp/src/lib/evidencePursuitUi.ts` 把 hops 收成目标、搜了什么、结果性质、还缺什么。
`mvp/src/components/v3/phases/mission/MissionPursuitFold.tsx` 在过程层折叠展示 hops。
`mvp/src/components/v3/phases/ResultView.tsx` 的足迹同样列出 hops。
`hopsFromTools` 会跳过带 `reason` 的判停事件：主界面 hop 列表展示每一跳的目标与缺口，不是四类枚举原文；判停中文在 SSE 工具结果里，见 `mvp/src/lib/missionShell/streamAdapter.ts` 的 `formatPursuitDetail`。
书里让模型自己宣布目标达成、自己选下一步：故意不做。

## 对能信/不能信的意义
没搜到足够能点开的证据，就停在「还查不清」，不会把空检索写成假。
转载不算新证据，避免同一通稿铺满来源后过早写成能信或不能信。
用户第一眼是判断；过程可回看这一跳要找什么、找到了什么、为什么不再搜。
