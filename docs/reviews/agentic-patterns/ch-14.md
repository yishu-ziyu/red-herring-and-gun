# 第 14 章 · 知识检索（RAG）

## 裁决
done-in-our-form

## 分数
4 / 5

## 书要解决什么
模型不能靠训练记忆写结论。
生成之前必须先去外部材料里查找，再把查到的内容写进回答，并标出能核对的出处。
书里的默认形状是把内部文档切块、做成向量库再检索；也写了用搜索上网，以及让模型自己决定再查一轮。

## 我们有没有
有但形状不同。
核查要的是「每条能核对的说法对着公开网页核，来源能点开」，不是把内部 PDF 切块。
对应路径：`mvp/server/src/lib/casePipeline/runCasePipeline.ts` Phase 1b 在原句自证之后调用 `retrieveForAtoms`。
`mvp/server/src/lib/atomSearch.ts` 的 `selectAtomsToSearch` 最多检索 6 条可核查原子，每条一轮；`buildAtomSearchBundle` 按 `claimAtomKey` 把来源绑回该条。
`mvp/server/src/handlers.ts` 的 `makeSearchOneAtom` → `retrieveAtomSources`：每条原子用 `mvp/server/src/lib/atomSearchQuery.ts` 的 `buildAtomSearchQueries` 出 2–3 路问法，并行打 360 / AnySearch / Metaso / Tavily / Exa（有 key 才出活）；`mergeParallelSearchPayloads` 用 RRF 合成可点开 URL。
`mvp/server/src/lib/retrievalFilter.ts` 的 `hardFilterSources`：没有 `http(s)` URL 的丢掉，短链、空标题且空摘要也丢掉。
`mvp/server/src/lib/atomSearch.ts` 的 `bindAtomEvidenceToVerdicts` 加上 `mvp/server/src/lib/citationBinding.ts` 的 `filterSourcesWithRemap`：模型写出的 URL 必须出现在该原子本轮检索里，否则剥掉并改写 `[n]`；检索垫进去的来源标 `sourcesRelatedOnly`，句内编号全部剥掉。
`mvp/server/src/lib/reportAssembly/assembleFinalReport.ts` 组装后调用 `normalizeReportCitations`；`runCasePipeline.ts` 审稿后再绑一次，避免补链把编号写飞。
用户点击：`mvp/src/components/v3/InlineCitations.tsx` 把 `[n]` 做成可点开链接；`mvp/src/components/v3/phases/ResultView.tsx` 结论脚的 `citationSources` 同样是 `href`。
模型侧纪律：`mvp/server/src/lib/agentConfigs.ts` 的 FactChecker 写明「模型记忆不是核查」「给不出 URL 不得判肯定值」；`mvp/server/src/lib/agentSkills.ts` 的 `skill.dual-search` 写明「无检索来源不得判真/假」。
整句守门：`assembleFinalReport.ts` 的 `deriveOverallVerdict` 只把 bind 过的真实 URL 算作有据之真；检索垫的 related-only 不算；真假交织时，无据之真不能把整句从「不能信」救回来。
书里的 Agentic RAG（评来源、处理冲突、拆开多步、缺口再搜）我们用代码做。
`mvp/server/src/lib/evidencePursuit/evidencePursuit.ts` 出 Query Portfolio、证据缺口、RRF、信息增益。
`mvp/server/src/lib/evidenceLoop/evidenceLoop.ts` 只在 unverified / 冲突时再搜，笼子封顶；LLM 只改写检索词，不决定下一跳。
依据：`docs/adr/ADR-003-production-case-pipeline.md`、`docs/adr/ADR-004-evidence-sufficiency-loop.md`、`docs/adr/ADR-005-evidence-pursuit-search-policy.md`、`docs/PRODUCT_SPEC.md` 第四节。
本地案件库不是本案检索库：`mvp/src/lib/knowledgeBase.ts` 和 `mvp/src/lib/semanticRecall.ts` 用同义词组和汉字重叠找旧案；`mvp/src/components/v3/phases/MissionControlView.tsx` 的 `buildLocalMemoryRecall` 写明旧案只作检索线索，不直接进入本案结论。
故意不做：Vertex RAG Corpus、Weaviate 切块、PDF 向量库、GraphRAG、LangGraph retrieve-generate、让模型自己选工具再搜。
依据：`docs/PRODUCT_SPEC.md` 第六节「不是自治 Agent」「不迁移 LangGraph / DeepAgents」；`docs/adr/ADR-002-deepagents-evaluation.md`。

## 对能信/不能信的意义
用户看见「能信 / 不能信」时，句内编号应对着能点开的网页，点开的是本轮检索里真实出现过的地址，不是模型编的链接。
某一截没搜到，报告写待补证或「还查不清」，不能因为没搜到就写成「不能信」。
立场型判断不发起检索，报告写「立场型 / 不适用真/假判断」。

## 缺口
单条判词：绑定只剥虚构 URL，不把「已经没有 URL 的 true/false」改成 unverified。
用户可能看见「能信」，条下只有「相关检索（未写入句内引用）」或「定向检索无结果」。
整句全是 true 时，`deriveOverallVerdict` 明确「有据无据均可」仍出 true。
这不是缺检索，是收束没有用代码执行「无 URL 不得保留真/假」。
本章不建议上向量库或 GraphRAG。
