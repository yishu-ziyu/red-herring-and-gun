# 第 17 章 · 推理技术

## 裁决
done-in-our-form

## 分数
5 / 5

## 书要解决什么
复杂说法不能一轮直接写成能信或不能信。
要把问题拆开、中间对照材料、必要时多花计算再判一次，结论才站得住。
书把这件事做成思维链、思维树、ReAct、Deep Research，并主张把思考过程展示给用户。

## 我们有没有
有但形状不同。
本域的「推理」是拆原子再逐条对照来源，不是模型独白，也不是把思维链当产品。
对应路径：`mvp/server/src/lib/casePipeline/runCasePipeline.ts` 生产编排是拆题 → 自证 → 按条检索 → 核查/信源 → 证据循环 → 收束。
`mvp/server/src/lib/agentConfigs.ts` 的 `rumor_detector` 只拆原句里真实存在的判断，写出 `claimAtoms` / `claimAtomTypes` / `verifiable`，不许写能信或不能信。
`mvp/server/src/lib/claimAtom/selfProof.ts` 的 `runClaimAtomSelfProof` 丢掉原句没说过的原子。
`mvp/server/src/lib/atomSearch.ts` 的 `retrieveForAtoms` 只给可核查原子检索；被标成立场的判断不进真假清单，报告写「立场型 / 不适用真/假判断」。
`mvp/server/src/lib/agentConfigs.ts` 的 `fact_checker` 强制 `subclaimVerdicts` 覆盖每条原子，对着检索 URL 写 true / false / partial / unverified / exaggerated；给不出 URL 不得写肯定判词。
多花计算落在工单上，不落在表演上。
`mvp/server/src/handlers.ts` 的 `makeRunAgent` 主步骤 `reasoningEffort: "high"`；自证与证据循环改写是机械闸门，用 `"low"`；冲突二审再用 `"high"`。
`mvp/server/eval/runCase.ts` 同一套高低分配。
`mvp/server/src/lib/minimaxM3.ts` 默认 `thinking: adaptive`，思考计入 `max_tokens`，输出预算用官方推荐 128K，避免思考写满、正文为空。
`mvp/server/src/lib/providerRouter.ts` 的 `stepFunReasoningEffortForModel`：`step-3.7-flash` 拒收 `reasoning_effort`，思考预算压到 `low`，超时单独放宽。
自我纠正与补查已是代码循环，不靠模型再念一遍思维链：证据充分性见 `mvp/server/src/lib/evidenceLoop/evidenceLoop.ts` 与 `docs/adr/ADR-004-evidence-sufficiency-loop.md`；检索分路见 `mvp/server/src/lib/evidencePursuit/` 与 `docs/adr/ADR-005-evidence-pursuit-search-policy.md`；分数由 `mvp/server/src/lib/credibilityScore.ts` 的公式算，不让模型拍分。
思考句可以回看，不是第一眼。
`mvp/server/src/handlers.ts` 只把模型真实 `reasoning` 拆句后以 `agent_thought` 送出，用 `mvp/src/lib/reasoningThoughts.ts` 的 `splitReasoningSentences` / `thoughtInterSentenceDelayMs` 控节奏；没有思考文本就不发，前端不编句。
`mvp/src/components/v3/phases/mission/ThinkingReasoning.tsx` 思考中可看，查完自动折上；`mvp/src/lib/missionShell/speechInstrument.ts` 把思考放在仪器卡，不放进对用户说的话。
依据：`docs/PRODUCT_SPEC.md` 第二节「过程默认收着」、第四节工单表、第八节「decompose-then-verify」；`mvp/DESIGN.md` 第一屏是出处与能信吗；`mvp/DESIGN-GALLERY.md` 场景 1「不是在看模型思考秀」。

依据：`docs/PRODUCT_SPEC.md` 第六节「不是自治 Agent」「不是编排框架演示」；`docs/adr/ADR-002-deepagents-evaluation.md` 不迁 LangGraph / DeepAgents；`docs/adr/ADR-003-production-case-pipeline.md` 生产真相是 Case Pipeline；ADR-005「LLM 不决定下一跳」。

## 对能信/不能信的意义
用户第一眼是能信、不能信、哪一截能信，或还查不清，不是思考链。
一句话拆开后，属实的那截与有问题的那截分开判；立场句不拿去证真证伪。
模型多想一会儿只为把工单填对；没有可点开的来源，思考再长也不能写成能信。

## 缺口
无。
拆题类型闸没有第二意见，标错会变成「立场型 / 不适用真/假判断」而不去查；那是已知不满，不是欠一层思维链。
本章不建议把 CoT 做成卖点，也不建议补思维树、ReAct 自治或 Deep Research。
