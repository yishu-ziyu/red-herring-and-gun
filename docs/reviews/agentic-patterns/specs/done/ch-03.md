## retrieveForAtoms 是否只对可核查原子调用 searchOne
是。
用例：`只对可核查原子调用 searchOne，并打出 bundle`。
`claimAtoms` 含「事实1 / 立场 / 事实2」，`atomsToSearch` 只有「事实1」「事实2」，`searchOne` 被调 2 次。
管线用例：`顺序：rumor → self-proof 过滤 → 只搜可核查 → assemble 排除立场`，`searchOne` 只收到「事实A」。
生产：`splitVerifiableAtoms` 把 `verifiable: false` 剔出后再 `selectAtomsToSearch`。
JSON 入口 `searchMode: "parallel"`，SSE 入口 `searchMode: "sequential"`，都不把立场条送进检索。

## sequential 模式 hooks 是否按原子成对出现
是。
用例：`sequential 模式按序调用 hooks`。
顺序是 `start:A → search:A → done:A → start:B → search:B → done:B`。
`runCasePipeline` 把 `hooks.searchMode` 接到 `retrieveForAtoms` 的 `mode`。
SSE `orchestrateStreamHandler` 设 `searchMode: "sequential"`，`onAtomSearchStart` / `onAtomSearchResult` 成对发事件。
原子层排队只改进度形状，每个原子内部仍是多 query × 五源并行。

## 多 query 合并是否按 URL 去重
是。
用例：`合并多路检索时按 URL 去重，并对多 query 列表做 RRF 再按题权重排`。
两路都带 `https://www.piyao.org.cn/a`，合并后该 URL 只留一条。
`mergeParallelSearchPayloads` 用 `seenUrl` 去重，多路再走 RRF。
生产 `retrieveAtomSources` 对 2–3 条 query 走 `Promise.allSettled`，再交给该合并函数。

## 立场条是否进「立场型 / 不适用真/假判断」
是。
`assembleFinalReport` 把立场条放进 `nonVerifiableAtoms`，不进 `subclaimVerdicts`。
`ReportModal.test.tsx`：该条标签是「立场型」，说明是「不适用真/假判断」。
管线用例：`价值B` 进 `nonVerifiableAtoms`，不出现在 `subclaimVerdicts`。

## 并行形状（对照规范独立审查意见）
五源并行成立。
`callParallelSearchProviders` 对 360、AnySearch、Metaso、Tavily、Exa 走 `Promise.allSettled`，一路失败记缺口，有一路成功就合并。
同原子 2–3 条 query 再并行成立。
Phase 2 的 FactChecker 与 SourceValidator 走 `Promise.allSettled`。
拆出因果原子时，`alternative_explanation_searcher` 与 `counter_evidence_grader` 同样 `Promise.allSettled`，失败不阻断收束。
证据循环串行成立。
`evidenceLoop.ts` 对 target 与 query 用 `for` + `await`，后一跳等前一跳缺口。
原子并行支确是 `Promise.all` 不是 `allSettled`。
生产被 `get360SearchForClaim` 包住：`retrieveAtomSources` 抛错时返回 `build360SearchFailure`，不会整句因一路检索异常而少查。
没有发现并行形状导致该查没查。
