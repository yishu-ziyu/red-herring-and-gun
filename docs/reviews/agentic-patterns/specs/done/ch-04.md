## findLoopTargets 无判词是否触发 unverified
是。
用例：`无判词 → unverified 触发`。
`verdicts: []` 时目标是 `{ trigger: "unverified" }`。
`findLoopTargets` 在 `evidenceLoop.ts`：按 `atomsSearched` 找判词，没有对应条就推 unverified。
判词状态是 unverified 类同样触发。
支撑与反证同时非空才走 conflict。

## 正向判词不带来源是否不触发
不触发。
用例：`判词状态为 unverified 类 → unverified 触发；正向判词不带来源也不触发`。
`verdict: "true"` 且 `supportingSources` / `contradictingSources` 皆空 → 目标列表为空。
代码注释写明：fact 阶段 URL 绑定在报告组装时才发生，来源为空不是未证实信号。
有单侧来源的已有结论也不触发。
正向空来源仍写成能信或不能信，归第 14、18 章。

## 新证据是否 evidence-found 且重跑 fact_checker
是。
循环单测：`第一轮拿到新证据 → evidence-found，重跑 fact_checker`。
`stopReason` 为 `evidence-found`，`recheckFactChecker` 为 true。
管线用例：`evidence loop：unverified 原子补查命中新证据后重跑一次 fact_checker（ADR-004）`。
`factRuns` 恰好为 2，最终 `factCheckResult` 是重判结果。
生产：`runCasePipeline` Phase 2a 仅在 `passOutcome.recheckFactChecker` 为真时再调 `fact_checker`。
重判失败保留原判，补查来源仍在 bundle。

## 两轮零新增是否 no-new-evidence 且不重跑
是。
循环单测：`两轮策略全零新增 → no-new-evidence，不重跑`。
同 URL 不计新增，`recheckFactChecker` 为 false，补查封顶 4 次（2 轮 × 2 条）。
管线用例：`evidence loop：两轮零新增 → 判停且不重跑 fact_checker`。
`factRuns` 为 1。
生产：整 pass 无增益就 `break`，不续期。

## 有据之真 + 假是否 faceVerdict「只能信一部分」
是。
`deriveOverallVerdict` 用例：`有据之真 + 假 → partial（mixed 救回，RUMOR-011 形态）`。
管线用例：`原子级守门：有据之真 + 假 → mixed 救回`。
`verdictType` 为 `mixed_misleading`，`conclusion` 以「只能信一部分」起头，`faceVerdict` 为「只能信一部分」。
`FACE_VERDICT.mixed_misleading` 就是这六个字。
真但无据 + 假不救，保持 false。
检索已有对题辟谣时，`boundTinyRumorVerdict` 仍可把「只能信一部分」收成「不能信」，那是短谣守门，不挡本章笼子。

## overclaim true + fact unverified 是否 verdictType unverified
是。
审稿单测：`downgrades overclaim true when fact check is unverified`。
`previousOutputs` 含 `factCheckResult: "unverified"`，报告写 `true` → `repaired.verdictType` 为 `unverified`，issue code 为 `overclaim`。
管线用例：`report review hooks emit start/result and repair thin reports`。
同样降成 unverified，分数不超过 45。
生产：`reviewAndRepairReport` 之后 `faceVerdict` 按新 `verdictType` 重算，脸上是「还查不清」。
审稿者只改类型与分数，不改 conclusion 原文。

## crossExam 分歧是否降分不改主判词
是。
`compareVerdicts`：相反为 `disagree`；第二意见 unverified 为 `inconclusive`。
`crossExamConfidenceAdjustment`：每次分歧 -10，封顶 -20。
`runCrossExam` 写出 `primaryVerdict` 与 `secondVerdict`，不回写主判词。
生产：Phase 2b 只把 `confidenceAdjustment` 加进 `credibilityScore`，并写入 `finalReport.crossExam`。
管线这 13 个用例没有单独跑交叉复核；此条靠单测加读 `runCasePipeline.ts`。
