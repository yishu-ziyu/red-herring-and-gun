## retrieveForAtoms 立场条是否进 searchOne
不进。
用例：`只对可核查原子调用 searchOne，并打出 bundle`。
`claimAtoms` 含「事实1 / 立场 / 事实2」，`atomsToSearch` 只有「事实1」「事实2」，`searchOne` 被调 2 次。
管线用例：`顺序：rumor → self-proof 过滤 → 只搜可核查 → assemble 排除立场`。
`searchOne` 只收到「事实A」。
`价值B`（`verifiable: false`，`type: value`）进 `nonVerifiableAtoms`，不进 `subclaimVerdicts`。
生产：`splitVerifiableAtoms` 把 `verifiable: false` 剔出后再 `selectAtomsToSearch`。
`runCasePipeline` Phase 1b 把拆题结果交给 `retrieveForAtoms`，再把 bundle 注入后续 Agent。
检索是代码先搜，不是模型现场点工具。

## makeRunAgent 是否仍是 tools: []
是。
`mvp/server/src/handlers.ts` 的 `makeRunAgent` 调 `buildAgentStatusBar` 时写死 `tools: []`（约 754 行）。
空列表在状态栏打成 `tools=[none]`。
`orchestrateHandler` 与 `orchestrateStreamHandler` 都用这个 `makeRunAgent`。
`fact_checker` / `source_validator` / `report_composer` 只拿到注入的 `search360` / `atomSearches` JSON。
`mvp/server/src/lib/agentConfigs.ts` 无 `tools` 字段。

## 生产核查路径是否传工具定义
不传。
`providerRouter.ts` 的 `CallAgentParams` 只有 `systemPrompt`、`userContent`、`responseSchema`、`maxTokens`、provider 选择；没有 `tools`。
`callAgentWithFallback` 全文无 `tools`。
`agentProviders.ts` 各家 HTTP 体只有 messages / system / user，没有 function calling 工具表。
自证、证据循环改写、交叉复核同样走 `callAgentWithFallback`，都不带工具定义。
`eval/runCase.ts` 的评测 `makeRunAgent` 也不传 `tools`。
读图是 `callStepFunVisionForIntake` 服务端先抽字，再拼进待查材料，不是模型自选视觉工具。
