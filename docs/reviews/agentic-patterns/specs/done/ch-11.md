## 四类停因
都在。
类型只有 `evidence-found` / `no-new-evidence` / `rewrite-empty` / `search-failed`。
用例：第一轮新证据 → `evidence-found` 且 `recheckFactChecker=true`。
用例：两轮零新增 → `no-new-evidence` 且不重跑。
用例：检索抛错 → `search-failed` 且不阻断。
`rewrite-empty` 在 `fresh.length === 0` 时写入；套件只枚举四类，没有单独把查询用尽跑一遍。
`handlers.ts` 把四类写成中文 `reasonText` 随 SSE 发出：搜到 → 缺口收窄转入重判；没新证据 / 问法用完 / 搜索挂了 → 判停。
循环只补证据。
查询改写提示写明「不判断真假」。
停不停由缺口与 `GAIN_STOP_THRESHOLD=0.18` 决定，不由模型自报成功。

## faceVerdict
跟 `verdictType` 走。
`faceVerdictFor`：true→能信，false→不能信，mixed_misleading→只能信一部分，unverified→还查不清。
对不上的类型一律「还查不清」。
用例：未设 `verdictType` → `faceVerdict` 为「还查不清」。
用例：`verdictType=false` → 「不能信」。
「能信」「只能信一部分」靠常量映射，assemble 套件未单独 assert。
立场条进 `nonVerifiableAtoms`，不进真假清单，不为它设证据目标。
界面是「立场型 / 不适用真/假判断」。
