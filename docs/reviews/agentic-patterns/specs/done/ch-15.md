## buildAgentInput 是否透传原子与 merge 后的判词
透传。
用例：`buildAgentInput：fact_checker 透传 claimAtoms，report_composer 透传 merge 后的 subclaimVerdicts`。
`fact_checker` 输入的 `claimAtoms` 是前序 `rumor_detector` 交出的 `["原子A", "原子B"]`。
`report_composer` 输入的 `factCheck.subclaimVerdicts` 经 `mergeSubclaimVerdicts`：有判词的「原子A」仍是 false，未覆盖的「原子B」补 unverified。
生产函数在 `mvp/server/src/lib/agentConfigs.ts` 的 `buildAgentInput`。
`handlers.ts` 的 `makeRunAgent` 把这份 JSON 写成下一步 `userContent`，并把 `atomSearchBundle.forAgent` 注入 `fact_checker` / `report_composer` 的 `atomSearches`。

## bundle.forAgent 是否带来源 URL
带。
用例：`按原子归档来源并聚合去重 URL`。
`bundle.forAgent` 两条；第一条来源 `url` 为 `https://a.example/1`。
`asSourceList` 丢掉空 URL；硬过滤后再写入 `forAgent`。
交叉复核只拿该条判断和两侧来源：`crossExam.test.ts` 的 userContent 含 `https://s/1`，分歧只降分不改主判词。
报告收束用前序 JSON：`assembleFinalReport` 可核查进 `subclaimVerdicts`，立场进 `nonVerifiableAtoms`。

## rumorDetectorSchema.required 是否含 handoffTargets
生产 schema 不含。
`mvp/server/src/lib/agentConfigs.ts` 的 `rumorDetectorSchema.required` 是 `claimAtoms`、`claimAtomTypes`、`stanceClaimType`、`rumorIndicators`、`severity`、`analysis`、`detectedPatterns`。
生产 `agentConfigs.ts` 与 `runCasePipeline.ts` 都不读 `handoffTargets`。
谁下一步由管线定，模型不能点名下一个角色。
套件没有单独 assert「required 无 handoffTargets」，此条靠读生产 schema。

## 生产是否含 Google A2A
无。
`mvp/` 源码与 `mvp/server/package.json` 未找到 `well-known/agent.json`、`sendTask`、`tasks/send`、`@a2a`、`a2a-sdk`。
仓库没有 `agent.json`。
`mvp/src/components/v3/phases/mission/AgentCard.tsx` 是 UI 执行态卡片，不是协议身份文件。
规范要求不删它。

## 非生产残留（不挡验收）
`mvp/src/lib/agentConfigs.ts` 的 Vite / AgentRuntime schema 仍 required `handoffTargets`。
`handlers.ts` 的 `buildOrchestrateDemoFallback` 仍写出该字段。
两者都不是 Case Pipeline 生产拆题 schema，也不实现 Google A2A。
与 ADR-003 一致：生产是同进程 JSON 交接，Vite / AgentRuntime 是 Dev/eval。
