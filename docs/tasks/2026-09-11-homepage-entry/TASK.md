2. 「模型设置」普通人进门不该看到  
3. 进门看不到查完大概长什么样

## 要改什么

只动**首页进门**（未登录、空白输入态）。不要顺手改结果页、不要改后端。

### A. 去掉首页左栏「新查一条」

- 人已经站在中间输入框前，首页不需要再点「新查一条」
- 「新查一条」只在**正在看某次旧结果**时出现（点了回到空白输入）
- 左栏首页只保留：品牌名、最近查过的、登录

### B. 首页拿掉「模型设置」

- 未登录首页底栏不要出现「模型设置」
- 登录后放进账号相关入口即可（文案可用「账号」或进设置页，不要在进门第一眼用「模型」吓人）

### C. 输入区下方加「查完大概长这样」

- 空白首页、输入框和例子下面，放一小块**示意**（静态即可，不是真跑一次）
- 示意里要能看出：上面一句直接回答、下面有材料是帮还是拆、有一句摘录
- 标明这是示意，不是真结果（文案可用「查完大概长这样（示意，不是真结果）」）
- 视觉跟现有暖纸风格一致，不要另起一套皮

### 明确不要做

- 不要用 Cursor Cloud / 云端 agent 交这单  
- 不要改结果页（PR #85 那套另算）  
- 不要加 Agent / 工具日志 / 模型名到首页  
- 不要大改信息架构；这是进门减法 + 一块示意  

## 建议动手位置（自行核实）

多半在前端首页壳子 / 输入态：`mvp/src/goldenPath/InputStage.tsx`、`ProductShell.tsx`、相关 CSS。以仓库现状为准，不要死盯路径。

## 验收标准（必须全部满足）

打开本地首页（`mvp` 常规 `npm run dev` 或项目惯用启动方式），**未登录空白态**：

1. **截图对照**  
   - 左栏**没有**「新查一条」按钮  
   - 左栏**没有**「模型设置」  
   - 左栏仍有品牌、最近查过的（可空）、登录  

2. **主操作仍清楚**  
   - 中间大输入框仍是唯一主操作  
   - 说明和例子还在，第一次来的人仍知道往框里放东西  

3. **查完示意**  
   - 输入区下方能看到「查完大概长这样」一类示意块  
   - 块里能分辨：一句回答 + 帮/拆关系 + 摘录感  
   - 写明是示意  

4. **旧结果路径**  
   - 打开一条历史/完成态后，仍能「新查一条」回到空白输入（按钮可以出现在结果态，而不是首页重复）  

5. **回归**  
   - 相关前端测试通过（至少跑首页/goldenPath 相关测试；项目惯用 `cd mvp && npm test` 能过更好）  
   - 不要引入「模型 / Agent / provider」到未登录首页文案  

## 交付给验收的东西

本地 Codex 做完后请留下：

1. 改动说明（三五句人话）  
2. 未登录首页截图（桌面）  
3. 若动到结果态「新查一条」：结果页上该按钮的截图  
4. 自测命令与结果  

然后由 **Grok Bot + 用户** 对照 `assets/after-mock.png` 做最终是否过关。

## 过关判定

- 过：上面 1–5 全满足，且用户看截图/真机觉得比现在顺  
- 不过：任一验收条失败，或首页又冒出模型/开发者向文案
