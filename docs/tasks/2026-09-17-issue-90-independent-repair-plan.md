## 代码中已确认的薄弱环节

- `apps/server/src/lib/atomSearch.ts:368–429`：`bindAtomEvidenceToVerdicts` 校验 URL 在该命题检索集合中、修正引用编号并区分相关填充；不验证段落是否真正支持整条命题。URL 合法不等于语义支持。
- `apps/server/src/lib/citationBinding.ts:63–64`：来源 title/snippet 仍可来自模型返回对象，经过长度裁切；已知 URL 集合不能同时证明这些文字是原文。
- `apps/server/src/lib/investigation/build.ts:568–590`：sources 按 URL 去重，先注册的 title/excerpt 被保留。同一合集网址被不同命题引用时，段落不能只放在 URL 级公共对象上。
- 同文件 `clipExcerpt` 与 `takeFinding`：来源摘要截短，整条命题的综合解释挂到第一条来源关系上。它们分别是「摘要可能丢上下文」和「综合解释不是单条出处原话」两类问题，不能通过把徽章改红一起掩盖。
- 同文件 support/contradict 映射：从上游两个来源桶读取方向，对 partial/exaggerated 等不能仅依赖最终整体守门器修复已发布的分条证据。
- `apps/src/goldenPath/SourceDrawer.tsx:153–230`：徽章读 link.role，摘录读 source.excerpt，解释读 link.finding；三者缺少同一段落、同一版关系的完整关联契约。

## 必须明确的关系规则

关系属于「这条命题—这段材料」，不属于整个网页。对「气泡水可以降低尿酸」，该小节的完整论述提供反向材料；对「气泡水不能实现降尿酸的治疗作用」，同一段可以支持。对「胃不舒服喝苏打水就够了」，不能只凭降尿酸小节直接完成反驳，仍需胃部问题相关材料；否则只是把错支持变成错反驳。

理论机制、实际饮用效果、治疗是否充分要分开核查，并保留它们在原句里的推理联系。气泡水与苏打水也不能未经材料确认就当成同一个对象。允许证据支持其中一个有条件的前提，但不能把这种支持传播成整句治疗结论成立。

## 修复顺序

### 一：先阻止未经核验的方向性证据上屏

Change：在 evidence binding 到 investigation snapshot 的共同边界引入关系核验结果；首轮 judging、补查、质询后重判、最终报告使用同一个规则，不能只有完成态纠错。已有网页地址但没有足够上下文、段落定位失败、核验超时或对象/结果指标不匹配时，不发布裸 support/contradict；保留为待核验或仅相关，并解释还缺什么。

确定性代码检查来源身份、段落存在、引文范围、对象字段、引用编号；语义核对处理完整命题、原文语境和作者最终立场。关键词只能触发取上下文与复核，不能直接决定正反。优先复核将用于主答案的少量关键来源，复用已有调用或有预算的定向核对；沿用取消与剩余时间预算，不能对所有搜索结果加一轮无限抓取/模型调用。

必须区分「尚未核验」与「已确定仅相关」：段落未取得、核验超时或结论不明时用 unassessed 并记录缺口；只有核对后确认不能直接支持/反驳目标主张，才归为 context-only。不能拿一个保守标签掩盖两种不同状态。首轮、中途重判与最终判词均按已接受关系计算，旧版关系不得因迟到响应覆盖新版本。

Evaluator：重放中途 support→最终 context-only 场景。方向未核验时不出现绿色支持；核验后所有卡片/抽屉/活动更新一致。任何最终守门都不能成为允许前面误导用户的借口。

**状态：已实施。** 初轮 FactChecker 候选先由 SourceValidator 逐 `claimAtom + URL` 审计后才进入第一份 judging 快照；后续 evidence loop / cross-exam / whole-claim 新来源也会刷新审计。未覆盖或审计失败的方向性来源 fail-closed，不再先上绿/红标签。候选保存在管线内部，后续审计成功可以恢复正确方向，不会因一次安全降级永久丢失。

### 二：证据取到完整小节，来源信息不得串用

Change：保留真实网页标题、URL、发布时间作为 source 元数据；把「命中小节、原文引述、前后条件、段落定位、原文快照校验值」放到具体 evidence link/passage 上。模型只选择已取得的段落标识，不允许凭 URL 重新编原文摘录。搜索摘要明确标为摘要；完整原文没有抓到时，不假装展示原文引用。

针对合集，根据正文结构寻找匹配段落与所属小节，而非取最近一个 b/strong 就认作标题。辟谣标题中的流言与作者的解释结论一并保留。长段落可折叠，但默认可见文字不得隐藏决定语义的限制条件。页面无真实锚点时不伪造 #anchor。

抓取复用已有安全边界：限制响应大小、内容类型、重定向与超时，重新校验重定向目标和域名解析，禁止借引用抓取访问内网地址。原文和网页中的任何指令都视为不可信材料。字段以向后兼容方式加入 source/passage/evidence，同步生产与 packages 的快照镜像；老报告缺核验记录时明确标记未知，不推造新的核验结果。

Evaluator：本 CNR HTML 按其声明编码解析；显示命中小节「流言：喝气泡水可以降尿酸」，同时保留原文总标题。两条命题引用同一个 URL 的不同小节，展开的引文必须分别匹配，不能因 URL 去重而共享错摘录。无小节时保留真实页标题并明确未定位，不能让模型臆造。

**状态：核心已实施。** Source 保留真实网页 title；EvidenceLink 持有 sectionTitle / passage / relationReason；模型返回的 title/snippet 不能覆盖检索层 canonical metadata；抽屉优先展示 link passage。当前小节识别覆盖本 CNR 的「流言…真相」结构，尚不是通用 HTML DOM section parser，因此其他复杂合集仍需后续真实样本扩展。

### 三：拆题与整句判断保留原意及依赖

Change：合并「所以可以中和酸」这类无主语残句与其完整主张，保留原始位置；分别记录饮品属性、条件性的中和作用、胃部不适仅靠饮品是否足够。保留用户最终要确认的主张，限制前提支持向治疗结论传播；不为了得到全假而删除被证据支持的限定事实。

Evaluator：原输入、同义改写、调整句序均保留主结论；不能只回答首个前提。相同来源可以对不同主张有不同关系，关系变化有原文与理由，不靠一句「但是」强行翻桶。

**状态：本案残句已修。** 已有完整带主语主张覆盖 leap 时，不再增加「所以可以中和酸」这种残句；真正遗漏的所以/因此结论仍补入。更完整的「主张依赖图」没有在本轮扩张实现。

### 四：统一展示、历史与复核记录

Change：徽章、引文、解释与局限从同一条已核验关系读取。综合命题解释与原文引述分开命名。动态更新时先保证当前来源/段落指向正确，再更新关系；无法安全定位的 held 视图明确标记历史/暂失联，不把旧关系作为当前结果。

旧调查不得无记录改写；复核修订保存原日期、修订时间和变动依据。对可能进入知识库的错关系单独检查并暂停复用至复核完成，不能在本轮顺手删除全部历史。分享及复制简报不能丢失限制条件。

Evaluator：打开抽屉后发生关系变化、来源被撤回、同一来源多段关系、历史重开和分享均不出现旧绿标冒充当前关系；停止/复核失败保留材料但不产生确定方向。

**状态：展示主路径已实施并验证。** SourceDrawer 的网页标题、小节、passage、关系理由来自同一 EvidenceLink/Source 组合。历史修订版本化与存量错误关系知识库审计尚未在本批次执行，不能把本次代码修复说成历史记录已自动纠正。

## 修复验收集

1. 本案实际 CNR 页面 + 已保存活动与终态；原始版本和修复版本使用同一材料重放，区分结构回归与真实模型判断。
2. 原句/否定句成对：含「流言」「辟谣」的网页不能一律归入反驳。
3. 正向机制 + 否定实际功效；「但是」后只是在限定适用范围而非推翻主张。
4. 尿酸/胃酸等不同对象和结果指标不能跨题给支持或反驳；需要新证据时明确留下缺口。
5. 同 URL 多小节、跨不同命题、来源标题与小节分离、模型改写引文、320/80 字裁切的限定丢失。
6. 提前发布/最终修正/重连/打开抽屉未关闭的时序；检索无结果、源站失败、预算用尽与取消。

所有新增回归与现有哨兵通过后，固定模型配置与材料做真实案例复验；检查原文与判词，不以全量单测绿或某条徽章由绿变红宣称判断质量通过。首个修复交付优先处理发布前关系核验与原文段落绑定；不夹带 T20 迁移或整站视觉重构。
