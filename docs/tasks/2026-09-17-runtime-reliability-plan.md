- 同文件 `invokeAndParse`（约 795–839 行）：首调与一次模型 JSON 修复分别获得相同的 `timeoutMs`；修复启动时未重新计算阶段剩余预算。不能把所有长延迟都归因于供应商。

## 任务一：让停止和超时真正终止本次调用

Change：建立一次调查共享的取消信号和绝对截止时间，贯穿 handler → pipeline → runAgent / 自证 / 质询 / 报告 → provider / BYO → fetch、响应流读取及检索。复用现有组件，不新增另一套运行时。

每个尝试的截止时间取本次调用上限、阶段截止、调查截止三者最早值。达到时限时取消底层请求；所有 catch 分支先识别用户取消与截止时间，之后才处理可重试错误。取消不能触发 JSON 修复、供应商回退或新的补查。

用户点停止与页面刷新/暂时断连必须分开：显式停止取消调查，单纯失去 SSE 订阅不取消服务端调查。停止保留现有材料；迟到结果不得把取消终态改成完成、继续发布新判词或写入新调查记忆。已有完成任务的重复停止保持幂等。

覆盖所有启用中的供应商、BYO、检索与重试路径；不能只接 MiniMax 一条路径。取消监听器、计时器、流 reader 在结束时清理。

Not this：不只在前端换文字，不只丢掉 Promise.race 的落败结果，不把取消当服务失败，不暗中改用平台密钥。客户端中断请求也不等于已验证供应商停止计算或退款；计费效果不能据此保证。

Evaluator（拟定本地验收目标，不是现有测量值）：

1. 本地可控 HTTP 服务故意不结束响应：在请求发出前、响应头后、流读取中、退避等待中分别取消；服务端观测连接关闭，取消确认后 2 秒内本地在途数归零且不新增模型或搜索请求。
2. 取消与完成同刻、重复取消、超时与取消竞争：最终状态一致、只结算一次、保留此前快照，不接受迟到结果。
3. 从真实页面点击停止到可见「正在停止」不超过 1 秒；真实上游断连结果另记，不能只用 mock 证明供应商行为。
4. 刷新与重连不新建调查、不重复扣额度；BYO 401/取消均不回退到平台凭证。

## 任务二：约束坏 JSON 和长延迟，不改变证据含义

Change：接任务一的共享预算。JSON 修复最多一次且只用剩余时间；阶段预算不足就不再发请求。超时、网络故障、截断、语法错误、字段错误分别记录，不用无限兜底掩盖差异。

复用已有 `responseSchema` 做解析后的字段、类型和枚举校验；同时检查命题与引用是否来自当前输入材料。JSON 能解析不代表判断正确。严格模式只验证，不能通过转换、填充或删除字段把无效判断变成有效判断。

保留流的结束原因及用量/耗时元数据（供应商提供才记录），区分输出截断和转义错误。任何本地清理不得猜测缺失的判断或补造来源。未经验证的修复输出不能进入结果页。

缩小各阶段输出工单：让报告复用已核查命题与来源，不重复生成同一组判断、评分及长段落；每个减少的字段先确认消费者。需要拆除自证重复调用时，先复现两次空结果并检查返回形状与解析协议，不直接跳过自证以换速度。

报告失败且已有足够结构化结果时，用现有确定性报告保留事实、证据与边界；资料未齐则明确未完成或未查清，不为了收束标成完整核查。记录是否使用兜底，但不把模型日志展示给用户。

供应商输出约束先做最小能力验证：MiniMax 官方 Anthropic 兼容文档列出 tools/tool_choice 支持，但未在该页给出严格 JSON Schema 保证。不能承诺加一个 `response_format` 就解决；M2.x 的 thinking 也不能通过 disabled 真正关闭。保持当前模型和套餐，模型更换/收费优先级/并发备用调用另行裁决。

Not this：不简单缩短全部超时、不降证据标准、不靠追加重试变快、不用 JSON 合法率冒充事实准确率、不承诺供应商永不输出坏 JSON。

Evaluator：

1. 故障注入覆盖引号错误、半截 JSON、空文本、thinking-only、合法 JSON 但字段/枚举错、慢响应、取消时修复待发；所有无效结果必须被阻断或诚实收束。
2. 测试首调用尽大部分预算后坏 JSON：修复只剩余额度，不能重获完整时限；预算耗尽后没有新的调用。
3. 锁定输入、模型配置和知识库快照做前后对照；分别记录首次材料可见时间、总耗时、重试量、调用量、输出校验失败和判断变化。小样本逐例报告，不用单次成功或一次更换缓存状态证明性能改善。
4. 原隔夜菜案例及有效追问完整走通；另覆盖纯事实、混合判断、证据不足、无法打开链接和取消场景。逐条核对结果与出处，部分成立不得变为整条成立。

## 任务三：T20 迁移，不丢现有产品能力

Change：先制作 `apps` → `packages` 能力及数据差异表。至少包括首页三类输入、拆题和整句守门、引用绑定、渐进快照、取消/恢复、访客与账号额度、历史日期与所有权、追问、分享与撤销、BYO、图片来源、安全检查和数据备份。

先把任务一、二及现行判断规则收敛为可共享实现，再由生产适配层接入，避免两个目录独立复制补丁。保留用户已确认的 Golden Path；新 `packages/web` 如要接管，必须先承载相同用户路径，不能把后端迁移偷换成前端重做。

按共享逻辑 → HTTP/存储适配 → 前端承载 → 部署切换推进。接口不同可用有退出条件的薄适配器；每条调查只由一个引擎执行。对照测试优先重放固定材料，不在生产暗中跑两套模型调查。

切换前在数据副本上演练备份、迁移和回滚：历史调查、原日期、归属、分享链接和撤销状态不可丢失；回滚不能只换代码却读不了新格式。发布需单独授权。旧生产实现仅在完整验收、数据回滚验证和确认无引用后移除，不能照旧 T20 的 mvp 删除指令执行。

Not this：不迁移时顺便改产品规则，不仅改 ops.sh 路径，不上线后再补账号/历史/额度，不删除未提交或未合并工作，不保留两个默认产品入口。

Evaluator：同一固定案例集与用户路径在新入口通过；根目录与生产壳测试/构建及相关 eval gate 均通过，不能改旧基线凑绿；备份恢复与回滚演练通过。真实浏览器验证输入 → 调查 → 来源下钻 → 追问 → 历史重开 → 分享撤销，并覆盖停止、刷新、链接失败及桌面/窄屏布局。
