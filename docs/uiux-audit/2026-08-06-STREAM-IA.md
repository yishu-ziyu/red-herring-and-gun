# 过程流信息架构 — Stream IA（2026-08-06）

> 角色：UX Architect · 产品：红鲱鱼与枪  
> 对齐：`2026-08-06-SYNTHESIS.md` · 结构真源：`2026-08-06-kimi-cluster-prototype.html`  
> 用户 job：粘贴传言 → 看懂过程与证据 → 决定信不信 / 转不转

## 1. 本产品里的「流式优先」是什么

用户要看到的是**核查结论如何随时间长出来**，不是运维台日志刷新。

流式优先 = 下列内容**按到达顺序进入固定槽位**，用户可随时扫一眼：

| 到达物 | 用户应感知到的 |
|--------|----------------|
| 思考 / 命题拆解 | 「系统在理解我说的什么」 |
| 工具 / 检索 | 「在对照公开材料，有几条可点」 |
| 角色（Agent） | 「谁在干活、各自任务一句」 |
| 阶段性发现 | 不等收束完，先有可消费的预告句 |
| 判决 | 完成时置顶：判定 + 人话 + 转发建议 + ≤3 来源 |

**透明 = 可点分层**（主栏 Phase → 动作条 → 协作集群 → 点角色看右栏明细 → 底栏切换）。  
**透明 ≠ 把 SSE / 模型 ID / 供应商名 / 事件计数全喷一级。**

编排与真实事件流保留在管道层；UI 只升格人能决策的那一层。

## 2. 等待 vs 完成：信息架构

```
                    ┌─ 顶栏：产品名 | 状态点 + 人话阶段 + 用时 ─┐
                    │  主栏固定锚：核查对象 = 用户原句（截断可展） │
等待（进行中） ────┤  Phase 卡（同时只亮一个「进行中」）          │
                    │  动作条（可点：拆解 / 检索 n 条 / 参考…）   │
                    │  协作集群（真角色去重 3～5，一人一卡）       │
                    │  右栏：点谁才看谁的工作台 / 材料             │
                    │  底栏：角色条（状态：完成 / 进行中）         │
                    └─ 禁止：Case Workbench 主标签、双卡、供应商墙 ┘

                    ┌─ 顶栏：完成 · 绿点 ───────────────────────┐
完成 ──────────────┤  【判决块置顶】判定标签 → 一句话 → 转发建议 │
                    │            → 关键来源 1～3                  │
                    │  其下「过程回放」：Phase / 动作 / 集群收起感 │
                    │  右栏 / 底栏仍可下钻，默认不抢判决位       │
                    └──────────────────────────────────────────┘
```

| 层级 | 等待时 | 完成时 |
|------|--------|--------|
| L0 锚 | 原句 + 当前阶段人话 | 原句（可折）+ 判决块 |
| L1 叙事 | Phase：命题拆解 → 公开材料对照 → 结论与建议 | Phase 摘要一句 + 判决 |
| L2 动作 | 可点行：结果计数，不写引擎主标题 | 回放同一套动作 |
| L3 人 | 集群去重；运行中标「进行中」 | 全员完成；可点回看产出 |
| L4 明细 | 右栏按点击填充；空则诚实说未挂接 | 同左，不默认展开总线 |

人话阶段（与原型一致，可微调措辞，不可换成模型名）：

1. **命题拆解**  
2. **公开材料对照**（分轨核验；发现随进度披露）  
3. **结论与转发建议**

## 3. 事件种类 → UI 块（映射）

管道事件（`agent_*` / `tool_*` / `complete` 等）**不直接等于界面行**。先归类，再进槽。

| 事件族（示意） | 归入 UI 块 | 一级是否可见 | 规则 |
|----------------|------------|--------------|------|
| 会话开始 / 阶段切换 | **Phase** | 是 | 只亮一个「进行中」；文案用人话，不用 `minimax:…` |
| LLM 思考 / 分诊产出 / 命题列表 | **Thought → Phase 正文或「命题拆解记录」动作** | 摘要是；长文右栏 | 拆出的命题进列表，不 dump 原始 token |
| `tool_start` / `tool_result` / 多源搜索 | **Tool 动作条** | 是（合并一行） | 主标题如「公开材料检索 · n 条」；供应商名只进右栏或角标 |
| Memory / 历史命中 | **动作条「历史参考」** | 可一行 | 标明「不作本案证据」 |
| `agent_start` / `agent_complete` | **Agent 集群 + 底栏** | 是 | **按角色 ID 去重**；同一步不双卡；展示名用产品角色（分诊 / 核对 / 来源 / 收束） |
| 可消费发现 / 冲突摘要 | **Phase 内阶段性发现 或 预告句** | 是（一有就上） | 如「外地素材拼接」不得只埋在工具段落 |
| `agent_error` / `tool_error` | 该角色/动作失败态 | 局部 | 人话失败 + 可重试；不弹工程师栈 |
| `complete` + 报告 / claimReview | **Verdict 判决块** | 完成态 L0 置顶 | 判定 → 人话 → 转发建议 → ≤3 来源；逐条定罪进二级 |
| 模型 ID、latency、事件 KPI | **不进默认 UI** | 否 | 最多进开发折叠或导出 |

映射一句话：**事件进管道；用户只看见 Phase / 动作 / 集群 / 判决四类块。**

## 4. 验收（可证伪）

固定 case：百色洪灾视频（或等价「外地素材拼接」类）。

| # | 当… | 用户看到… | 时限 |
|---|------|-----------|------|
| A | 点开始核查 | 主区是原句 + 人话阶段，**无** Case Workbench / Agent Team / 模型 ID /「N 完成 · M 运行」作主信息 | ≤ 2 s |
| B | 分诊产出命题 | Phase「命题拆解」完成或列出可核验项；集群至多 **一张** 分诊角色卡 | 事件到达后 ≤ 1 s |
| C | 多源检索返回 | 一条「公开材料检索 · n 条」可点；主标题**不含** 360/AnySearch/Metaso 墙 | 首条结果后 ≤ 1 s |
| D | 链路出现可消费发现 | 主栏 Phase/预告区出现该发现（如拼接/不实倾向），**不**仅在左栏工具污泥里 | 发现事件后 ≤ 2 s |
| E | 全程等待 | 始终能回答「在查我那句吗、到哪一步」；空材料写「未挂接」，不放假 Sources 模块 | 全程 |
| F | `complete` 到达 | 判决块**置顶**：标签 + 一句话 + 转发建议 + ≤3 来源；过程下沉为回放 | ≤ 1 s |
| G | 点集群某角色 | 右栏只显示该步任务/产出/来源，不是整页总线 | 点击后即时 |
| H | 完成态打开结果 | 未先学 agent 名也能回答「转不转」 | 首屏 10 s 内 |

不通过条件（任一即 FAIL）：双「立案分诊员」；供应商串作主标题；结论只在「最终判断已生成」按钮文案里；等待期零人话进度。

## 5. 明确不做（Non-goals）

- **不做**默认曝光：模型 ID、事件流 KPI、Case Workbench / 子 Agent 运维标签。  
- **不做**供应商墙当一级标题（多引擎合并为一次「公开材料检索」）。  
- **不做**同一角色同一步双卡 / 右栏标题双写。  
- **不做**整页 SSE dump、中英双头标签（THINKING/思考并排）。  
- **不做**为「像专业」再叠第三套指挥中心；canvas/workbench 最多是高级审计层。  
- **不做**假进度糊弄：无事件就诚实空态，不编造「已找到 n 条」来源。  
- **不砍**（只改暴露层级）：真实编排与事件流、ReportModal 逐条定罪、排除层、来源导出、取消/失败重试。
