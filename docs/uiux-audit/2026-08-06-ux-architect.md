# UX Architect 死刑报告 — 2026-08-06

**角色**：ArchitectUX（信息架构）  
**样本 case**：网传广西百色严重洪灾视频  
**产品镜头**：粘贴谣言 → 看懂证据 → 决定信不信 / 微信群转不转  
**主用户**：普通中文信息消费者（不是 MLOps / agent 工程师）  
**取证**：`docs/uiux-audit/2026-08-06-evidence.md` + `mvp/output/uiux-audit/01`–`04*.png`  
**结构热点**：`mvp/src/components/v3/phases/MissionControlView.tsx`、`ReportModal.tsx`

---

## 1. 一句话死刑判决

**办案台把「要不要转发」做成了「看 agent 流水线」，用户跑完 3 分钟仍拿不到可转发的一句结论，关键辟谣句埋在工具污泥里。**

---

## 2. 真实用户路径 vs 当前 UI 路径

```
【用户心里的 3 步】
  粘贴谣言 ──► 等一下（别慌） ──► 看：真/假 + 为什么 + 能不能转
       │              │                    │
       │              │                    └─ 一句人话 + 1–3 条可点来源
       │              └─ 进度：在查什么 / 还要多久
       └─ 输入框就是主舞台

【当前 UI 实际路径】
  首页长文案 + 5 步英文流水线 + 模型下拉 + footer 供应商名册
       │
       ▼ 开始调查
  Case Workbench 双栏控制台
       │
       ├─ 顶栏：CASE WORKBENCH / minimax:MiniMax-M3 / 事件流计数
       ├─ 左栏：活动过程 11→21 条 · Agent Team 重复卡 · 工具调用瀑布
       └─ 右栏：搜索|360/AnySearch/Metaso/Tavily/Exa 标题双写
                 · Thinking / Sources 空态
                 · 关键结论「外地素材拼接」不在标题位
       │
       ▼ ~3min 仍「报告收束员 · 进行中」
  用户仍不知道：信不信？转不转？
  （结论若在 ReportModal，也要等收束完才出现；等待期零预告）
```

**错位一句话**：用户要判决书；系统给的是刑侦指挥中心直播。

## 3. IA 致命问题

每条：现象 + 证据 + 用户代价。

### 3.1 模式错认：消费产品伪装成 Agent Ops 控制台

| | |
|--|--|
| **现象** | 进入后主标签是 `CASE WORKBENCH`；分区是 `活动过程` / `Agent Team` / `子 Agent` / `工具调用` / `Parallel Search` / 模型 ID。 |
| **证据** | `02-mission-early.png`、`03-mission-mid.png` 顶栏与左栏；`MissionControlView.tsx` ~4995 `Case Workbench`，~3208/`4162` `Agent Team`；evidence a11y：`minimax:MiniMax-M3`、`4 完成 · 6 运行 · 11 条真实事件`。 |
| **代价** | 普通用户默认：这是给我用的吗？还是开发后台？认知先崩半秒，再谈读懂证据。 |

### 3.2 主任务被从扫描路径上踢掉

| | |
|--|--|
| **现象** | 用户原句只作为搜索 QUERY 复述出现；屏上没有固定「正在查这句话」+「目前倾向」锚点。主视觉是工具名串与 agent 卡。 |
| **证据** | `02`/`03` 右栏大标题是 `搜索 \| 360 / AnySearch / ...` 双写，正文是原 claim 回声；`04-after-wait.png` 右栏是「开始报告收束 / 合成结论 计算 FIRE 置信度」，Findings 下「结论」空。 |
| **代价** | 用户无法一眼回答：系统在查我那条吗？查到哪了？该信什么？ |

### 3.3 关键发现不进一级信息架构

| | |
|--|--|
| **现象** | 后台已有强结论：网传百色严重洪灾视频实为外地素材拼接。UI 不把它提升为一级 headline；混在 agent 墙与多事件搜索污泥里。 |
| **证据** | evidence.md Later mission：`Key finding buried`；同屏还混「蛇出逃 / 贵州酒吧假视频 / 钦州水库」；`04` 已到报告收束，右栏结论区仍空，Sources「本步尚未挂接可点开的来源材料」。 |
| **代价** | 用户最需要的那句「假的、别转」迟到或找不到 → 默认继续转或放弃产品。 |

### 3.4 等待态没有「人话进度」，只有工程 telemetry

| | |
|--|--|
| **现象** | 长时间等待用「仍在等待模型返回」「事件流 9 完成 · 11 运行 · 21 条」+ 90 秒黄条解释。阶段 pill 写「证据交叉验证」时，用户仍看不到可消费的中间结论。 |
| **证据** | evidence a11y + `03` 黄条；`MissionControlView.tsx` ~1592 `仍在等待模型返回`，~5032–5034 90 秒文案；`04` 顶栏「证据交叉验证」vs 右栏仍在「报告收束」。 |
| **代价** | 焦虑上升；黄条教用户「重开」而不是「再等 30 秒会出什么」；3 分钟后仍像卡死。 |

### 3.5 重复与噪声占用 IA 槽位

| | |
|--|--|
| **现象** | 同一「立案分诊员」两张 Agent Team 卡（一蓝点一绿点）；右栏同一工具标题重复两遍；左栏近重复搜索条目瀑布。 |
| **证据** | `02`/`03` 左栏两张「立案分诊员」；右栏标题双写；evidence：`Duplicate Agent Team cards`、`right pane title repeated twice`。 |
| **代价** | 用户以为卡了 / 派了两队人；可用像素被管道日志吃光，真正材料区永远「尚未挂接」。 |

### 3.6 首页卖流水线，不卖决策结果

| | |
|--|--|
| **现象** | Hero 多段产品说明；「它如何工作」5 卡英文 codename（CLAIM DECOMPOSER…）；footer 供应商名册；主 CTA 旁「4-Agent 模型选择」。 |
| **证据** | `01-home.png`；evidence Home a11y。 |
| **代价** | 进门就在培训用户成为 agent 操作员；「微信群要不要转」的 job 被埋在第二屏 demo 卡里。 |

### 3.7 中英双语标签加倍认知税

| | |
|--|--|
| **现象** | 同一区块同时 `THINKING`/`思考`、`SEARCH / TOOL`/`搜索与工具`、`SOURCES`/`材料来源`、`FINDINGS / HANDOFF`/`结果与交接`。 |
| **证据** | `02`/`03`/`04` 右栏分区头；evidence bilingual labels。 |
| **代价** | 主用户只需要中文决策语言；英文是工程师镜像，不是可信度。 |

### 3.8 设计系统与现网 IA 互相打架（结构层）

| | |
|--|--|
| **现象** | `mvp/DESIGN.md` 定的是深色 spatial reasoning canvas（Flowith 向）；现网 mission 是浅色 Case Workbench 双栏控制台。两套世界观并存。 |
| **证据** | `DESIGN.md` front matter `stageBg: #070807` + Flowith 章节；截图全是浅色 workbench；evidence 亦记 canvas dark vs light conflict。 |
| **代价** | 后续改 UI 无单一结构真源；容易继续叠第三套「更好看的控制台」。 |

## 4. 目标信息架构（三屏）

只服务 job：**贴 → 等 → 判**。Agent / 工具 / 模型全部降为可展开审计层，默认不进一级扫描路径。

```
┌─────────────────────────────────────────────────────────┐
│ 屏 A · 首页（贴）                                         │
│  ┌───────────────────────────────────────────────────┐  │
│  │ 一句话：粘贴传言，30 秒内告诉你能不能信、能不能转     │  │
│  │ ┌─────────────────────────────────────────────┐   │  │
│  │ │  粘贴文字 / 链接 / 截图                       │   │  │
│  │ └─────────────────────────────────────────────┘   │  │
│  │          [ 开始核查 ]                              │  │
│  └───────────────────────────────────────────────────┘  │
│  次要（折起或一屏以下）：一个示例 · 一句「怎么判」         │
│  砍掉默认曝光：5 步英文 agent 名 / 模型 picker / 供应商墙  │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 屏 B · 等待（等）— 单栏，不是控制台                        │
│  顶：正在查 · 「百色洪灾视频…」截断原句                     │
│  中：人话阶段（三选一，同时只亮一个）                       │
│       ① 理解你在说什么  ② 对照公开报道  ③ 整理能否转发     │
│  中下：【已出现的关键发现】可滚动预告（一有就顶上来）         │
│       例：· 多条官方/媒体称视频为外地素材拼接（待收束）      │
│  底：预计还要 ~X 秒 · 取消                                 │
│  ─── 默认折叠 ─────────────────────────────────────────  │
│  ▸ 查看核查过程（点开才见：步骤 / 来源数 / 可选 agent 细节） │
│  禁止默认：CASE WORKBENCH、模型 ID、事件流 N 完成 M 运行    │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ 屏 C · 结果（判）— 先判决，后证据，再审计                   │
│  ┌─ 判决条 ───────────────────────────────────────────┐  │
│  │  不实 / 部分属实 / 无法核实 · 一句话人话结论          │  │
│  │  微信建议：不要转发 / 可转但附免责 / 证据不足勿转      │  │
│  └────────────────────────────────────────────────────┘  │
│  原句（可展开）                                            │
│  依据（默认 1–3 条可点开链接，标题人话）                    │
│  还不确定什么（缺口，短）                                   │
│  ─── 默认折叠 ─────────────────────────────────────────  │
│  ▸ 逐条命题 / 立场型说明（ReportModal 能力保留在此）       │
│  ▸ 完整过程时间线 / 原始 trace（工程师与复盘用）            │
└─────────────────────────────────────────────────────────┘
```

**扫描路径（屏 C，F 型）**：判决条 → 微信建议 → 1–3 来源 → 需要时才下钻。  
**等待期规则**：任何已稳定的强发现，允许在屏 B 以「预告」出现；不要等 `报告收束员` 全部跑完才第一次说人话。

## 5. P0 必须改（≤5，可验收）

| # | 改什么 | 怎样算完（可观察） |
|---|--------|-------------------|
| **P0-1** | **等待/结果默认去控制台化** | 新用户跑百色 case：首屏可见区**没有** `Case Workbench` / `Agent Team` / `子 Agent` / 模型 ID / `N 完成 · M 运行` 作为主信息。上述内容只在「查看核查过程」展开后出现。截图对比 `02`/`03` 可判。 |
| **P0-2** | **一级锚点：原句 + 当前阶段（人话三态）** | 运行中顶区固定显示：截断原 claim + 唯一阶段文案（理解 / 对照公开报道 / 整理结论）。**禁止**用 `minimax:…` 或工具名串当阶段标题。 |
| **P0-3** | **关键发现升级为一级模块（含等待预告）** | 一旦链路出现可消费结论（如「外地素材拼接」），在屏 B/C **主栏标题或判决区**可见，**不得**仅存在于左栏 Agent 墙或工具段落。`04` 类状态下右栏「结论」不得长期空白若左栏已有实质发现。 |
| **P0-4** | **结果首屏服务「转不转」** | 收束完成后默认落地（或等价全屏结果）顺序：判定标签 → 一句人话 → **转发建议** → ≤3 条可点来源。打开结果 **不需要** 先理解 agent 名或 FIRE/技术 jargon 才看到建议。 |
| **P0-5** | **消重与空态诚实** | （1）同一 agent 同一步不渲染双卡；（2）右栏标题不双写工具供应商串；（3）Sources 无链接时不占「材料来源」一级假模块，或明确「暂无公开链，结论仅基于…」。对照 `02` 双卡 + 双标题可回归。 |

**P0 不做**：换肤、动效、新品牌色、再加一列「更聪明的」面板。

## 6. 明确不要改（保护域）

这些是产品真能力或已对齐的契约，IA 改版时**保留机制、只改暴露层级**：

1. **多 agent 编排与真实事件流**（`MissionControlView` 流式、handoff、冲突调解）— 保留；默认折叠为「过程」，不做假进度条糊弄。
2. **ReportModal 报告模型能力**：`subclaimVerdicts` / `claimItems` 逐命题、立场型 `stanceClaimType` 横幅、排除层（不可核验原子）— 保留语义；放进结果屏的二级「逐条说明」，不要删定罪能力。
3. **可追溯来源与导出**（markdown/json、来源 URL）— 保留；首屏只展示精选 1–3，全量在展开层。
4. **原句自证闸门 / 排除层**（服务端判定立场/预测等不硬判真假）— 逻辑不砍；UI 用中文「这类句子无法用公开事实核验」表达，而不是工程师字段名。
5. **取消核查 / 失败可重试** — 保留；文案从「保留记录并重新发起」改为与人话阶段一致，避免暗示产品已死。
6. **Demo / 示例卷宗作为教学入口** — 可保留，但不得压过首页主输入；示例要示范「判决 + 转发建议」，不是只示范 agent 步骤名。

**不要**为了「更像专业工具」把 `DESIGN.md` 的 canvas 与 Case Workbench 再合成第三套指挥中心。先定：**消费决策三屏** 是唯一一级 IA；canvas/workbench 最多是高级审计皮肤。
